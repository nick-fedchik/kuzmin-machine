## 1. Епістемологічні засади Попперівської верифікації

У критичних кіберфізичних системах (наприклад, рівнів ASIL D чи DAL A) тестування, спрямоване лише на демонстрацію «працездатності», недостатнє:
> *«Жодна кількість експериментів не може довести, що я маю рацію; один-єдиний експеримент може довести, що я помиляюся.»* — Карл Поппер (1934).

KPOL v0.7 вводить у компілятор принцип **інженерної презумпції фальсифікації**:
1. Будь-яке правило `Solution` вважається **потенційно дефектним**, доки доказ `Proof` не знищить усі семантично можливі мутації цього правила.
2. Якщо в коді змінено логічний оператор (наприклад, `<` на `<=`, або `x + 1` на `x - 1`), і жоден тест у блоці `Proof` не впав — **тестовий набір визнається неповноцінним**, а компіляція блокується.
3. Міра підкріплення гіпотези надійності $h$ емпіричними свідченнями $e$ визначається за формулою Поппера:
   $$C(h, e) = \frac{P(e \mid h) - P(e)}{P(e \mid h) - P(e \cdot h) + P(e)}$$

## 2. Оператори мутації KPOL (First-Order Mutation Operators)

Компілятор генерує сімейство мутантів $\mathcal{M} = \{M_1, M_2, \dots, M_k\}$, застосовуючи до AST строго один із таких операторів:

| Оператор | Позначення | Опис | Приклад вихідного коду | Приклад мутованого коду |
| :--- | :--- | :--- | :--- | :--- |
| **ROR** | Relational Operator Replacement | Заміна операторів порівняння | `Temp > 100` | `Temp >= 100`, `Temp == 100`, `Temp < 100` |
| **BSR** | Boundary Shift Replacement | Зсув константних границь | `Threshold := 50` | `Threshold := 51`, `Threshold := 49` |
| **LCR** | Logical Connector Replacement | Заміна логічних зв'язок | `A and B` | `A or B`, `not A` |
| **AOR** | Arithmetic Operator Replacement | Заміна арифметичних дій | `Val + Delta` | `Val - Delta`, `Val * Delta` |
| **GDR** | Guard Drop Replacement | Видалення захисної умови (Forced True) | `when Temp > 100` | `when true` |
| **SVR** | State Value Replacement | Мутація значення присвоєння | `set Status := 1` | `set Status := 0` |

## 3. Формальний метричний апарат: Мутаційний бал та підкріплення

### 3.1. Мутаційний бал (Mutation Score)
Нехай $K$ — кількість мутантів, на яких хоча б один тест блоку `Proof` зазнав невдачі (*Killed Mutants*), а $T$ — загальна кількість нееквівалентних згенерованих мутантів.
$$M = \frac{K}{T}, \quad M \in [0.0, 1.0]$$

* **Правило KPOL v0.7:** Для генерації промислового бінарного образу BRAM (`compile_bram_image`) або заголовка для STM32 (`compile_c_header`) компілятор вимагає **строго $M = 1.0$**.  
* Якщо $M < 1.0$, компілятор зупиняє трансляцію та видає точний рядок коду мутанта, який вижив, із зазначенням неперевіреної граничної умови.

### 3.2. Ступінь підкріплення Поппера $C(h, e)$
На основі відношення кількості виконаних жорстких фальсифікаційних спроб до теоретичного простору станів обчислюється нормалізований ступінь підкріплення:
$$C(h, e) = \frac{K}{T} \cdot \left(1 - \frac{1}{2 + \log_2(1 + \text{Steps})}\right)$$
Ця метрика фіксується у сертифікаційному звіті для аудиторів авіоніки та автотранспорту.

## 4. Bounded SMT генератор контрприкладів

Для інваріантів `Invariant` та аварійних небезпек `Hazard` компілятор виконує символьний пошук вхідних значень аргументів, які можуть порушити контракт:
$$\exists \vec{x} \in \text{Domain} : \text{Guard}(\vec{x}) \land \neg \text{Invariant}(\text{NextState}(\vec{x}))$$
Якщо такий $\vec{x}$ існує, компілятор відхиляє програму ще на стадії статичного аналізу і виводить контрприклад:
`Counterexample found: at event Sample(MeasuredT = 101), Invariant 'SafeT' is violated!`

## 5. Програмний інтерфейс компілятора (API)

Модуль верифікації розширюється такими публічними функціями:

1. `generate_mutants(module: Module) -> list[Module]`:
   - Приймає валідне AST модуля;
   - Синтезує вичерпний список мутантів першого порядку;
   - Забезпечує детерміністичний порядок генерації для повторюваності.

2. `run_falsification_suite(module: Module) -> FalsificationResult`:
   - Виконує базову перевірку `verify_module(module)`;
   - Проганяє `Proof` проти кожного мутанта;
   - Обчислює $K$, $T$, $M$ та $C(h, e)$;
   - Повертає структурований звіт із переліком убитих та живих мутантів.

3. `enforce_popperian_gate(module: Module) -> None`:
   - Викликає `run_falsification_suite`;
   - Викидає виняток `KpolError("Popperian falsification gate failed: M = ... < 1.0")`, якщо хоча б один мутант вижив.

## 6. Висновок

KPOL v0.7 ліквідує феномен «тестів заради галочки». Жоден рядок логіки в Kuzmin Machine не може бути скомпільований у залізо, якщо він не захищений суворим доказом, здатним виявити будь-яку мутацію.
