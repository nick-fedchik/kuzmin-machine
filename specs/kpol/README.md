# Специфікації KPOL

* **Версія:** 0.3.0
* **Дата:** 2026-11-12

**Ціль для розробки #8 —
[KPOL-CME-1 і ABI CME-RAW-1](kpol-cme-subset-0.1.0.md).**
Це запропонована початкова підмножина B3 з граматикою, семантикою,
правилами відмови, трасуванням і приймальними сценаріями.
Decision B3-01 ще потребує явного прийняття власником у PR для
[#19](https://github.com/nick-fedchik/kuzmin-machine/issues/19).
Документ не заявляє, що поточний компілятор уже виконує цей контракт.

[Консолідований робочий контракт](kpol-consolidated-0.1.0.md) — окремий
**опис наявної реалізації**, ширшої за цільовий профіль, з відомими
дефектами lowering. Злитий у [PR #131](https://github.com/nick-fedchik/kuzmin-machine/pull/131);
[повторна рецензія](https://github.com/nick-fedchik/kuzmin-machine/pull/131#issuecomment-6824578749)
прийняла стан `da4092a`. Формулювання того документа про ще не виконане
архівування описує його власний зріз, а не поточну навігацію.
Жоден із цих документів не є повним стандартом KPOL v1.0.

Особливо: `compile_bram_image` і `compile_concept_microcode_bram_image`
створюють різні 1024-байтні формати; їх не можна взаємозамінювати.
Успішний парсинг не означає підтримки відповідної конструкції CME-бекендом.

## Історичні входи — в Git

**Повні тексти v0.1–v0.9 перенесено в [Git-архів](history.md).**
Старі шляхи містять тільки навігаційні записи з посиланнями на immutable
SHA, а не чинні дельти. Приклади v0.1 збережено незмінними в окремих
fixtures; тести більше не читають стару специфікацію. Історичні звіти
та raw не переписано. Деталі залежностей і команда відновлення —
у history.md.

Незалежний аудит v0.2–v0.9: [reviews/kpol-0.2-0.9-audit-review.md](reviews/kpol-0.2-0.9-audit-review.md) — вердикт **No-Go для стандарту v1.0**. Виправлення за аудитом: [experiments/KPOL-FIX/report.md](../../experiments/KPOL-FIX/report.md).

Для фактичної підтримки використовувати §6 робочого контракту; для
дозволу/відмови цільового бекенду — §§2, 5–7 KPOL-CME-1.
Історичні оцінки «реалізовано» не переносяться в новий профіль.

Імена історичних файлів зберігають SemVer 2: `0.N.0` відповідає
колишній `vN.0`; v0.1 — колишня «Draft». Версія навігаційного запису
в його шапці не є новою версією історичної специфікації.
