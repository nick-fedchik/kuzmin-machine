## Мета та формат відповіді

Цей документ просить автора уточнити походження, семантику й доказову базу описаної мови та архітектури. Це не звинувачення у плагіаті й не припущення, що проєкт уже пройшов апаратну перевірку. Відповіді допоможуть відокремити первинні твердження автора від пізніших реконструкцій і планів.

Для кожного питання позначте один чи кілька варіантів, де це доречно. Додайте коротке пояснення, точне посилання на сторінку/розділ/версію джерела та, за можливості, датований артефакт (специфікацію, код, трасу, звіт вимірювання). Якщо жоден варіант не підходить, оберіть «Інше» й уточніть.

### Q08. Як узгодити заборону само-тригера з `Nod` та ітераційними прикладами?

У матеріалах правило не породжувати повторне спрацювання співіснує з прикладами, де оновлення `a -= b` має повторно перевірити `a > b` (`Пример для АН.pdf`, с. 3 і 11; HLL, § 5.4).

- [ ] Заборона діє лише на рекурсивний повторний вхід у поточний обробник.
- [ ] Заборона діє на атрибут.
- [ ] Заборона діє на весь концепт.
- [ ] Заборона діє лише в межах транзакції/активації.
- [ ] У прикладі або правилі є помилка; правильний варіант: …
- [ ] Інше: …

Наведіть покрокову трасу `Nod(120, 6)` і поясніть, чому вона завершується з результатом 6; окремо покажіть поведінку циклічного правила.

- [ ] `←` читає з пам’яті/адреси до регістра; `→` записує з регістра до пам’яті.
- [ ] Значення залежить від контексту/операндів.
- [ ] У таблиці або прикладах є помилка; виправлення: …
- [ ] Інше: …

Надайте виправлену таблицю ISA та щонайменше один повний тест кодування/декодування.

## 3. Статус FPGA-проєкту та інженерні твердження

### Q13. Який фактичний стан FPGA-досліджень?

За поточним уточненням до цього опозиційного звіту, FPGA-дослідження ще не проводилися. Просимо підтвердити формулювання або уточнити статус:

- [x] Апаратні дослідження ще не проводилися; є лише архітектурна пропозиція й ручні оцінки.
- [ ] Є RTL, але його не симулювали.
- [ ] RTL-симуляцію проведено; додаю testbench і результати.
- [ ] Виконано synthesis/place-and-route; додаю звіти Vivado та версію інструментів.
- [ ] Дизайн завантажено на плату; додаю bitstream, конфігурацію та журнал тестів.
- [ ] Інше: …

Уточніть, що означає слово «синтезований» у вступі та § 4.1 FPGA-документа, якщо синтезу/досліджень іще не було.

### Q14. Які саме числа FPGA є виміряними, а які — цільовими оцінками?

Для кожного показника позначте статус: LUT, DSP, частота, latency, GOPS, кількість ядер, потужність.

- [ ] Усі наведені числа — оцінки/цілі.
- [ ] Частину показників виміряно; перелік і докази: …
- [ ] Результати вимірювань є, але не включені до поточного пакета.
- [ ] Інше: …

Для кожного виміряного показника наведіть вихідний звіт, плату, версію Vivado, constraints і налаштування.

### Q15. Яка формула ресурсів є правильною?

У FPGA-документі (§ 2.1) формула дає для `P=32` значення 56 832 LUT, тоді як таблиця наводить 53 024 LUT.

- [ ] Формула правильна; таблиця/графік містять помилку.
- [ ] Таблиця правильна; формулу треба виправити.
- [ ] Обидва значення — грубі оцінки, не результат синтезу.
- [ ] Інше: …

Надайте виправлений розрахунок для `P=8,16,24,32` та позначте, які блоки/припущення входять у кожен член формули.

### Q16. Чи є `Do ^` степенем, зсувом або ще не реалізованою операцією?

У наведеному RTL (§ 4.3) для показника понад 3 використано зсув `nos_i << tos_i[5:0]`, що для `3^4` дає 48, а не 81.

- [ ] Операція має бути степенем; RTL є помилковим.
- [ ] Операція має бути зсувом; назва/специфікація помилкова.
- [ ] Це псевдокод або незавершений фрагмент, не реалізація.
- [ ] Інше: …

Наведіть тест-вектори для показників 0–5, граничних значень і правила обробки переповнення.

### Q17. Яка семантика числових типів у порівнянні?

У FPGA-фрагменті Float порівнюється цілочисельними операціями, а `DO_CMP` не розрізняє signed/unsigned.

- [ ] Float/Double поки не підтримуються апаратно.
- [ ] Є окремий comparator; його RTL/тест: …
- [ ] Специфікацію типів треба виправити.
- [ ] Інше: …

Уточніть IEEE-754, NaN, signed/unsigned U64 і кодування всіх бітів форматів Do/Sys.
