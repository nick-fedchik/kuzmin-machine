## 2. Підтверджені результати (TRL 3)

### 2.1. Програмний стек мови KPOL (15 тестів, 144 підтести)
У модулі [`03-engineering-software/test_kpol_reference.py`](../../../../sw/kpol-ref/tests/test_kpol_reference.py) на 100% підтверджено:
* Атомарний відкат транзакції: при порушенні інваріанта жоден концепт не оновлюється (`test_invariant_failure_rolls_back_whole_transaction`).
* Ізоляція шуму: при надходженні невизначеного значення `UNKNOWN` (`_`) накопичені дані лічильника зберігаються без спотворення (`test_meter_rejects_unknown_without_losing_accumulated_energy`).
* Математична збіжність алгоритму Евкліда на 144 випадкових парах чисел.
* Спрацьовування захисту від зовнішньої апаратної загрози `Hazard`.

### 2.2. Статичний аналіз графа залежностей подій EDG (9 тестів)
У модулі [`04-verification-and-qa/test_km_static_analyzer.py`](../../../../sw/tools/static-analyzer/tests/test_km_static_analyzer.py) на 100% підтверджено:
* Виявлення реактивного шторму (`KM-E001`): алгоритм Тар'яна знаходить цикл взаємної рекурсії $Ping \leftrightarrow Pong$ без спадної функції рангу.
* Допуск безпечних циклів (`KM-I001`): цикли з доведеним монотонним варіантом $V(\Sigma)$ успішно верифікуються.
* Детекція станів гонитви Бернштейна (`KM-E002`): виявляються всі типи паралельних конфліктів (`RAW`, `WAW`, `WAR`) у групах без Великої крапки `•`.
* Усунення гонитви Великою крапкою (`•`): рознесення операторів у фази 0 та 1 повністю ліквідує гонитву за даними.
* Гарантований розрахунок WCET за формулою Грехема — Брента для 8-ядерного прискорювача.

### 2.3. Програмний контракт драйвера прямого MMIO (MockMMIO, 8 тестів)
У модулі [`04-verification-and-qa/test_kpol_direct_mmio.py`](../../../../sw/runtime/pynq/tests/test_kpol_direct_mmio.py) у режимі програмної емуляції (`MockMMIO`) підтверджено коректність логіки взаємодії з регістровою картою:
* Зчитування регістру ідентифікації (`0x14`): сигнатура `0x4B504F4C` (ASCII `'KPOL'`).
* Валідний Commit: перехід бітів `done` та `committed`, оновлення стану.
* Input Reject: відхилення транзакції при хибних передумовах зі збереженням стану.
* Invariant Reject: відхилення транзакції при хибному інваріанті.
* Hazard Abort: аварійне скидання транзакції при спостереженні небезпеки та блокування при невизначеній небезпеці (`Unknown Hazard`).
> *Застереження:* Цей тест доводить виключно коректність програмної обгортки Python, але не є доказом успішного проходження апаратних транзакцій на шині кремнію.

### 2.4. Апаратна RTL-симуляція та логічний синтез
* Симуляція в Icarus Verilog підтвердила коректність роботи скінченного автомата однословного транзакційного шлюзу [`kpol_txn_gate.sv`](../../../../hw/rtl/core/kpol_txn_gate.sv) та AXI4-Lite обгортки [`kpol_txn_gate_axi_lite.sv`](../../../../hw/rtl/bus/kpol_txn_gate_axi_lite.sv).
* Строгий лінтинг у Verilator 5.032 не виявив комбінаційних петель чи проблем розрядності (`0 warnings, 0 errors`).
* Логічний синтез Yosys (`synth_xilinx`) підтвердив, що модуль `kpol_txn_gate` мапиться на примітиви Xilinx 7-ї серії та займає **21 логічну комірку** (Estimated LCs).

## 3. Чіткі межі та вимоги для досягнення TRL 4

1. **Апаратний AXI Interconnect та прив'язка до PS7:**
   Оминання `.hwh` вирішує лише питання драйвера в Python. У самій матриці PL необхідно апаратно реалізувати або згенерувати інтерконект між шиною процесора `M_AXI_GP0` та портом `kpol_txn_gate_axi_lite`. Без цього будь-який запит за адресою `0x40000000` викличе `Bus error` на рівні Linux.
2. **Скомпільований бітстрім:**
   Необхідно згенерувати цільовий файл `.bit` / `.bin` для кристала `xc7z020clg400-1` (через потік openXC7 із Zynq wrapper або Vivado).
3. **Прошивання на стенді:**
   Завантажити бітстрім на плату `pynq2` за допомогою `/usr/bin/openFPGALoader -b pynq_z1` або через `pynq.Bitstream.download()`.
4. **Фізичні вимірювання (HIL):**
   Виконати скрипт [`02-engineering-hardware/deploy/kpol_direct_mmio_driver.py`](../../../../sw/runtime/pynq/kpol_direct_mmio_driver.py) безпосередньо у середовищі Python на платі PYNQ-Z1, зафіксувати фізичні затримки транзакцій та зняти статус блокування TRL 4.
