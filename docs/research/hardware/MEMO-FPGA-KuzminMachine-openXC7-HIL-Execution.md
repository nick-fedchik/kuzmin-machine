## 1. Контекст та епістемічна чесність

У попередніх випробуваннях від 7 листопада 2026 року (див. [`MEMO-FPGA-KuzminMachine-FirstAttempt-log.txt`](../../archive/drafts-774d575-kuzminmachine.tar.gz) (член архіву: `02-engineering-hardware/MEMO-FPGA-KuzminMachine-FirstAttempt-log.txt`)) проводилося введення стенда в експлуатацію (board commissioning) із завантаженням фабричного образу `base.bit` та програмною емуляцією перемикання світлодіодів. Тоді власний бітстрім був відсутній через брак САПР Xilinx Vivado.

За згодою користувача від 8 листопада 2026 року було розгорнуто повністю відкритий стек інструментів **openXC7** на хості `x86_64` (каталог `~/opt/openxc7`), виконано наскрізну компіляцію RTL-модуля транзакційного шлюзу KPOL та проведено реальне апаратне випробування у кремнії PL Zynq-7000 через фізичну шину AXI4-Lite.

> [!IMPORTANT]
> **Умови безпеки та регламент роботи з платою:**
> - Завантаження бітстріму виконувалося **виключно у volatile PL (конфігураційну SRAM FPGA)**.
> - Енергонезалежна пам'ять (QSPI Flash, системний розділ SD-картки, `BOOT.BIN`) **не модифікувалася**.
> - Одразу після завершення випробувань штатний базовий стан плати відновлено повторним завантаженням оверлею `/lib/firmware/base.bin`.

## 3. RTL-архітектура та збірка цільового бітстріму

### 3.1. Синтезований модуль
Top-level модуль [`kpol_txn_gate_pynq_z1_top.v`](../../../hw/boards/pynq-z1/kpol_txn_gate_pynq_z1_top.v) об'єднує:
1. Апаратний примітив `PS7` (Processing System 7), налаштований на видачу тактової частоти `FCLK0` та порт головної шини `MAXIGP0` (AXI Master).
2. Тактовий буфер `BUFG` (`fclk0_buf`).
3. Апаратний шлюз [`kpol_txn_gate_axi_lite.sv`](../../../hw/rtl/bus/kpol_txn_gate_axi_lite.sv), підключений як MMIO slave за базовою адресою `0x40000000` (вікно `0x40000000 - 0x4000003F`).
4. Ядро атомарної валідації [`kpol_txn_gate.sv`](../../../hw/rtl/core/kpol_txn_gate.sv).
5. Фізичні піни плати PYNQ-Z1 (файл обмежень [`pynq_z1.xdc`](../../../hw/boards/pynq-z1/pynq_z1.xdc)):
   - **Зелені світлодіоди LD0..LD3:** LD0 = `committed` (номінальний коміт), LD1 = `rejected_invariant` (відхилення при порушенні інваріанта), LD2 = `hazard_observed`, LD3 = `rejected_input`.
   - **Багатоколірний світлодіод RGB4:** Зелений = успішний коміт, Червоний = порушення інваріанта (Fail-Closed Red Alert), Синій = невалідний вхід або аварія.
   - **Багатоколірний світлодіод RGB5:** Пульсуючий бірюзовий маяк (Heartbeat ~1.5 Гц від лічильника тактової частоти 100 МГц).
   - **Кнопка BTN0 та перемикачі SW0/SW1:** апаратний антибрязкіт (~10.4 мс) та можливість запуску транзакції як кнопкою вручну, так і програмно через AXI MMIO.

### 4.1. Протокол виконання транзакцій

```text
[HIL TEST LOG - 2026-11-08 12:28:56 EET]
1. Ініціалізація та завантаження SRAM PL:
   - Пристрій: EmbeddedDevice (/dev/fpga0, f8007000.devcfg)
   - Бітстрім: /home/xilinx/kpol_pynq.bit (4,045,719 байтів)
   - Статус завантаження: УСПІШНО (конфігураційна пам'ять прийняла бітстрім).

2. Прив'язка драйвера MMIO:
   - Базова фізична адреса: 0x40000000 (M_AXI_GP0)
   - Діапазон пам'яті: 0x1000 байтів

3. Верифікація апаратного ID (REG_ID, зсув 0x14):
   - Очікувано: 0x4B504F4C ("KPOL")
   - Зчитано з шини: 0x4B504F4C
   - Результат: MATCH (апаратний блок KPOL відповідає на шині AXI)

4. Сценарій 1: Номінальна атомарна транзакція (Nominal Commit):
   - Запис REG_CANDIDATE (0x00)   <= 0x00001234
   - Запис REG_CONDITIONS (0x04)  <= 0x0000003F (всі передумови та інваріант валідні, hazard відсутній)
   - Запис REG_COMMAND (0x08)     <= 0x00000001 (EXECUTE)
   - Зчитування REG_STATUS (0x0C) => 0x00000003 (STATUS_VALID | STATUS_COMMITTED)
   - Зчитування REG_STATE (0x10)  => 0x00001234
   - Результат: MATCH (транзакція зафіксована за 1 такт)

5. Сценарій 2: Порушення інваріанта (Invariant Fail-Closed Rejection):
   - Запис REG_CANDIDATE (0x00)   <= 0x00005678 (спроба записати нове значення)
   - Запис REG_CONDITIONS (0x04)  <= 0x0000002F (біти invariant_true=0, invariant порушено!)
   - Запис REG_COMMAND (0x08)     <= 0x00000001 (EXECUTE)
   - Зчитування REG_STATUS (0x0C) => 0x00000015 (STATUS_VALID | STATUS_REJECTED | STATUS_REJECTED_INVARIANT)
   - Зчитування REG_STATE (0x10)  => 0x00001234
   - Результат: MATCH (апаратне блокування спрацювало безвідмовно: небезпечний кандидат 0x5678 відкинуто, стан 0x1234 збережено без спотворень)

VERDICT: PASS: KPOL ID, nominal commit, and invariant fail-closed behavior (state=0x00001234)
```
