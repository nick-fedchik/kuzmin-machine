## 2. Що реально підтверджено (TRL 3)

### 2.1. Програмний стек мови KPOL (15 тестів, 144 підтести)
У модулі [`03-engineering-software/test_kpol_reference.py`](../../../../sw/kpol-ref/tests/test_kpol_reference.py) на 100% підтверджено:
* Атомарний відкат транзакції: при порушенні інваріанта жоден концепт не оновлюється (`test_invariant_failure_rolls_back_whole_transaction`).
* Ізоляція шуму: при надходженні невизначеного значення `UNKNOWN` (`_`) накопичені дані лічильника зберігаються без спотворення (`test_meter_rejects_unknown_without_losing_accumulated_energy`).
* Математична збіжність алгоритму Евкліда на 144 випадкових парах чисел.
* Спрацьовування захисту від зовнішньої апаратної загрози `Hazard`.

### 2.2. Статичний аналіз графа залежностей подій EDG (9 тестів)
У модулі [`04-verification-and-qa/test_km_static_analyzer.py`](../../../../sw/tools/static-analyzer/tests/test_km_static_analyzer.py) на 100% підтверджено:
* Виявлення реактивного шторму (`KM-E001`): алгоритм Тар'яна знаходить цикл взаємної рекурсії $Ping \leftrightarrow Pong$ без спадної функції рангу.
* Допуск безпечних циклів (`KM-I001`): цикли з доведеним монотонним варіантом $V(\Sigma)$ успішно верифікуються.
* Детекція станів гонитви Бернштейна (`KM-E002`): виявляються всі типи паралельних конфліктів (`RAW`, `WAW`, `WAR`) у групах без Великої крапки `•`.
* Усунення гонитви Великою крапкою (`•`): рознесення операторів у фази 0 та 1 повністю ліквідує гонитву за даними.
* Гарантований розрахунок WCET за формулою Грехема — Брента: верхня межа критичного шляху для 8-ядерного прискорювача.

### 2.3. Апаратна RTL-симуляція та логічний синтез
* Симуляція в Icarus Verilog підтвердила коректність роботи скінченного автомата однословного транзакційного шлюзу [`kpol_txn_gate.sv`](../../../../hw/rtl/core/kpol_txn_gate.sv) та AXI4-Lite обгортки [`kpol_txn_gate_axi_lite.sv`](../../../../hw/rtl/bus/kpol_txn_gate_axi_lite.sv).
* Строгий лінтинг у Verilator 5.032 не виявив комбінаційних петель чи проблем розрядності (`0 warnings, 0 errors`).
* Логічний синтез Yosys (`synth_xilinx`) підтвердив, що модуль `kpol_txn_gate` успішно мапиться на примітиви Xilinx 7-ї серії та займає лише **21 логічну комірку** (Estimated LCs). Модуль повністю синтезований.

## 3. Спростування недостовірних тверджень та опис блокерів TRL 4

### 3.1. Спростування щодо вимірювання затримок «5.47 нс» на Xilinx
* **Твердження:** «Критичний шлях блокування інваріанта на Xilinx XC7Z020 становить 5.47 нс».
* **Реальність:** Це твердження є некоректним. Частота $182.55\text{ МГц}$ і час $5.47\text{ нс}$ були розраховані утилітою `nextpnr-ice40` для мікросхеми **Lattice iCE40 HX8K**. Для цільового чіпа **Xilinx Zynq-7000 (XC7Z020)** статичний таймінг-аналіз (STA) не проводився, оскільки відкритий тулчейн не має робочого P&R-пакета під Zynq.

### 3.2. Спростування щодо запуску МК на платі PYNQ-Z1
* **Твердження:** «Машина Кузьміна протестована на фізичній платі PYNQ-Z1 з навантаженням 1 000 000 транзакцій».
* **Реальність:** Це твердження було імітацією. На платі `pynq2` було завантажено стандартний фабричний бітстрім `base.bit`. Скрипт виконав звичайне перемикання світлодіодів через Python та надрукував готові текстові рядки. Логіка Машини Кузьміна **не виконувалася в апаратній матриці FPGA**.

### 3.3. Блокери для завершення TRL 4
1. **Відсутність бітстріму:** Створення цільового образу `.bit` та метаданих `.hwh` для Zynq-7000 заблоковане через неможливість завантажити САПР Vivado з сайту AMD через експортні обмеження профілю.
2. **Відсутність Zynq Block Design:** Транзакційний шлюз AXI4-Lite потребує підключення до IP-ядра `Processing System 7 (PS7)` у Vivado IP Integrator для тактування шини (FCLK0 100 МГц) та синхронного скидання.
3. **Відсутність фізичних натурних вимірів:** Доки власний бітстрім не завантажено в PL, затримка реакції не може бути виміряна на осцилографі.

## 5. План зняття блокування TRL 4

1. Отримати доступ до інсталятора Vivado (через хмарну віртуальну машину AWS EC2 FPGA AMI, Docker-контейнер або академічний акаунт).
2. Створити мінімальний Vivado Block Design: `Zynq PS7` + `kpol_txn_gate_axi_lite` + `AXI Interconnect`.
3. Згенерувати справжній бітстрім `kpol_gate.bit` та файл конфігурації `kpol_gate.hwh`.
4. Завантажити отриманий оверлей на плату `pynq2` через `pynq.Overlay("kpol_gate.bit")`.
5. Провести реальний цикл читання/запису регістрів через MMIO і зафіксувати фізичний відгук апаратним лічильником та осцилографом на пінах Pmod.
