## 1. Метод

| Крок | Інструмент | Примітка |
| :--- | :--- | :--- |
| Генерація | `compile_axi_lite_wrapper` | Ширина даних 32, ширина адреси 6, параметри за замовчуванням |
| Обгортка з властивостями | [`axi64_props.sv`](scripts/axi64_props.sv) | DUT не змінено; припущення щодо master і тіньова модель регістрів |
| Доказ | Yosys 0.52 → AIGER → ABC 1.01 `pdr` | Необмежений доказ (IC3/PDR). Припущення AIGER трактує як обмеження. Початковий стан — нулі (`-zinit`), а перший такт є скиданням |
| Перехресна перевірка | `yosys-smtbmc` + Z3 4.13.3, BMC `-t 8` | Довільний початковий стан регістрів |
| Невакуумність | `yosys-smtbmc -c -t 10` | 7 сценаріїв із критерію |
| Мутанти | [`run_axi64_formal.py`](scripts/run_axi64_formal.py) | Точна текстова заміна, рівно 1 збіг. Для назви порушеної властивості BMC запускають на глибині кадру контрприкладу + 1 |

**Відхилення від запланованого методу.** Заплановано BMC і k-індукцію глибиною
30. Z3 не завершив BMC глибиною 30 за понад 8 хв, тому доказ виконано через
PDR. Відхилення записано в #64 до офіційного прогону.

## 2. Властивості

Припущення щодо master такі:
- скидання триває перший такт;
- під час скидання VALID = 0;
- VALID і корисне навантаження AW, W та AR стабільні до рукостискання.

| ID | Твердження | Клас F-04 / вимога ARM IHI 0022 |
| :--- | :--- | :--- |
| `P1_b_stable` | Якщо `BVALID ∧ ¬BREADY`, то в наступному такті `BVALID = 1`, а `BRESP` не змінюється | Стабільність B; Case D |
| `P2_r_stable` | Якщо `RVALID ∧ ¬RREADY`, то в наступному такті `RVALID = 1`, а `RDATA` і `RRESP` не змінюються | Стабільність R |
| `P3_b_count` | `min(#AW, #W) − #B ∈ {0,1}` і дорівнює `BVALID` | Одна відповідь B на пару; немає запису без AW (Case A) |
| `P4_r_count` | `#AR − #R ∈ {0,1}` і дорівнює `RVALID` | Одна відповідь R на AR |
| `P5_data` | Прочитане з 0x00, 0x04 або 0x08 дорівнює тіньовій моделі: адреса з AW, WSTRB побайтово; незмаповане читається як 0 | Case B, Case C |
| `P6_reset` | Після скидання `BVALID = RVALID = 0` | Скидання |

## 4. Межі

* Перевірено лише один модуль з параметрами за замовчуванням. Шаблон від
  модуля не залежить, але інші ширини не перевірялися.
* Не перевірено AWPROT/ARPROT (входи ігноруються), відповіді SLVERR/DECERR
  (генератор завжди повертає OKAY) і лічильник 0x10.
* Не перевірено функціональний зв'язок `EVENT_ID`/`PARAM0` з `dispatch` (F-04,
  друга частина) та обмеження лічильника (F-19). Це не протокольні властивості.
* Чи залежить VALID від READY, явно не перевіряли. BVALID і RVALID у генераторі —
  виходи регістрів.
* Не було сертифікованого VIP, інтеграції з PS Zynq і фізичного прогону.
* Ручні обгортки [`kpol_txn_gate_axi_lite.sv`](../../hw/rtl/bus/kpol_txn_gate_axi_lite.sv)
  та [`kpol_bram_pipeline_axi.sv`](../../hw/rtl/bus/kpol_bram_pipeline_axi.sv)
  не є об'єктом; див. [#48](https://github.com/nick-fedchik/kuzmin-machine/issues/48).

## Абревіатури та глосарій

* **AXI4-Lite** — спрощений протокол шини AMBA (ARM IHI 0022).
* **BMC** — обмежена перевірка моделі.
* **IC3/PDR** — алгоритм необмеженого доказу інваріантів.
* **Cover** — перевірка досяжності сценарію, тобто невакуумності властивостей.
* **Мутант** — навмисно внесений дефект для перевірки чутливості.
* **VIP** — верифікаційний IP.
* **HIL** — перевірка на апаратному стенді.
