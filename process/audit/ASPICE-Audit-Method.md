# Методика незалежного аудиту проєкту за ASPICE 4.0 і TRL

* **Версія:** 0.2.0 (чернетка) · **Дата:** 2026-11-09 · **Власник:** Микола Федчик
* **Джерело моделі:** Automotive SPICE PAM v4.0 (VDA QMC). Шкалу рейтингів і правило рівня 1 звірено з текстом PAM. Сам PAM аудитор завантажує з сайту VDA QMC; у репозиторії його не зберігаємо.
* **Статус методу:** спрощений внутрішній аудит. **Це не оцінювання ASPICE** в розумінні VDA: немає сертифікованого асесора, а метод рейтингу R1–R3 формально не застосовується.

---

## 1. Мета

Незалежно встановити, чи досягають процеси проєкту рівня можливостей 1 (Performed) і чи підтверджено доказами заявлений рівень TRL.

## 2. Незалежність аудитора

1. Аудитор — агент у **новій сесії** без доступу до розмов авторів. Бажано іншої моделі, ніж основний виконавець.
2. Аудитор не був автором чи рецензентом жодного об'єкта аудиту в межах цієї базової версії.
3. Аудитор отримує лише: назву репозиторію, **тег базової версії**, цю методику, PAM 4.0.
4. Аудитор нічого не змінює в репозиторії, крім свого звіту в окремій гілці. Знахідки стають Issues після рішення власника.

## 4. Шкала

Рейтинг BP та атрибута процесу PA 1.1 (PAM 4.0):

| Рейтинг | Значення | Досягнення |
| :--- | :--- | :--- |
| N | Not achieved | 0 – ≤ 15 % |
| P | Partially achieved | > 15 – ≤ 50 % |
| L | Largely achieved | > 50 – ≤ 85 % |
| F | Fully achieved | > 85 – ≤ 100 % |

**Рівень 1 досягнуто**, якщо PA 1.1 = L або F.

## 5. Правила доказів

1. **Немає доказу — N.** Наміри, плани «зробимо», чернетки й обіцянки в чатах доказом не є.
2. Доказ — файл або Issue/PR **на тезі базової версії**. Те, що з'явилося після тегу, не враховується.
3. Кожен доказ — посилання на конкретний файл чи рядок, Issue або PR.
4. Твердження про результати перевіряються **повторним виконанням** там, де це дешево:
   - `pytest` і CI;
   - lint RTL;
   - перевірка посилань `python3 tools/check_links.py` і, коли з'явиться (крок S2), скрипт трасування;
   - аналіз сирих даних щонайменше для одного експерименту AV-xx (перерахувати зведені числа із `raw/`).
5. Перевірка тестів на бутафорію: для щонайменше 3 випадково обраних тестів аудитор вносить дефект у копію коду й перевіряє, що тест падає. Копію відкидає.
6. Документи, що заявляють відповідність стандартам або сертифікацію без доказів, — знахідка `sev:major`.

## 6. Порядок аудиту

1. **Фіксація.** Записати тег `vX.Y.Z`, SHA, дату, модель аудитора.
2. **Інвентаризація.** Скласти перелік робочих продуктів і зіставити його з інформаційними елементами PAM: 17-00 Requirement, 13-51 Consistency Evidence, 13-08 Baseline, 13-07 Problem, 13-16 Change request, 15-09 Risk status, 13-19 Review evidence, 13-25 Verification results та інші.
3. **Оцінка BP.** Для кожного процесу й кожної BP: доказ (посилання) → рейтинг N/P/L/F → одне-два речення обґрунтування.
4. **PA 1.1.** Рейтинг за процесом з обґрунтуванням агрегування. Механічно не усереднювати: відсутній ключовий результат процесу обмежує рейтинг.
5. **Перевірка TRL.** Заявлений рівень звірити з критеріями ISO 16290 і доказами в [паспорті TRL](../trl/TRL-passport.md). Кожен критерій: доказ є / немає / частково. Висновок: підтверджено, не підтверджено або підтверджено з умовами.
6. **Знахідки.** Кожна знахідка: ID `A-<дата>-NN`, процес / BP, `sev`, факт, доказ, наслідок, рекомендація. Факт і судження відокремлені.
7. **Що не перевірено.** Окремий обов'язковий розділ: що не вдалося перевірити й чому.
8. **Звіт** — у `process/audit/reports/Audit-<YYYY-MM-DD>-<тег>.md` за шаблоном нижче. PR, рішення власника.

## 7. Поведінка аудитора

- Без компліментів і без розділу «сильні сторони», якщо їх не підкріплено доказами.
- Не завищувати рейтинг через «молодий проєкт» або «агенти старалися».
- Не занижувати рейтинг для враження суворості: кожен рейтинг обґрунтовано доказом або його відсутністю.
- Вказувати ступінь упевненості (висока / середня / низька), якщо доказ непрямий.
- Рекомендації — найменші кроки, що закривають знахідку. Без пропозицій нових процесів понад обсяг.

## 9. Промпт для незалежного агента

> Ти — незалежний аудитор процесів. Проведи аудит репозиторію `nick-fedchik/kuzmin-machine` на тезі `<тег>` за методикою `process/audit/ASPICE-Audit-Method.md`, версія `<v>`. Завантаж Automotive SPICE PAM v4.0 з сайту VDA QMC і бери назви BP лише з нього.
>
> Не читай історію обговорень авторів і не змінюй файли репозиторію, крім свого звіту в гілці `audit/<N>-<дата>`, де `<N>` — номер Issue на аудит. Рейтинг без доказу — N. Повтори дешеві перевірки (§5.4–5.5) і запиши команди та результати.
>
> Пиши українською, без компліментів, з обов'язковим розділом «Що не перевірено». Результат — один файл звіту за шаблоном §8 і PR. Більше нічого не роби.
