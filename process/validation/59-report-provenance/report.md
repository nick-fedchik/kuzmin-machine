## 1. Що не вдалося і обмеження

**Критерій повного походження чисел не виконано; S1 не пройдено.**
У всіх трьох первинних зведеннях AV-03 поле `metadata.git_commit` має
значення `unknown`. Точний коміт вимірювання цими записами не встановлено;
коміт перенесення файла не є його заміною.

| Первинне джерело | Поле коміту |
| :--- | :--- |
| [AV-03 host](../../../experiments/AV-03/raw/av03_host_summary.json) | `unknown` |
| [AV-03 Jetson](../../../experiments/AV-03/raw/av03_jetson_orin_summary.json) | `unknown` |
| [AV-03 PYNQ](../../../experiments/AV-03/raw/av03_pynq2_cortex_a9_summary.json) | `unknown` |

Новий перевіряльник також не підтверджує машинне покриття жодного з наявних
канонічних звітів: у них немає sidecar-файлів нового формату. **Це не тотожне
відсутності всіх історичних доказів.** Наприклад, AV-04 і AV-08 уже містять
первинні файли provenance. Відсутність нового формату не використовується
як самостійне спростування їхніх результатів.
Їхні історичні коміти `20b63a9faaacbb371bad0d34c1f7519d1bcf63e7` та
`62219ef0927bc0ca427deabc533833fa41960e43` належать `drafts` і відсутні
в історії `kuzmin-machine`: наявність файлів provenance не означає,
що поточний інструмент перевірив доступність цих комітів у іншому репозиторії.

Інструмент перевіряє наявність та структурну цілісність трасування рядків із
цифровими символами; він не розпізнає числа словами, не перевіряє істинність
довільного тексту, не перераховує числові результати з вибірок і не доводить,
що зазначена команда справді запускалась. Відтворення AV-04/07/08 залишається
окремою [Issue #75](https://github.com/nick-fedchik/kuzmin-machine/issues/75).
Тести перевіряльника синтетичні, не апаратні. TRL не підвищено.

## 2. Метод

Реалізовано [перевіряльник](../../../tools/check_report_provenance.py)
і [контракт трасування](../../../tools/report-provenance.md), на який
тепер посилається [шаблон звіту](https://github.com/nick-fedchik/kuzmin-machine/blob/fc97238a5491aca19b820d570d4bcf6c66202f23/process/templates/report.md).

Після рецензії автоматично інвентаризуються всі `.md`/`.txt` у
`experiments/` рекурсивно й без залежності від регістру розширення.
Виключено лише кореневий `PLAN.md` і каталоги `raw/`, `scripts/`.
Для кожного числового рядка потрібен валідний запис про прогін:
команда, повний доступний SHA коміту, дата з часовим поясом, хост,
сирі файли цього експерименту та їхні SHA-256. SHA-256 самого звіту
не дозволяє мовчки використати застарілу нумерацію рядків.

Неповне покриття, відсутній або змінений сирий файл, невалідний коміт чи
порожній обсяг перевірки дають ненульовий код завершення. Інструмент не
виконує команд із метаданих. У старі звіти й сирі дані нічого не дописували.
JSON розрізняє `STRUCTURAL_PASS` / `STRUCTURAL_FAIL` і завжди повертає
`s1_status: NOT_ASSESSED`, `result_values_verified: false`,
`metadata_authenticated: false`. Отже, навіть структурний успіх не є
підтвердженням походження або правильності числа. Додано перевірку, що
дата не раніша за committer date коміту й не пізніша за поточний час.

Аудит виконано `2026-11-10T08:56:42.888707+00:00`. Його запис містить
команду, код завершення, SHA перевіряльника, SHA звітів, інвентар рядків,
метадані хоста та копії полів первинних записів AV-03 з їхніми SHA-256.

## 4. Перевірка гіпотези / критеріїв

| Критерій | Очікувано | Отримано | Висновок |
| :--- | :--- | :--- | :--- |
| Автоматична перевірка, не лише ручний огляд | Виконуваний інструмент з негативними тестами | Реалізовано; реальний негативний результат збережено | Реалізацію підготовлено до незалежної рецензії |
| Усі числа мають команду, коміт, дату й raw | Повне трасування без невідомого коміту | AV-03: первинні записи містять `git_commit: unknown`; машинне покриття канонічних звітів не підтверджене | Критерій S1 не виконано |
| Не вигадувати відсутні докази | Незмінні історичні дані | Метадані не підставляли; нових вимірів замість старих не заявляли | Відсутні дані залишено явними |

Прийняття реалізації #59 не означатиме проходження S1. Необхідно окремо
відновити походження з первинних доказів або виконати нові, правильно
задокументовані вимірювання. Старі результати при цьому не переписувати.
Рішення про прийняття PR — після незалежної рецензії, не автором.

### 4.1. Відповідь автора на F1–F6

| Зауваження | Зміна та залишкові межі |
| :--- | :--- |
| F1 | Рекурсивний пошук `.md`/`.txt`, незалежний від регістру й номера експерименту; додано регресії для `Report.md`, `.txt`, вкладених шляхів, `KPOL-FIX`, `.MD` |
| F2, F5 | Загальний PASS замінено на `STRUCTURAL_PASS`; у JSON явно заборонено інтерпретацію як S1 або перевірку значень. Перегенерований sidecar з хибним значенням може бути структурно валідним, але не отримує підтвердження S1; тест це фіксує. Прив'язку кожного значення до обчислення з raw не реалізовано |
| F3 | Неможливу хронологію відхилено й протестовано. Автентичність хоста та фактичне виконання команди не доведені; цю частину не оголошено закритою. Whitelist назв або хеш самі не є доказом виконання |
| F4 | У §1 додано застереження про коміти іншого репозиторію |
| F6 | Набір сфокусованих тестів розширено з 27 до 41: discovery, дати, перегенерований sidecar, явна неавтентифікованість, форми JSON і валідний вкладений звіт |

Це перелік змін автора, **не повторна рецензія й не закриття знахідок
від імені рецензента**. Вердикт попередньої рецензії лишається «Не перевірено».

## 5. Відтворення

```bash
git checkout 4f14f6d97037c9dd6acd25c823cdcf251c6b4a68
python3 tools/check_report_provenance.py --json
# Очікувано: код 1, FAIL; цей коміт не містить пізнішого запису аудиту.

```

Виправлену структурну перевірку відтворюють окремо:

```bash
git checkout cc448f1a7e5a6308279d492dc407496db8373bb3
python3 tools/check_report_provenance.py --json
# Код 1, STRUCTURAL_FAIL; s1_status = NOT_ASSESSED.
python3 -m pytest -q
```

Для нового аудиту зберігати вивід у новий файл; наявний запис не
перезаписувати. Значення `metadata.git_commit` можна незалежно перевірити
без запуску експериментів у трьох первинних JSON, наведених у §1.
