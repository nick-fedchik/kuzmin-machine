## 1. Що не вдалося і обмеження

**Повний збіг не отримано; підстав оголошувати S1 пройденим немає.**
Перший числовий контрприклад у AV-08: `S3_rcfc`, `N=4`, порожній seed,
статус `SYNTH_ONLY`. Старий CSV містить **321 LUT**, новий — **328 LUT**.
Це результат синтезу, не вимірювання фізичної затримки чи апаратний тест.
Причину відмінності не локалізовано; допуск, джерела й параметри після
отримання результату не підганяли.

За попередньо опублікованим правилом подальші `S3_rcfc` для
`N=8,16,32,64` **не запускалися**. Їх не зараховано ані як збіг, ані як
розбіжність. Зовнішній драйвер завершився кодом `1`; самі підзапуски
завершилися кодом `0`. Отже, це негативний результат порівняння, не
аварійне завершення інструмента.

Окреме обмеження — **не встановлено тотожність повного історичного
джерельного SHA**:

| Експеримент | Проблема історичного запису |
| :--- | :--- |
| AV-04 | Коміт `20b63a9faaacbb371bad0d34c1f7519d1bcf63e7` доступний у `drafts`, не в приватному клоні; його дерево не містить `av04_gate_props.sv` і `run_av04_formal.py` |
| AV-07 | Первинний JSON не містить Git SHA |
| AV-08 | Коміт `62219ef0927bc0ca427deabc533833fa41960e43` доступний у `drafts`, не в приватному клоні; його дерево не містить `run_av08_scaling.py` |

Докази: [читання історичних файлів](raw/historical-source-audit-20261110.json)
і [пошук у повних деревах комітів](raw/historical-tree-search-20261110.json).
RTL шлюзу AV-04 побайтово збігається з історичним; хеш перенесеного
props-файла збігається з хешем, заявленим у старому provenance. Це корисні
часткові відповідності, але не доказ збереження всього виконуваного досліду
в зазначеному коміті.

Тому висновок стосується **перенесених артефактів на приватній базі
`2518fa3`**. Повтор буквально на тих самих історичних SHA не виконано;
його не оголошено ані підтвердженим, ані спростованим цим запуском.
Розбіжність ресурсів не спростовує концепцію МК загалом. TRL не змінено.

## 2. Метод

Окремий клон із GitHub мав detached HEAD на зафіксованій базі, чистий стан
до й після виконання. Джерела, еталонні результати й старі `raw/` не
редагувалися. [Драйвер](run.py) записував нові результати поза source-клоном;
тимчасовий build також був окремим від source та збережених raw.

| Частина | Метод |
| :--- | :--- |
| AV-04 | Незмінний формальний раннер, Z3 та cvc5, W=8/32, depth=25; вердикти, кількість assert/cover, множини досягнутих і недосягнутих cover-цілей |
| AV-07 | Незмінний набір мутацій і симуляційний раннер; totals, score та status/stage кожного мутанта |
| AV-08 | Новий синтез і, де передбачено початковим раннером, P&R; seed 1/2/3, jobs=1, timeout=3600 секунд на P&R; без `--reparse` |

Час розв'язувача, timestamp, тимчасові шляхи та неєдиний конкретний
контрприклад не порівнювалися — виключення зафіксовані до запуску.
Для AV-08 порівнювалися всі стовпці CSV. Додаткового округлення
[компаратор](compare.py) не застосовує.

Для AV-07 `TMP_DIR` спрямовано у власний тимчасовий каталог, не спільний
`/tmp/av07_mutation`. Згенерований раннером Markdown із застарілим
авторством видалено лише з нового output; він не є цим Report.
JSON і console збережені.

| Інструмент | Фактична версія |
| :--- | :--- |
| Yosys для формальної частини | 0.52, `fee39a3284c90249e1d9684cf6944ffbbcbb8f90` |
| Z3 | 4.13.3 |
| cvc5 | 1.3.2 |
| Icarus Verilog | 12.0 stable |
| openXC7 Yosys | 0.69, `9f75ca1f9` |
| nextpnr-himbaechel | 1.0.0-41-g3e5c2cdd |

Версії, команди, середовище, хеші джерел і еталонів — у preflight.
Кожен підзапуск має `execution.json` із повними argv, cwd, environment
overrides, часом, returncode та хешем console. Це авторські журнали
виконання, не незалежна автентифікація хоста.

Окреме [зауваження до перевірки staged diff](raw/staging-validation-20261110.json):

новим raw. Їхні байти навмисно збережено, не відформатовано під лінтер.
Перевірка коду й документації з виключенням raw проходить; перевірено також,
що Git зберігає raw побайтово, без нормалізації перенесень рядків.

## 4. Перевірка гіпотези / критеріїв

| Критерій | Очікувано | Отримано | Висновок |
| :--- | :--- | :--- | :--- |
| Чистий клон приватної бази | Точний SHA, без змін до й після | `2518fa3`; чистоту й хеші перевірено | Виконано для перенесеної версії |
| Повний збіг вердиктів і чисел | Точність за попереднім протоколом | S3_rcfc N=4: 321 проти 328 LUT | Не виконано |
| Той самий повний історичний SHA | Усі виконувані артефакти зафіксовані в первинному коміті | Деякі раннери й props відсутні в указаних деревах; для AV-07 SHA немає | Не встановлено |
| Не приховувати неповне виконання | Явно показати зупинку та невиконані конфігурації | S3_rcfc N=8,16,32,64 не виконано | Виконано за попереднім протоколом |
| Проходження S1 | Усі вимоги гейту підтверджено | Є розбіжність і невстановлений історичний SHA | Не підтверджено |

Потрібні незалежна рецензія та рішення власника. Прийняття цього
негативного звіту не означатиме прийняття S1. Issue #75 не закривається
автором; наступні задачі поза погодженим паралельним повтором не беруться
до завершення етапу рецензії за WIP.

```bash

  --source /home/mfedchyk/GitHub/nick-fedchik/km-repro-75-clean \
  --out /home/mfedchyk/GitHub/nick-fedchik/km-wt-copilot-75/process/validation/75-reproduce-av/raw/run-20261110-01 \
  --build /home/mfedchyk/.copilot/session-state/8533854a-7756-4530-afda-d6ff033f53b0/files/kuzmin-machine/reproduce75-build-20261110-01
```

Її не слід повторювати з тими самими output-каталогами: драйвер їх
не перезаписує. Для нового дорогого повтору — власний worktree з драйвером
на `e8d5e050f772c2b9fafe17c43df172327ea520dd`, ті самі версії інструментів
і нові каталоги, які ще не існують:

```bash
git clone --no-checkout https://github.com/nick-fedchik/kuzmin-machine.git ../km-repro-75-next
git -C ../km-repro-75-next checkout --detach 2518fa3d856e6ebbe9d894171018d19310de809b
python3 process/validation/75-reproduce-av/run.py \
  --source ../km-repro-75-next \
  --out process/validation/75-reproduce-av/raw/run-next \
  --build /home/mfedchyk/.cache/km-reproduce75-next
```

Оцінювати код завершення за протоколом, а не вимагати штучний `0`:
`1` — розбіжність/помилка; `2` — числовий збіг без підтвердження
історичного SHA. Повторне виконання може дати інші результати;
зафіксований негативний запис при цьому не переписувати.
