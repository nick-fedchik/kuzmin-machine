# Аналітичний звіт: Метрологічне забезпечення вимірювань на Raspberry Pi Pico

* **Версія:** 1.0.0
* **Дата:** 2026-11-12
* **Об'єкт і база:** [`hw/boards/pynq-z1/pico-logic-analyzer-guide.md`](pico-logic-analyzer-guide.md), [`hw/boards/pynq-z1/pico/pico_capture.py`](pico/pico_capture.py), [`hw/tests/test_pico_capture.py`](../../tests/test_pico_capture.py).
* **Автор:** Antigravity (agy)
* **ASPICE 4.0 процеси:** `HWE.3`, `HWE.4`, `SYS.4`, `SYS.5`

## Обмеження

1. Фізична точність вимірювання затримки обмежена тактовою частотою RP2040 (дискретність вибірки $8\text{ нс}$ при 125 МГц та $5\text{ нс}$ при 200 МГц).
2. Затримки передачі через USB CDC хосту не впливають на вимірювання, оскільки всі часові мітки формуються локально на апаратному таймері RP2040.
3. Звіт верифікує алгоритм експорту VCD та математику розрахунку латентності на базі симуляційного генератора `test_pico_capture.py`, що дозволяє запускати перевірку в CI без підключеного фізичного контролера.

## Питання і метод

* **Питання аналізу:**
  1. Чи достатня дискретність вимірювача на базі RP2040 (8 нс) для підтвердження детермінізму BRAM-конвеєра Машини Кузьміна (80 нс)?
  2. Чи забезпечує формат виводу VCD повну сумісність зі стандартними засобами візуалізації осцилограм (PulseView / GTKWave)?
  3. Чи підтверджує автоматизований аналізатор очікуваний бюджет затримки конвеєра ($80\text{ нс}$ обчислення $+ 20\text{ нс}$ CDC)?
* **Метод аналізу:**
  - Розробка юніт-тестів для перевірки алгоритму розпізнавання фронтів (edge detection) та розрахунку інтервалів.
  - Синтез тестового потоку вибірок із точним накладенням затримок 8 тактів FPGA ($80\text{ нс}$) та імпульсу розширювача ($100\text{ нс}$).
  - Перевірка синтаксичної структури згенерованих файлів VCD.

## Результати та висновок

1. **Достатність дискретності:**
   - При латентності конвеєра $80\text{ нс}$ крок дискретизації $8\text{ нс}$ дає роздільну здатність у 10 відліків на цикл виконання, що становить похибку вимірювання $\pm 10\%$, а при частоті 200 МГц ($5\text{ нс}$) — 16 відліків (похибка $\pm 6{,}25\%$). Це повністю достатньо для розрізнення 8-тактового циклу від позаштатних затримок.
2. **Формат VCD:**
   - Тести `test_vcd_export` підтвердили генерацію коректних секцій `$timescale 1ns`, `$scope` та змінних сигналів для 8 каналів.
3. **Розрахунок латентності:**
   - Тест `test_latency_measurement` підтвердив, що розрахована затримка потрапляє в діапазон $90\text{--}110\text{ нс}$ ($100\text{ нс} \pm 1$ відлік).
4. **Висновок:**
   - Розроблений комплекс (прошивка PIO, хост-скрипт захоплення та посібник) повністю забезпечує метрологічний базис для фізичних випробувань стенда HIL (HWE.3/HWE.4).
