## 1. Що не вдалося і обмеження

Не визначено спеціальне тлумачення Max=0, одиницю лічби успішних
виконань, порядок вибору Array та поведінку для інших типів індексів.
Default Min=1/Max=0 і загальне `>=Min` / `<=Max` без додаткового
правила не узгоджуються зі звичайним числовим інтервалом.
Це не виправляється нашою здогадкою про «безмежно», додавання одиниці
чи прихований лічильник. Q-AUTH-01 уточнене частково, не закрите.

Фрагмент не задає кількості тактів, рекурентної реалізації, однотактового
fan-out, фази виконання дужок або native ABI. Compiler/RTL та профіль
KPOL-CME-1 не змінено; нової native реалізації або HIL немає.
Попередні Source, Data та Reports #155/#157 залишені незмінними.
Атрибуція Автору — за передаванням власника, не перевіреним оригінальним каналом.

## 3. Результати

### 3.1. Що нове, а що повторено

Текст слайда 3 у двох попередніх редакціях однаковий. Релевантні
абзаци 17–19 порівняно з новими абзацами 1–5:

| Тема | Попередні Source, слайд 3 | Новий Source, слайд 1 / наслідок |
|---|---|---|
| Роль над-/підрядкового значення | Абзац 17: властивості Min/Max задаються індексами після закривальної дужки. | Абзаци 3–4: виконання залежить від **типу** цих значень; саме для **Token** це відповідно Min/Max. Нове явне розрізнення за типом. |
| Успіх Collection | Абзац 18 поєднував І всіх елементів та обмеження кількості. | Абзац 1 окремо визначає успіх **вмісту** через І всіх елементів; абзац 5 окремо формулює кратність успіху **групи**. Не втрачати це розділення. |
| Успіх Array | Абзац 19: Min успішних елементів, семантичне АБО, Max разів. | Абзац 2 повторює правило; порядку вибору чи трас не додано. |
| Default 1/0 | Абзац 17: одне обов'язкове виконання Collection / одна вибірка одного елемента Array. | Абзац 4 повторює це; особливе декодування Max=0 не пояснене. |
| Min=0 | Абзац 18 дозволяє успіх без успішного елемента. | Абзац 5 повторює правило в загальному формулюванні успіху групи. |

Наслідок для native представлення: зберігати тип та позицію індексу,
відділяти успіх вмісту від умови успіху групи; не сплощувати всі
індекси в безтипову пару чисел. Це інженерний висновок, не вибір
Автором конкретного IR/compiler framework.

### 3.2. AUTH та Q-AUTH

| ID | Оцінка після нового входу |
|---|---|
| AUTH-03 | Уточнено: залежність від типу; Token-підрядкове → Min, Token-надрядкове → Max; успіх вмісту/групи відділено. Лишається Proposed, не реалізовано. |
| AUTH-07 | Майбутній структурний шар має не втрачати тип/позицію індексів; нової канонічної лексики, одиниць span чи повної граматики не отримано. |
| AUTH-01/02/04/05/06/08 | Нових даних про їх окремі контракти немає; стан із #157 не змінюється. Зокрема, дужки не отримали фази/ефектів. |
| Q-AUTH-01 | **Частково уточнено**, не закрито: відома роль індексів типу Token, але Max=0, лічба/успіх, явні/відсутні межі та інші типи ще потребують контракту. |
| Q-AUTH-02–07 | Нових відповідей у цьому фрагменті немає; оцінки [Report #157 §3.3](kpol-syntax-157-report.md#33-оцінка-q-auth) збережені. |

Нових AUTH-ID не введено: уточнюється вже наявний AUTH-03.
Кандидатів залишається вісім; цей вхід не є погодженням їх baseline.

Для подальшого уточнення Q-AUTH-01 — одна тема, до трьох пов'язаних запитань:

1. Що означає Max=0: спеціальний код, відсутня межа чи інше правило? Варіанти — наші гіпотези; потрібне авторське пояснення.
2. На короткій трасі Collection та Array із default 1/0 що саме рахується: успішні виконання всього вмісту, окремі елементи чи спроби? Як співвідносяться вибір Min елементів і повторення Max разів?
3. Як трактувати над-/підрядкові значення не типу Token або змішану пару типів; що робити з некоректним випадком?

Це перелік у Report, не новий надісланий RFC; drafts не редагувався.

## 5. Перевірки та відтворення

[checks-01.log](data/kpol-syntax-159/checks-01.log) містить команди,
час/хост/базу, хеши входу/референсу, exit-коди: links,
WP/immutable inputs, formatting, inventory, незмінність коду/попередніх
матеріалів та повний `python3 -m pytest -q`.
Перевірки не є тестом native Min/Max або HIL.
Локальний open_flow не потрібен, бо `Engineering/hw/` не змінено;
звичайний hosted CI виконує його окремо.

Репродуктор збережено в полі `reproducer_source` audit JSON;
параметри — `ROOT SESSION`, де SESSION містить markitdown-витяг,
окремий reader venv та PNG. Запускати в окремій копії без наявного
Data #159: режим `x` не перезаписує raw.
Рендер: skill wrapper `scripts/office/soffice.py`, окремий
`UserInstallation`, headless PDF, `pdftoppm -png -r 150`.
Достатні вихідні матеріали залишені у Git; похідні зображення можуть
відрізнятися на іншій версії renderer/fonts.
