# Звіт: Поточний стан та аналіз дослідження симбіозу ПЛІС і GPU

* **Версія:** 0.3.0
* **Дата:** 2026-11-13
* **Тип WP:** Report
* **Власник:** Микола Федчик; автор аналізу — Микола Федчик.
* **Об'єкт і база:** Архітектурні розрахунки монографії, стенд PYNQ-Z1 + Jetson Orin J501, симуляції BRAM-конвеєра.

## Обмеження дослідження

1. **Фізичний стендовий експеримент заплановано, але ще не завершено:** Стенд перебуває на етапі підготовки кабельної розводки та складання джерельно-синхронного драйвера паралельної шини.
2. **Результати, наведені нижче, є аналітичними оцінками та симуляційними прогнозами:** Вони ґрунтуються на відомих параметрах затримок контролера пам'яті Orin, драйвера SPI Linux та конвеєра BRAM.
3. **Остаточний висновок щодо повної детермінованості буде винесено лише після фіксації осцилограм Raspberry Pi Pico:** Симуляція не замінює фізичного HIL-вимірювання на кремнії.

## Питання і метод

Аналіз проведено для з'ясування:
* Чи здатна зв'язка ПЛІС + GPU усунути Callback Bottleneck у реальних застосуваннях робототехніки та безпілотних систем (де час реакції критичний).
* Які компроміси виникають між затримкою, енергоспоживанням та складністю шинного інтерфейсу.

## Аналітичні результати та порівняння архітектур

Зіставлення трьох архітектурних підходів до виконання 32 паралельних підписок:

| Характеристика | 1. Розсип MCU (Baseline) | 2. Дискретні кернели GPU (`cudaLaunchKernel`) | 3. Persistent Mega-Kernel на GPU (Досліджуване рішення) |
|---|---|---|---|
| **Фізичний інтерфейс** | UART / CAN / SPI (розсип ліній) | PCIe / AXI DMA | 8-бітна паралельна шина або PCIe Direct |
| **Накладні витрати диспетчеризації** | $10\dots 100\ \mu\text{с}$ (послідовне опитування) | $3.0\dots 10.0\ \mu\text{с}$ (драйвер ядра ОС) | $20\dots 50\text{ нс}$ (poll-loop у Shared Memory) |
| **Час передачі шини ($T_{\text{bus}}$)** | $10\dots 1000\ \mu\text{с}$ | $0.5\dots 1.0\ \mu\text{с}$ | $160\text{ нс}$ (8 байтів @ 50 МГц) |
| **Повна латентність ($T_{\text{e2e}}$)** | $20\dots 1000\ \mu\text{с}$ | $4.0\dots 12.0\ \mu\text{с}$ | **$\approx 0.4\dots 0.8\ \mu\text{с}$** ($80\text{ нс} + 160\text{ нс} + 50\text{ нс} + \dots$) |
| **Апаратний джитер ($\sigma$)** | $\gt 10\ \mu\text{с}$ | $\gt 1\ \mu\text{с}$ | **$\le 50\text{ нс}$** |
| **Апаратна складність плати** | Велика (десятки мікросхем MCU) | Низька (один SoC Jetson) | Низька (один модуль J501) |

### Аналіз типу обчислювальних ядер GPU (Уточнення Федчика)

У межах дослідження розв'язано питання вибору обчислювального блоку GPU:
1. **Непридатність Tensor Cores:** Матричні блоки орієнтовані на пакетні тензорні операції (FP16/INT8 GEMM). Вони не підтримують довільні скалярні розгалуження, поодинокі бітові перевірки та мають надмірний оверхед на завантаження матриць.
2. **Вибір Універсальних шейдерних ядер (CUDA Cores / Stream Processors / Xe Vector Engines):**
   * Обслуговування нано-підписників є скалярною/векторною задачею (ПІД, поліном, фільтр).
   * Шейдерні АЛП надають апаратну бітову логіку (`BFE`, `LOP3`), предикатний вибір (`SEL`) без Warp Divergence та роботу на тактовій частоті $1.3\dots 2.5\text{ ГГц}$ ($10\dots 20\text{ нс}$ на підписку).
   * Інваріант нульової глобальної пам'яті: стан підписників та маска подій утримуються виключно в регістрах та Shared Memory ($1\dots 2\text{ такти}$).

## Висновки та подальші кроки

1. **Теоретична спроможність та когнітивна основа:** Математична модель підтверджує, що комбінація апаратного конвеєра BRAM ПЛІС (80 нс) та персистентного ядра GPU дозволяє скоротити повний цикл реакції підписників нижче $1.0\ \mu\text{с}$, що на 2–3 порядки швидше за традиційні рішення на базі дискретних мікроконтролерів. Архітектура реалізує біонічні закономірності Бернштейна, Брукса та Альбуса на сучасному напівпровідниковому рівні.
2. **Пріоритет HIL-верифікації:** Подальші роботи зосереджені на виконанні двох запланованих апаратних експериментів:
   * [EXP-GPU-01](experiments/EXP-GPU-01/README.md) — вимірювання фізичної латентності передачі та пробудження варпа на стенді PYNQ-Z1 + Jetson Orin J501 через логічний аналізатор Raspberry Pi Pico;
   * [EXP-GPU-02](experiments/EXP-GPU-02/README.md) — перевірка онлайнової інжекції правил у BRAM через другий порт (Zero-Downtime Rule Injection) без зупинки реактивного контуру безпеки.
3. **Патентна перспектива:** Отримані метрологічні часові діаграми стануть об'єктивним доказом промислової придатності та досягнення технічного результату для патентної заявки за класом комп'ютерно-реалізованих винаходів (CII).

## Абревіатури та глосарій

* **HIL** (Hardware-in-the-Loop) — апаратне тестування в замкненому контурі.
* **MCU** (Microcontroller Unit) — однокристальний мікроконтролер.
* **SoC** (System on Chip) — система на кристалі.
