## 1. Питання і призначення

Цей документ формалізує теоретичний та епістемічний базис гетерогенного симбіозу Машини Кузьміна (ПЛІС) та графічних процесорів (GPU), систематизуючи зв'язок архітектури з класичною теорією продукційних експертних систем (алгоритм RETE), багаторівневою біонічною моделлю керування (Бернштейн, Брукс, Альбус) та методологією онлайнового самонавчання без пересинтезу бітстріму кристала.

## 2. Генетичний зв'язок із продукційними системами та алгоритмом RETE

У канонічній продукційній моделі Е. Фейгенбаума та Ч. Форгі знання формалізуються парою правил вигляду:

$$\mathbf{IF}\ \langle\text{LHS: стан фактів у робочій пам'яті}\rangle\ \mathbf{THEN}\ \langle\text{RHS: дії або висновки}\rangle$$

Між базовими компонентами класичної продукційної системи та апаратним конвеєром Машини Кузьміна існує строгий математичний та структурний ізоморфізм:
* **Робоча пам'ять фактів (Working Memory):** У класичному штучному інтелекті це динамічна таблиця фактів у пам'яті DRAM. У Машині Кузьміна — це детермінований масив регістрів станів концептів, локалізований у внутрішньокристальній пам'яті BRAM.
* **Ліва частина правила (Left-Hand Side, LHS):** Логічні предикати переходів (`::`), що перевіряють збіг умов та валідаційні біти. В апаратному конвеєрі МК предикатне зіставлення здійснюється за 4 такти ($`80\text{ нс}`$ при частоті $`100\text{ МГц}`$) паралельними комбінаційними схемами.
* **Конфліктний набір (Conflict Set) та спрацьовування (Rule Firing):** Момент переходу концепту в новий стан за бар'єром Великої Крапки (`•`).
* **Права частина правила (Right-Hand Side, RHS):** Вектори підписників (колбеків), які запускаються при спрацьовуванні правила для виконання дій над зовнішнім середовищем або модифікації інших фактів.

### Подолання історичного глухого кута експертних систем реального часу (RTES)

У 1980–1990-х роках експертні системи реального часу (G2, CLIPS, OPS5, Lisp-машини, DADO/NON-VON) зазнали невдачі у жорсткому контурі (Hard Real-Time) через три фактори:
1. **Недетермінізм часу виведення ($`\text{WCET}`$):** Обхід дерева $\alpha$- та $\beta$-вузлів алгоритму RETE в DRAM мав стохастичну затримку від мілісекунд до секунд.
2. **Фон-нейманівське горло пам'яті та Garbage Collection:** Перевиділення пам'яті руйнувало кеш-пам'ять і спричиняло критичні паузи збирача сміття.
3. **Параліч черги дій (Action Execution Bottleneck):** Послідовний процесор не міг обслужити сотні одночасно активованих правил.

У симбіозі ПЛІС і GPU цей бар'єр усувається:
* Зіставлення фактів LHS закріплено за 4-тактовим апаратним конвеєром BRAM ($`T_{\text{LHS}} = 80\text{ нс}`$, $`\sigma = 0\text{ нс}`$);
* Виконання дій RHS перенесено на тисячі паралельних шейдерних ядер GPU через персистентний мега-кернел.

## 3. Трирівнева біонічна модель: Рефлекторна дуга, моторика та неокортекс

Гетерогенна система реалізує повний ізоморфізм нервової системи вищих організмів:

```
[ Фізичні сенсори / Периферія ] (Зовнішній світ: неперервний хаос, шуми, наносекунди)
               │
               ▼  Bus_in (миттєвий захват сигналів)
┌────────────────────────────────────────────────────────────────────────┐
│ Рівень 1: Спинний мозок / Рефлекторні ганглії — ПЛІС (Машина Кузьміна) │
│ • Апаратна модель фактів (Active BRAM Pipeline)                       │
│ • Семантичний компресор: апаратна пре-фільтрація відсікає 99.9% шуму   │
│ • Жорсткий апаратний рефлекс і безаварійний захист (80 нс, σ = 0 нс)   │
│ • Формування очищеного вектора активних концептів                      │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ GPUDirect RDMA / Direct Interconnect
                                   ▼ (вектор станів, латентність < 500 нс)
┌────────────────────────────────────────────────────────────────────────┐
│ Рівень 2: Мозочок / Підкіркові рухові ядра — GPU (CUDA Cores)          │
│ • Масово-паралельний персистентний мега-кернел (Persistent Mega-Kernel)│
│ • Виконання тисяч RHS-дій (нано-підписників) паралельними варпами     │
│ • Нелінійне векторне регулювання, ПІД-траєкторії, фільтри Калмана     │
│ • Локальність пам'яті: нульове звернення до DRAM під час циклу реакції │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ Асинхронні повідомлення стану
                                   ▼ (мілісекундний контур планування)
┌────────────────────────────────────────────────────────────────────────┐
│ Рівень 3: Кора великих півкуль / Неокортекс — Host CPU / Агенти / LLM  │
│ • Стратегічне цілепокладання та глобальна оптимізація місії            │
│ • Синтез нових концептуальних моделей та графів знань                 │
│ • Динамічне перенавчання нижчих рівнів                                 │
└────────────────────────────────────────────────────────────────────────┘
```

## 4. Концептуальний горизонт: Онлайнове навчання без пересинтезу бітстріму

Фундаментальне завдання самонавчання системи полягає у зміні бази знань без зупинки реактивного контуру:

1. **Онлайнова реконфігурація в активній пам'яті (In-Memory Rule Injection):**  
   Через другий незалежний порт двопортової Block RAM (Port B) контролер верхнього рівня змінює пороги компараторів (`::`) та маски зв'язків за $`\le 20\text{ нс}`$ (інваріант **Zero-Downtime Knowledge Update**).
2. **Автономне виявлення кореляцій та синтез концептів (Concept Genesis):**  
   Апаратна фіксація матриці ко-активацій ($`C_i \to C_j`$) дозволяє виявляти стійкі зв'язки та синтезувати макро-концепти:
$$C_{\text{meta}} = \bigwedge_{k \in \mathcal{K}} C_k$$
   що зменшує глибину логічного виведення.
3. **Замкнений контур гетерогенного перенавчання (Closed-Loop Co-Learning):**  
   Шейдерний кластер GPU за результатами оцінки похибки реакції розраховує градієнтну корекцію коефіцієнтів та інжектує нові правила в BRAM ПЛІС.
