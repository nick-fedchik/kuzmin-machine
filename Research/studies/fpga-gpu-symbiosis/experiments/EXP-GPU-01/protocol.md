# Протокол: Експеримент EXP-GPU-01 — верифікація гетерогенного симбіозу PYNQ-Z1 та Jetson J501 через Raspberry Pi Pico

* **Версія:** 0.2.0
* **Дата:** 2026-11-14
* **Тип WP:** Protocol
* **Статус:** Запропоновано (Proposed; має інженерні передумови RTL та узгодження рівнів).
* **Власник:** Микола Федчик; автор експерименту — Микола Федчик.
* **Підстава:** Архітектурне рішення [B6](../../../../../Engineering/decisions/b6-gpu-persistent-kernel-subscribers.md), загальний протокол дослідження [fpga-gpu-symbiosis](../../protocol.md).

## Питання і межі

### Мета перевірки
Метою експерименту EXP-GPU-01 є фізичне вимірювання наскрізної часової латентності ($T_{\text{e2e}}$) та джитеру ($\sigma$) при передачі зведеного регістра подій із ПЛІС PYNQ-Z1 у персистентний кернел GPU на платформі Seeed Studio reServer Industrial J501 (NVIDIA Jetson AGX Orin 64GB) із реєстрацією часових інтервалів цифровим логічним аналізатором на базі Raspberry Pi Pico (`RP2040 PIO`) та внутрішніми апаратними лічильниками тактів ПЛІС і `clock64()` GPU.

### Гіпотеза експерименту
1. Використання персистентного CUDA-варпа (Persistent Mega-Kernel), який виконує атомарне `acquire`-опитування когерентного буфера `Event Mailbox` (`Unified Memory` через `L2`-кеш) і утримує стани підписників у регістрах та `Shared Memory` SM, усуває програмний оверхед запуску кернелів (`cudaLaunchKernel`), наближаючи час пробудження обробника події після появи даних у `L2` до $T_{\text{wakeup}} \le 150\text{ нс}$.
2. Передача 64/128-бітного зведеного вектора подій через високошвидкісний цифровий інтерфейс між PYNQ-Z1 та Jetson J501 забезпечує наскрізний цикл виконання 32 однорідних предикатних підписників у межах цільового вікна $T_{\text{e2e}} \lt 1.0\ \mu\text{с}$ (проти $100\dots 1000\ \mu\text{с}$ на класичних шинах UART/CAN із перериваннями ОС).

### Інженерні передумови (обов'язкові до початку вимірювань)
1. **Розширення RTL для PYNQ-Z1 (`PMOD Event Egress`):** Поточний верхній модуль `Engineering/hw/rtl/top/kpol_bram_pipeline_pynq_z1_top.v` виводить лише чотири діагностичні лінії `PMOD JA` (`ja1..ja4`) і не містить `SPI Slave` або 8-бітної джерельно-синхронної шини. До фізичного запуску EXP-GPU-01 в окремій гілці створюється й верифікується симуляцією модуль `PMOD Event Egress` на роз'ємах `PMOD JA` + `PMOD JB` (`3.3V LVCMOS`).
2. **Узгодження рівнів напруги та цілісність сигналів на `50 МГц`:** Роз'єми PMOD плати PYNQ-Z1 працюють на рівні `3.3V LVCMOS`, тоді як низьковольтні сигнальні лінії Jetson AGX Orin / J501 мають домени `1.8V` або буферизовані `3.3V` (див. [j501-hardware-interface.md](j501-hardware-interface.md)). Пряме підключення `3.3V` виходу ПЛІС до `1.8V` входу SoC заборонене; обов'язкове застосування швидкодіючого перетворювача рівнів (наприклад, серії `SN74AVC8T245` з власною затримкою $\le 3\text{ нс}$) та перевірка відсутності критичного дзвону (`ringing`) на коротких провідниках із чергуванням ліній `GND`.

### Межі експерименту
* **Охоплює:** Вимірювання цифрових часових інтервалів між стробом емісії події на ПЛІС (`EVENT_START`) та стробом завершення варпа на GPU (`GPU_DONE`), аналіз джитеру з урахуванням кроку квантування аналізатора та порівняння предикатного виконання з розгалуженим.
* **Не охоплює:** Сертифікацію за галузевими стандартами безпеки та перенесення результатів стендового інтерфейсу PMOD безпосередньо на промисловий PCIe GPUDirect RDMA без окремого вимірювання.

## Умови та порядок

### Апаратне забезпечення стенда
1. **Генератор подій:** Плата PYNQ-Z1 (Xilinx Zynq-7000 XC7Z020, ядро `CFG-P` @ 100 МГц + експериментальний блок `PMOD Event Egress`).
2. **Обчислювач підписників:** Seeed Studio reServer Industrial J501 (Jetson AGX Orin 64GB, Ampere GPU 2048 ядер). Детальний схемотехнічний аналіз несучої плати наведено в [j501-hardware-interface.md](j501-hardware-interface.md).
3. **Основний цифровий вимірювач:** 8/10-канальний цифровий логічний аналізатор на базі Raspberry Pi Pico (`RP2040 PIO`, логічні входи `3.3V LVCMOS`, частота вибірки `125 МГц` із кроком квантування `8 нс` або `250 МГц` із кроком `4 нс`). *Застереження:* вбудований у RP2040 SAR АЦП має частоту лише `500 kSPS` (крок `2 мкс`) і **не використовується** в експерименті; верифікація аналогової форми фронтів на `50 МГц` за потреби виконується окремим зовнішнім осцилографом зі смугою $\ge 200\text{ МГц}$.
4. **Комутація:** Короткі екрановані або звиті зі спільним `GND` цифрові лінії через узгоджувач рівнів без низькошвидкісної оптоізоляції (промисловий клемник `J25` з оптронами `SFH690BT` має власну затримку $\tau \approx 5\dots 15\ \mu\text{с}$ і для субмікросекундного тесту не підходить).

### Схема підключення цифрових каналів RP2040 PIO
* **Цифровий вхід `GP0` (`3.3V LVCMOS`):** Пін PYNQ-Z1 `EVENT_START` (строб фіксації переходу у точці Великої Крапки `•`).
* **Цифровий вхід `GP1` (`3.3V LVCMOS` через буфер рівня):** Вихідний строб Jetson J501 `GPU_DONE` (завершення обробки підписників у варпі).
* **Цифрові входи `GP2..GP9` (`3.3V LVCMOS`):** Контроль такту й ліній передачі даних (`SPI SCK/MOSI/CS` у Фазі 1 або `CLK + D[6:0]` у Фазі 2).

### Порядок виконання вимірювань
1. **Фаза 1 (Базовий SPI DMA контур):**
   * Налаштування модуля `PMOD Event Egress` на PYNQ-Z1 як `SPI Slave` (до `50 МГц` після перевірки цілісності сигналів) або `SPI Master` залежно від режиму контролера Jetson.
   * Приймання пакета на Jetson J501 через системний SPI DMA у когерентний буфер `Unified Memory` (`Event Mailbox`).
   * Серія з 1000 пакетів емісії події; реєстрація розподілу $T_{\text{e2e}}$.
2. **Фаза 2 (Джерельно-синхронна паралельна шина GPIO):**
   * Переведення ліній `PMOD JA/JB` у режим 8-бітної джерельно-синхронної паралельної шини з узгодженням рівнів.
   * Вимірювання фактичної латентності доставки 64/128-бітної маски в пам'ять, видиму для GPU (з урахуванням латентності приймання на боці SoC Orin).
3. **Фаза 3 (Латентність пробудження персистентного варпа):**
   * Запуск на GPU Jetson Orin персистентного CUDA-варпа з атомарним опитуванням `ld.global.acquire.sys` когерентного `Event Mailbox` та резидентними станами підписників у регістрах і `Shared Memory` SM.
   * Оцінка $T_{\text{wakeup}}$ за внутрішніми мітками часу GPU `clock64()` / `globaltimer` у поєднанні із зовнішньою дельтою `GP0 -> GP1`.
4. **Фаза 4 (Тест однорідного предикатного виконання проти розходження гілок):**
   * Емісія подій із різною кількістю активних бітів підписок ($k = 1, 8, 16, 32$).
   * Статистичний збір 100 000 циклів цифровим захватом `RP2040 PIO` та внутрішнім таймером GPU для побудови емпіричної функції розподілу (`p50`, `p99`, `p99.9`, `max`, $\sigma$).

## Критерії та дані

| Параметр | Критерій успіху (Acceptance Threshold) | Метод перевірки |
| :--- | :--- | :--- |
| **Латентність трансферу SPI** | $T_{\text{spi}} \le 3.0\ \mu\text{с}$ | Цифровий захват `RP2040 PIO` (`GP0 -> GP1`, крок `8 нс`) |
| **Латентність паралельного тракту** | $T_{\text{par}} \le 600\text{ нс}$ | Цифровий захват `RP2040 PIO` + перевірка цілісності пакетів |
| **Пробудження персистентного кернела** | $T_{\text{wakeup}} \le 150\text{ нс}$ (від оновлення `Event Mailbox` у L2) | Апаратний таймер GPU `globaltimer` / `clock64()` + зовнішні строби |
| **Наскрізний час ($T_{\text{e2e}}$)** | $T_{\text{e2e}} \lt 1.0\ \mu\text{с}$ (`p99` для Фази 2–3) | Статистичний аналіз серії $N \ge 1000$ подій на `RP2040 PIO` |
| **Стабільність контуру ПЛІС** | Внутрішні такти = константа (`8 тактів` за вільної черги); зовнішнє відхилення $|\Delta T_{\text{fpga}}| \le 1\text{ LSB}$ (`8 нс` @ 125 МГц) | Лічильник циклів ПЛІС + цифрова гістограма `RP2040 PIO` |
| **Збереження даних** | Незмінні цифрові траси (`.vcd` / `.sr` / `.csv`) зберігаються в `../../data/` | Хеш SHA-256 у фінальному звіті |

## Абревіатури та глосарій

* **DMA** — Direct Memory Access (прямий доступ до пам'яті).
* **Event Mailbox** — когерентна комірка пам'яті низької латентності для безпроцесорної сигналізації подій у GPU.
* **LSB** (Least Significant Bit) — крок дискретизації цифрового вимірювача за часом (`8 нс` при `125 МГц`).
* **Persistent Kernel** — довготривалий кернел GPU з резидентними даними підписників у регістрах і `Shared Memory` SM.
* **RP2040 PIO** — програмований автомат цифрового вводу-виводу мікроконтролера Raspberry Pi Pico.
* **VCD** — Value Change Dump (формат запису цифрових часових діаграм).
* **WCET** — Worst-Case Execution Time (найгірший час виконання).
