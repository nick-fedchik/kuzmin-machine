## 1. Що не вдалося і обмеження

1. **Фізичний тракт між ПЛІС PYNQ-Z1 та Jetson J501 залишається розімкненим:**
   * Усі вимірювання в цьому звіті охоплюють виключно підсистему GPU на фізичному кристалі NVIDIA Jetson AGX Orin (`Host ARM Cortex-A78AE <-> L2 SCF <-> Ampere SM 8.7`). Фізичне замикання контуру `PYNQ-Z1 PL Event Egress -> Jetson J501` та захват зовнішнім логічним аналізатором `RP2040 PIO` винесені в окрему заплановану задачу [#226](https://github.com/nick-fedchik/kuzmin-machine/issues/226).
2. **Часткове перевищення жорсткого порога `p99.9 <= 1500 нс` на 256 підписниках у профілі `MODE_50W` (`816 МГц`):**
   * У конфігурації `1 блок x 256 ниток` (`8 варпів` на 1 SM) за обмеженої частоти профілю `MODE_50W` (`816.0 МГц` замість номінального максимуму кристала `1300.5 МГц` у `MAXN`) середній повний час на SM склав `1410.04 нс` (`p50 = 1408.09 нс`, `p99 = 1508.58 нс`), але хвостовий перцентиль **`p99.9 = 1584.56 нс`** перевищив попередньо зафіксований поріг `1500.0 нс` на `+84.56 нс` (`+5.6%`). Критерій не пом'якшувався заднім числом (`AGENTS.md §3`).
3. **Спростовано наївне багатоблокове масштабування (`Multi-SM Broadcast` по одній кеш-лінії):**
   * Поширення тієї самої схеми опитування однієї лінії `ingress->seq_id` на кілька незалежних блоків SM (`4x32`, `8x32`, `16x32`) призводить до когерентного шторму інвалідацій L2 (`L2 Snoop Storm`): на 512 підписниках (`16x32`) час на SM деградує з `1688.12 нс` (`1x512`) до **`10613.67 нс`** (`6.29x` гірше), а наскрізний round-trip хоста — з `6541.8 нс` до **`40803.9 нс`**. Отже, прямий fan-out однієї поштової скриньки на багато SM непридатний без окремих 128-байтних слотів на кожен SM.
4. **Виявлена розбіжність API `cudaDevAttrClockRate` та реальної частоти DVFS на Tegra234:**
   * Виклик `cudaDeviceGetAttribute(..., cudaDevAttrClockRate, 0)` повертає статичний паспортний максимум `1300.0 МГц` навіть тоді, коли активний профіль `MODE_50W` жорстко обмежує `max_freq = 816.0 МГц`, а без `jetson_clocks` частота спокою падає до `306.0 МГц`. У режимі незафіксованого DVFS (`run-01-dvfs-unlocked-1x32.log`) перерахунок тактів за піковою частотою занижує реальний фізичний час `T_e2e_sm` на `39.7%` (`1115.69 нс` проти фактичних `1848.88 нс` за апаратним таймером `%globaltimer`).
5. **Обернено-однорідна структура обчислень:**
   * Бездивергентність підтверджена для однорідного шаблону ПІД-регулятора з фіксованою комою `Q8` у регістрах SM; різнорідні гілки байткоду в межах одного варпа викликатимуть серіалізацію і потребують групування підписників за класом оператора у компіляторі KPOL.

## 2. Метод

1. **Виправлення архітектури пам'яті та метрології (`persistent_subscribers.cu`):**
   * **Ізоляція 128-байтних ліній кешу L2:** вхідна структура `km_event_ingress_t` стиснута рівно до `128 байтів` (`static_assert(sizeof == 128)`, вміщує `seq_id`, `stop_flag`, `concept_val` та 512-бітну маску `event_mask[16]`); вихідна структура `km_event_egress_t` розміщує `ack_seq_id[16]` в окремій 128-байтній лінії, а масив `outputs[512]` — зі зміщенням `128 Б`, із предикатним записом **лише** при `is_active == true`.
   * **Регістрово-резидентний стан SM:** змінні `target, kp, ki_q8, kd, integral, prev_err, out_val, trigger_count` утримуються в регістрах SM протягом усього персистентного циклу й вивантажуються лише при зупинці для незалежної перевірки проти еталонної CPU-моделі (`0` розбіжностей на всіх прогонах).
   * **Ізольована подвійна метрологія:** буфер телеметрії винесено у локальну пам'ять GPU (`cudaMalloc`), щоб запис метрик не створював snooping-трафіку; кожна подія вимірюється одночасно лічильником тактів SM `clock64()`, фізичним 64-бітним таймером PTX `%globaltimer` (квант `32 нс` при зафіксованих частотах Tegra234) та `CLOCK_MONOTONIC_RAW` на ARM-хості, у поєднанні зі зчитуванням фактичної частоти GPU із `/sys/devices/platform/17000000.gpu/devfreq/17000000.gpu/cur_freq`.
2. **Умови проведення фізичних прогонів на стенді:**
   * Доступ до стенда `mfedchyk@192.168.68.68` виконувався під блокуванням `flock -w 600 /tmp/km-bench.lock`.
   * Профіль `nvpmodel` не змінювався (`MODE_50W`, ID `3`, `max_freq = 816 МГц`). Після контрольного заміру з розблокованим DVFS (`run-01`) поточну конфігурацію збережено через `jetson_clocks --store`, встановлено статичну частоту `816.0 МГц` на час серії `run-02` ($N = 2000$ подій на точку) і відновлено до вихідних `306.0 МГц` через `jetson_clocks --restore`.

## 3. Результати

### 3.1. Перевірка машинного коду `SASS` (`sm_87`) та впливу DVFS

У дампі [`sass-sm87-01.txt`](../../data/exp-gpu-01-phase3/sass-sm87-01.txt) підтверджено:
* Оновлення регістрового стану підписника скомпільовано в апаратні предикатні інструкції вибору без переходів: `SEL R7, R26, R7, P3` та `SEL R8, R3, R8, P3` (рядки 615–625).
* Умовний запис виходу активного підписника скомпільовано в предикатний запис `@P3 STG.E [R14.64+0x80], R6` із бар'єром варпа `WARPSYNC 0xffffffff` (рядки 585, 637) — без інструкцій розгалуження всередині обчислювального блока.
* Зчитування `seq_id` і публікація `ack_seq_id` використовують системно-когерентні інструкції `LDG.E.STRONG.SYS` та `STG.E.STRONG.SYS` (рядки 553, 653).

Порівняння розблокованого DVFS ([`run-01-dvfs-unlocked-1x32.log`](../../data/exp-gpu-01-phase3/run-01-dvfs-unlocked-1x32.log)) та зафіксованої частоти `816.0 МГц` ([`mask_1x32_all.json`](../../data/exp-gpu-01-phase3/mask_1x32_all.json)):
* **DVFS розблоковано (`306 -> 816 МГц`):** $T_{\text{e2e\_sm}}$ за `%globaltimer` становить **`1848.88 нс`** (при наївному діленні тактів на пікові `816 МГц` виходило б `1115.69 нс`), наскрізний Host RT = `8698.2 нс` (`p99.9 = 17216 нс`).
* **Частоту зафіксовано (`816.0 МГц`):** $T_{\text{e2e\_sm}}$ за `clock64() / 816 МГц` становить **`1346.96 нс`**, за незалежним апаратним `%globaltimer` — **`1346.80 нс`** (розбіжність між двома фізичними таймерами — **`0.16 нс` або `0.012%`**), Host RT = `5838.2 нс` (`p99.9 = 7296 нс`).

## 4. Перевірка гіпотези / критеріїв

| Критерій (#225 / ADR B6) | Очікувано | Отримано | Висновок |
| :--- | :--- | :--- | :--- |
| **Критерій 1 (`Zero Warp Divergence`)** | Ріст тактів на розріджених масках $\le 5\%$; предикати `SEL`/`@P STG` у `SASS` | `37.00 ± 0.00` тактів (`0.00%` росту) на `all/alt/one/ends/rand`; `SEL` і `@P3 STG.E` у `SASS` | **Підтверджено** |
| **Критерій 2 ($T_{\text{sub-exec}} \le 100\text{ нс}$ у реальному фізичному часі)** | $\le 100.0\text{ нс}$ за фактичної частоти GPU + збіг із `%globaltimer` | `45.34 нс` (`1x32`), `67.40 нс` (`1x256`), `83.64 нс` (`1x512`) вже при `816 МГц` (`MODE_50W`); збіг таймерів до `0.01–0.07%` | **Підтверджено** |
| **Критерій 3а (Масштабування `1x256`, `p99.9(T_e2e_sm) <= 1500 нс`)** | `p99.9 <= 1500.0 нс` | При `816 МГц` (`MODE_50W`): $\mu = 1410.04\text{ нс}$, `p99 = 1508.58 нс`, **`p99.9 = 1584.56 нс`** (`+5.6%` понад поріг) | **Частково не виконано на `816 МГц`** (потребує перевірки в `MAXN` `1.30 ГГц`) |
| **Критерій 3б (Топологія `1 SM x K warps` проти `K SM x 1 warp`)** | Відсутність L2 snoop storm при ієрархічному опитуванні лише `tid == 0` | На `512` підписниках `1x512` у **`6.29x` швидше** за `16x32` (`1688 нс` проти `10614 нс` на SM; `6.54 мкс` проти `40.80 мкс` Host RT) | **Підтверджено для `1xK`; наївний Multi-SM спростовано** |
| **Побітова точність проти незалежної CPU-моделі** | `0` розбіжностей станів і виходів | `0` розбіжностей на всіх `15` прогонах (`32..512` підписників $\times 2000$ подій) | **Підтверджено** |

## Абревіатури та глосарій

| Термін | Значення |
| :--- | :--- |
| DVFS | Dynamic Voltage and Frequency Scaling — динамічне керування частотою й напругою кристала. |
| L2 Snoop Storm | Деградація пропускної здатності когерентної шини через одночасні інвалідації однієї лінії кешу L2 багатьма мультипроцесорами SM. |
| PTIMER / `%globaltimer` | Фізичний 64-бітний апаратний таймер реального часу в архітектурі NVIDIA GPU (незалежний від частоти шейдерного домену). |
| Q8 | Формат арифметики з фіксованою комою з масштабом $2^8 = 256$. |
| SASS | Нативний машинний асемблер шейдерних ядер NVIDIA GPU (`sm_87` для Orin Ampere). |
| SCF | Scalable Coherency Fabric — когерентна міжз'єднувальна тканина SoC NVIDIA Tegra234 (Orin). |
| WP | Work Product — формалізований артефакт проєкту. |
