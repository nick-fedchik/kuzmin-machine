## 1. Що не вдалося і обмеження

1. **Фізичний тракт між ПЛІС PYNQ-Z1 та Jetson J501 залишається розімкненим:**
   * Усі вимірювання в цьому звіті охоплюють виключно підсистему GPU на фізичному кристалі NVIDIA Jetson AGX Orin (`Host ARM Cortex-A78AE <-> L2 SCF <-> Ampere SM 8.7`). Фізичне замикання контуру `PYNQ-Z1 PL Event Egress -> Jetson J501` та захват зовнішнім логічним аналізатором `RP2040 PIO` винесені в окрему заплановану задачу [#226](https://github.com/nick-fedchik/kuzmin-machine/issues/226).
2. **Невиконання порога `p99.9(T_e2e_sm) <= 1500 нс` на ВСІХ геометріях у профілі `MODE_50W` (`816 МГц`):**
   * У профілі `MODE_50W` (`816.0 МГц` замість номінального максимуму кристала `1300.5 МГц` у `MAXN`) хвостовий перцентиль `p99.9` перевищує `1500.0 нс` на **всіх** досліджених геометріях `1x32..1x512` (це базове перевищення, а не особливість `1x256`). За серією $N=10000$ із 95% bootstrap довірчим інтервалом (1000 підвибірок): `1x32` — `1692.40 нс` `[1656.86..1726.72]`, `1x128` — `1611.52 нс` `[1531.86..1656.86]`, `1x256` — `1664.22 нс` `[1615.20..1719.36]`, `1x512` — `1993.87 нс` `[1968.14..2014.71]`. Наскрізне цільове вікно `0.5..1.0 мкс` із ADR B6 при `816 МГц` не досягається (`T_e2e_sm` $\mu \approx 1.35..1.70\text{ мкс}`).
3. **Розмежування `L2 Read Snoop` і `Write False Sharing` у наївному Multi-SM (`4x32..16x32`):**
   * Контрольний A/B експеримент (`run-03-ab-scaling-10k.log`, $N=10000$) показав, що ізоляція `ack` кожного блока в окрему 128-Б кеш-лінію (`km_ack_line_t`, режим `isolated` проти `packed`) знижує `T_e2e_sm` на `16x32` з `10640.01 нс` до `10293.03 нс` (`-3.3%`, $\sigma$: `240.42 -> 137.53 нс`), а на `8x32` — з `6014.80 нс` до `5838.90 нс` (`-2.9%`, $\sigma$: `246.33 -> 71.23 нс`). Однак основна деградація Multi-SM (`10293.03 нс` на `16x32 isolated` проти `1704.40 нс` на `1x512`, тобто **`6.04x`**) зберігається і спричинена саме одночасним читальним опитуванням спільної вхідної лінії `ingress->seq_id` багатьма SM (`L2 Read Snoop`).
4. **Розбіжність `cudaDevAttrClockRate`, дискретність `%globaltimer` і робочий підкритерій `<= 100 нс`:**
   * Виклик `cudaDeviceGetAttribute(..., cudaDevAttrClockRate, 0)` повертає статичний паспортний максимум `1300.0 МГц` навіть при `MODE_50W` (`816.0 МГц`) чи простої DVFS (`306.0 МГц`). У `run-01` (розблокований DVFS) перерахунок за піком занижував `T_e2e_sm` на `39.7%` (`1115.69` проти `1848.88 нс`), а квант `%globaltimer` становив **`96 нс`** (проти `32 нс` при зафіксованих `816 МГц`). В оновленому `persistent_subscribers.cu` тихий fallback на `cudaDevAttrClockRate` заборонено (помилка без явного `--allow-attr-clock`).
   * Показник `T_sub-exec <= 100 нс` охоплює **лише регістрове обчислювальне вікно** (без читання `ingress` з L2 та запису `egress`); це робочий підкритерій внутрішньої математики SM, окремий від наскрізного `T_e2e_sm`.
5. **Обернено-однорідна структура обчислень:**
   * Бездивергентність підтверджена для однорідного шаблону ПІД-регулятора з фіксованою комою `Q8` у регістрах SM; різнорідні гілки байткоду в межах одного варпа викликатимуть серіалізацію і потребують групування підписників за класом оператора у компіляторі KPOL.

## 2. Метод

1. **Виправлення архітектури пам'яті та метрології (`persistent_subscribers.cu`):**
   * **Ізоляція 128-байтних ліній кешу L2 (`km_ack_line_t`):** вхідна структура `km_event_ingress_t` стиснута рівно до `128 байтів` (`static_assert(sizeof == 128)`). Для усунення зауваження `F-2` у вихідній структурі `km_event_egress_t` реалізовано прапорець `--ack-mode isolated|packed`: за замовчуванням (`isolated`) кожен блок SM пише підтвердження у власну окрему 128-Б лінію `km_ack_line_t isolated_ack[16]` (зміщення `128..2175 Б`), а `packed` зберігає суміжний `packed_ack[16]` для контрольного A/B порівняння; масив `outputs[512]` розміщено зі зміщенням `2176 Б` (`0x880`) із предикатним записом **лише** при `is_active == true`.
   * **Регістрово-резидентний стан SM і покрокова перевірка:** змінні утримуються в регістрах SM протягом усього персистентного циклу й звіряються з еталонною CPU-моделлю як на кожних `100` подіях (`mid_run_mismatches`), так і по завершенні (`0` розбіжностей на всіх прогонах).
   * **Телеметрія по всіх блоках, $N=10000$ та bootstrap CI:** `KM_TELEMETRY_CAP` розширено до `10000` подій; кожен активний блок пише телеметрію у власний слот у `cudaMalloc`, а хост агрегує **максимум по всіх активних блоках** (фіксуючи найповільніший блок у Multi-SM) та обчислює 95% bootstrap довірчий інтервал (1000 підвибірок, фіксований seed `0x5EED22901234ULL`) для `p99` та `p99.9`. Квант `%globaltimer` становить `32 нс` при зафіксованих `816 МГц` (`96 нс` у `run-01` при розблокованому DVFS). Тихий fallback на `cudaDevAttrClockRate` заборонено без `--allow-attr-clock`.
2. **Умови проведення фізичних прогонів на стенді:**
   * Доступ до стенда `mfedchyk@192.168.68.68` виконувався під блокуванням `flock -w 600 /tmp/km-bench.lock`.
   * Профіль `nvpmodel` не змінювався (`MODE_50W`, ID `3`, `max_freq = 816 МГц`). Після контрольного заміру з розблокованим DVFS (`run-01`) поточну конфігурацію збережено через `jetson_clocks --store`, встановлено статичну частоту `816.0 МГц` на час серії `run-02` ($N = 2000$ подій на точку) і відновлено до вихідних `306.0 МГц` через `jetson_clocks --restore`.

## Абревіатури та глосарій

| Термін | Значення |
| :--- | :--- |
| DVFS | Dynamic Voltage and Frequency Scaling — динамічне керування частотою й напругою кристала. |
| L2 Snoop Storm | Деградація пропускної здатності когерентної шини через одночасні інвалідації однієї лінії кешу L2 багатьма мультипроцесорами SM. |
| PTIMER / `%globaltimer` | Фізичний 64-бітний апаратний таймер реального часу в архітектурі NVIDIA GPU (незалежний від частоти шейдерного домену). |
| Q8 | Формат арифметики з фіксованою комою з масштабом $2^8 = 256$. |
| SASS | Нативний машинний асемблер шейдерних ядер NVIDIA GPU (`sm_87` для Orin Ampere). |
| SCF | Scalable Coherency Fabric — когерентна міжз'єднувальна тканина SoC NVIDIA Tegra234 (Orin). |
| WP | Work Product — формалізований артефакт проєкту. |
