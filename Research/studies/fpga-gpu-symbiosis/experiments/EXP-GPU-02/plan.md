# План: Проведення експерименту EXP-GPU-02 з онлайнового оновлення правил у BRAM

* **Версія:** 0.2.0
* **Дата:** 2026-11-14
* **Тип WP:** Plan
* **Власник:** Микола Федчик; автор експерименту — Микола Федчик.
* **Підстава:** Протокол [EXP-GPU-02](protocol.md), контракт завантажувача [B4](../../../../../Engineering/specifications/hw/kpol-image-loader-pipeline-contract.md), архітектурне рішення [B6](../../../../../Engineering/decisions/b6-gpu-persistent-kernel-subscribers.md), дослідження [fpga-gpu-symbiosis](../../README.md).

## Мета і межі

### Призначення плану
Цей план визначає порядок інженерної підготовки окремої двобанкової RTL-гілки `CFG-P-HA` (`B4 Варіант 2`) та стендового тестування механізму онлайнового перезапису 128-бітних дескрипторів активної пам'яті BRAM через тіньовий банк без розірваного читання (`torn-read`).
Метою робіт є отримання метрологічно підтверджених цифрових діаграм і показників лічильників тактів, які доводять модифікацію правил без пересинтезу бітстріму ПЛІС і без додаткових тактів затримки основного секвенсера.

### Межі робіт
* **Входить у план:** Реалізація й RTL-верифікація двобанкової обгортки пам'яті `CFG-P-HA` (`B4 Варіант 2`), розробка генератора пакетів оновлення правил (PYNQ PS через AXI4-Lite або Jetson через узгоджений інтерфейс), цифровий моніторинг стробів за допомогою `RP2040 PIO` та внутрішніх лічильників тактів, укладання звіту.
* **Не входить у план:** Розробка зовнішнього графічного інтерфейсу редактора онтологій або заміна базового однобанкового `CFG-P` до завершення верифікації ресурсів BRAM.

## Кроки й залежності

### Етап 1: Апаратна реалізація двобанкового RTL `CFG-P-HA` (`B4 Варіант 2`)
1. Створення двобанкової обгортки дескрипторів Block RAM (оскільки у базовому `CFG-P` Port B зайнятий 8-тактовим секвенсером, а 128-бітний дескриптор читається за 4 слова `W0..W3`):
   * Виділення активного та тіньового банків `RAMB36E1` / `RAMB18E1` (або 128-бітного тіньового регістра-защіпки перед комітом у початковому прототипі одного концепту);
   * Запис `W0..W3` у тіньовий банк без блокування читання/запису станів секвенсером в активному банку;
   * Атомарне перемикання покажчика активного банку строго на межі між подіями (`IDLE` / завершення `COMMIT`) з синхронізацією змінених станів.
2. Виведення стробових тестових сигналів (`3.3V LVCMOS` на PMOD):
   * `INJECT_STROBE` — початок запису нового дескриптора в тіньовий банк;
   * `BANK_SWAP_COMMIT` — такт перемикання активного банку;
   * `REACTION_OUT` — строб фіксації переходу концепту;
   * `SEQ_CYCLE_DONE` — індикатор завершення 8-тактового циклу секвенсера.

### Етап 2: Програмний стек інжекції правил
1. Розробка модуля керування на Seeed Studio J501 / PYNQ PS:
   * Генерація бінарного пакета оновлення правила: адреса концепту, нова маска дозволу, порогове значення компаратора, оновлений вектор підписників;
   * Передача пакета через високошвидкісний мікроінтерфейс у конфігураційний порт ПЛІС;
   * Верифікація коректності контрольної суми.

### Етап 3: Фізичні випробування на стенді
1. Прогін 1: Базовий вимір часу інжекції $T_{\text{inject}}$ для 1 концепту ($N = 1000$ ітерацій).
2. Прогін 2: Стрес-тест на відсутність джитеру в конвеєрі (запис нового правила відбувається в момент активної обробки подій за Port A).
3. Прогін 3: Верифікація коректності спрацьовування: підтвердження перемикання реакції на новий поріг спрацьовування без пропуску подій.
4. Збереження осцилограм VCD та числових вибірок у `../../data/exp_gpu_02_results.csv`.

## Абревіатури та глосарій

* **AXI-Lite** — полегшений синхронний інтерфейс шини ARM AMBA.
* **Port A / Port B** — незалежні порти доступу двопортової Block RAM.
* **RP2040 PIO** — програмований апаратний блок введення-виведення Raspberry Pi Pico.
* **True Dual-Port RAM** — статична пам'ять із повністю незалежними портами адресації та даних.
