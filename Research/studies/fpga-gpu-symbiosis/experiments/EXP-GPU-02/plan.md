# План: Проведення експерименту EXP-GPU-02 з онлайнового оновлення правил у BRAM

* **Версія:** 0.1.0
* **Дата:** 2026-11-13
* **Тип WP:** Plan
* **Власник:** Микола Федчик; автор експерименту — Микола Федчик.
* **Підстава:** Протокол [EXP-GPU-02](protocol.md), архітектурне рішення [B6](../../../../../Engineering/decisions/b6-gpu-persistent-kernel-subscribers.md), дослідження [fpga-gpu-symbiosis](../../README.md).

## Мета і межі

### Призначення плану
Цей план визначає порядок інженерної підготовки та стендового тестування механізму динамічного перезапису предикатних матриць активної пам'яті BRAM через виділений допоміжний порт (Port B) у ядрі `CFG-P` плати PYNQ-Z1.
Метою робіт є отримання метрологічно підтверджених часових діаграм, які доводять можливість миттєвої модифікації експертної логіки без перезавантаження бітстріму ПЛІС і без виникнення часового джитеру в основному конвеєрі реакції.

### Межі робіт
* **Входить у план:** Конфігурація двопортового інтерфейсу BRAM ядра `CFG-P`, розробка генератора пакетів оновлення правил (Host/Jetson через SPI або AXI-Lite), апаратний моніторинг латентності та безперервності конвеєра за допомогою Raspberry Pi Pico (RP2040 PIO), укладання звіту.
* **Не входить у план:** Розробка зовнішнього графічного інтерфейсу редактора онтологій або розширення ємності понад 64 концепти.

## Кроки й залежності

### Етап 1: Апаратна конфігурація RTL для Port B
1. Модифікація обгортки пам'яті `kpol_bram_pipeline`:
   * Підключення Port B двопортового блоку `RAMB36E1` / `RAMB18E1` до внутрішнього конфігураційного інтерфейсу;
   * Налаштування режиму роботи порту: асинхронний або синхронний запис конфігураційних слів (32/64 біт);
   * Забезпечення апаратної ізоляції від Port A (запобігання колізіям адреси за правилами True Dual-Port RAM).
2. Виведення стробових тестових сигналів:
   * `INJECT_STROBE` — сигнал початку запису нового правила в BRAM;
   * `REACTION_TRIGGER` — строб виникнення події за новим правилом;
   * `PIPELINE_JITTER_PROBE` — тактовий індикатор основного конвеєра.

### Етап 2: Програмний стек інжекції правил
1. Розробка модуля керування на Seeed Studio J501 / PYNQ PS:
   * Генерація бінарного пакета оновлення правила: адреса концепту, нова маска дозволу, порогове значення компаратора, оновлений вектор підписників;
   * Передача пакета через високошвидкісний мікроінтерфейс у конфігураційний порт ПЛІС;
   * Верифікація коректності контрольної суми.

### Етап 3: Фізичні випробування на стенді
1. Прогін 1: Базовий вимір часу інжекції $T_{\text{inject}}$ для 1 концепту ($N = 1000$ ітерацій).
2. Прогін 2: Стрес-тест на відсутність джитеру в конвеєрі (запис нового правила відбувається в момент активної обробки подій за Port A).
3. Прогін 3: Верифікація коректності спрацьовування: підтвердження перемикання реакції на новий поріг спрацьовування без пропуску подій.
4. Збереження осцилограм VCD та числових вибірок у `../../data/exp_gpu_02_results.csv`.

## Абревіатури та глосарій

* **AXI-Lite** — полегшений синхронний інтерфейс шини ARM AMBA.
* **Port A / Port B** — незалежні порти доступу двопортової Block RAM.
* **RP2040 PIO** — програмований апаратний блок введення-виведення Raspberry Pi Pico.
* **True Dual-Port RAM** — статична пам'ять із повністю незалежними портами адресації та даних.
