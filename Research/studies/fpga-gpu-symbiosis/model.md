# Модель: Дворівнева детермінована модель гетерогенного зв'язку ПЛІС і GPU

* **Версія:** 0.1.0
* **Дата:** 2026-11-12
* **Тип WP:** Model
* **Власник:** Микола Федчик; автор моделі — Микола Федчик.

## Об'єкт і призначення

Модель описує часові, комунікаційні та функціональні співвідношення гетерогенної системи, що поєднує:
1. **Рефлекторний контур (Рівень 1, ПЛІС / МК):** детекція подій, швидкісна редукція шуму та комбінаторна фільтрація в активній пам'яті BRAM за фіксований час $80\text{ нс}$ ($\sigma = 0\text{ нс}$).
2. **Когнітивно-аналітичний контур (Рівень 2, GPU):** банк нано-підписників подій, розміщений у пам'яті GPU (SRAM / Shared Memory / L2 Cache) під керуванням постійно активного персистентного ядра (Persistent Mega-Kernel).

Призначення моделі — теоретичний розрахунок гранично досяжної латентності $T_{\text{e2e}}$ та умов стійкості черги подій на межі ПЛІС $\to$ GPU.

## Визначення та часовий баланс

### 1. Рівняння наскрізної латентності ($T_{\text{e2e}}$)

Повний час реакції на подію від її фізичної появи на вході ПЛІС до завершення виконання підписки в потоці GPU визначається сумою 4 складових:

$$T_{\text{e2e}} = T_{\text{fabric}} + T_{\text{bus}} + T_{\text{gpu-poll}} + T_{\text{sub-exec}}$$

де:
* $T_{\text{fabric}} = 80\text{ нс}$ — детермінований час конвеєра BRAM ПЛІС (8 тактів при 100 МГц);
* $T_{\text{bus}}$ — час передачі зведеного бітового регістра подій через фізичну шину зв'язку (SPI DMA або 8/16-бітний паралельний інтерфейс):
  * Для SPI @ 50 МГц (64 біти пакету): $T_{\text{bus}} \approx 1.28\ \mu\text{с}$;
  * Для 8-бітної паралельної шини @ 50 МГц: $T_{\text{bus}} \approx 160\text{ нс}$;
  * Для GPUDirect RDMA over PCIe: $T_{\text{bus}} \approx 400\dots 600\text{ нс}$.
* $T_{\text{gpu-poll}}$ — затримка виявлення нового прапорця персистентним ядром GPU у Shared Memory / L2 Cache:
  $$T_{\text{gpu-poll}} \le 20\dots 50\text{ нс}$$
* $T_{\text{sub-exec}}$ — тривалість виконання тіла підписки на потоковому процесорі GPU:
  $$T_{\text{sub-exec}} = \frac{\text{WCET}_{\text{sub}}}{F_{\text{gpu}}}$$

### 2. Умова безперервної стійкості черги на вході GPU

Щоб черга подій на стику ПЛІС $\to$ GPU не переповнювалася при вхідному потоці з інтенсивністю $\lambda_{\text{in}}$, пропускна здатність передачі та обробки повинна задовольняти нерівність Джексона — Клейнрока:

$$\lambda_{\text{in}} \cdot P_{\text{filter}} \cdot P_{\text{route-gpu}} \le \min \left( \frac{B_{\text{bus}}}{W_{\text{event}}}, \frac{N_{\text{warps}} \cdot F_{\text{gpu}}}{\text{WCET}_{\text{sub}}} \right)$$

де:
* $P_{\text{filter}}$ — коефіцієнт апаратної фільтрації подій предикатором ПЛІС ($P_{\text{filter}} \le 1$);
* $P_{\text{route-gpu}}$ — частка подій, що адресуються до підписників у GPU;
* $B_{\text{bus}}$ — смуга пропускання шини (біти/с);
* $W_{\text{event}}$ — розрядність пакета події (біти);
* $N_{\text{warps}}$ — кількість паралельних варпів підписників, активних у пам'яті GPU.

## Перевірка і межі моделі

* **Що модель доводить:** Доводить принципову можливість усунення накладних витрат $3\dots 10\ \mu\text{с}$ хост-драйвера `cudaLaunchKernel` шляхом використання персистентного ядра та прямого шинного трансферу.
* **Чого модель не доводить:** Модель не враховує теплового тротлінгу модуля Jetson при 100% завантаженні SM ядрами опитування пам'яті, а також можливих конфліктів шини пам'яті LPDDR5 при високій активності тензорних ядер (якщо паралельно запущено нейромережу).

## Абревіатури та глосарій

* **WCET** (Worst-Case Execution Time) — максимальний час виконання функції в гіршому випадку.
* **Shared Memory** — швидка програмно-керована пам'ять потокового мультипроцесора GPU з часом доступу в кілька тактів.
* **Warp** — базова одиниця диспетчеризації в GPU (32 потоки, що виконують спільну інструкцію SIMT).
