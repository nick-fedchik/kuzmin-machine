# Конфігурації та межі доказів

* **Версія:** 0.1.0
* **Дата:** 2026-11-12
* **Тип WP:** Guide

## Призначення та склад

Конфігураційні файли зберігаються біля компонента; цей вхід визначає
зв'язки, не копіює XDC або скрипти вдруге.

| Об'єкт | Входи та спосіб перевірки |
|---|---|
| CFG-P: compiler/BRAM/CME | [Top](../hw/boards/pynq-z1/kpol_bram_pipeline_pynq_z1_top.v), [XDC](../hw/boards/pynq-z1/kpol_bram_pipeline.xdc), [збірка](../hw/boards/pynq-z1/build_bram_pipeline.sh), [loader](../hw/boards/pynq-z1/hil/hil_kpol_bram_pipeline.py). |
| CFG-I: окремий I/O trigger | [RTL](../hw/rtl/io/km_io_trigger_engine.sv), [симуляція](../hw/tb/km_io_trigger_engine_tb.sv); не самостійний доказ наскрізного compiler-тракту. |
| CFG-R: попередній реактивний gate-шлях | Лише [записи AV-10](../validation/experiments/AV-10/report.md) і [AV-11](../validation/experiments/AV-11/report.md). Legacy-реалізація з демо-блоками локально не включена. |

## Використання та обмеження

`BUILD_DIR` має задавати новий каталог збірки; скрипт не використовує
спільний старий build. Нова збірка має власний хеш, оточення й перевірку.
Перенесення шляхів та старий хеш bitstream не доводять тотожності
нового фізичного виконання. Частоти CFG-R не є межами CFG-P.

## Абревіатури та глосарій

CFG — локальне позначення конфігурації; XDC — обмеження FPGA;
I/O — введення/виведення; bitstream — двійкова конфігурація FPGA.
