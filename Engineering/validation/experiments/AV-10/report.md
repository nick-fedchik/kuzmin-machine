## 1. Мета експерименту та науковий контекст

Пряме фізичне вимірювання наносекундної затримки повного апаратного тракту:
$$\text{Зовнішній стимул (вхідний пін)} \longrightarrow \text{Апаратний транзакційний шлюз у PL} \longrightarrow \text{Реактивний вихід (вихідний пін)}$$
без участі центрального процесора (PS / ARM Cortex-A9) та ядра операційної системи Linux для експериментальної фальсифікації/підтвердження архітектурної вимоги **S6** та наукової гіпотези **$H_4$** (Issues #9, #72, #73).

### Етапи верифікації
1. **Етап 1 (Розвідувальний, Run 01, $N=1$):** Вимірювання базового реактивного шляху введення-виведення (`km_io_trigger_engine` / концепт `0p0`). Зафіксовано базову апаратну затримку $50.0\text{ нс}$.
2. **Етап 2 (Статистична фальсифікація, Run 03, $N=100$):** Повне тестування логіки реального шлюзу транзакцій `kpol_txn_gate_axi_lite` (перевірка предикатів, інваріантів, гіпотез і відсікання небезпечних станів) під керуванням апаратного генератора пачки зі 100 імпульсів із періодом $5.000\text{ мкс}$.

## 2. Апаратна конфігурація та підключення

### 2.1. Фізична комутація PMODA (Pmod JA) ↔ Raspberry Pi Pico

| Сигнал | Пін Pico (BB-102) | Канал LogicAnalyzer | Пін PYNQ-Z1 PMODA | Пін кристала Zynq-7020 | Призначення |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **GND** | Pin 3 / 8 (GND) | GND | Pin 5 (GND) | GND (Board Plane) | Спільна земля приладів |
| **STIM_JA1** | Pin 4 (GP2) | Channel 1 | Pin 1 (JA1_P) | `Y18` (LVCMOS33) | Вхідний стимул транзакції (монітор стимулу) |
| **REACT_JA2** | Pin 5 (GP3) | Channel 2 | Pin 2 (JA1_N) | `Y19` (LVCMOS33) | Апаратний вихід реакції `txn_committed` |
| **REACT_JA3** | Pin 6 (GP4) | Channel 3 | Pin 3 (JA2_P) | `Y16` (LVCMOS33) | Апаратний вихід `txn_rejected` (Fail-closed захист) |

*Примітка:* на платі PYNQ-Z1 сигнальні лінії роз'ємів Pmod захищені послідовними резисторами $200\ \Omega$ та ESD-діодами. Логічні рівні — LVCMOS33 ($3.3\text{ В}$).

### 2.2. Конфігурація RTL-шлюзу та генератора пачки
* **Тактова частота PL:** $f_{\text{clk0}} = 100.0\text{ МГц}$ ($T_{\text{clk}} = 10.0\text{ нс}$). Відповідає таймінгам OpenXC7 (максимальна частота синтезу $F_{\max} = 135.34\text{ МГц}$).
* **Синхронізація входу:** Швидкісний 2-ступеневий тригерний синхронізатор (обхід 10.4 мс дебаунсера).
* **Генератор пачки ($N=100$):** По фронту кнопки `BTN1` формується рівно 100 транзакційних запитів. Ширина імпульсу: $2.0\text{ мкс}$ ($200\text{ тактів}$), період: $5.0\text{ мкс}$ ($500\text{ тактів}$), загальна тривалість: $500\text{ мкс}$.
* **Конфігурація перемикачів:**
  * `SW0 = 1` (інваріант істинний) та `SW1 = 1` (припущення істинне) $\to$ шлюз фіксує коміт транзакції на піні `JA2`.
  * При `SW0 = 0` шлюз переходить у Fail-closed стан і скидає транзакцію через пін `JA3`.

## 3. Статистичні результати серії транзакцій ($N=100$)

Захоплення виконано на частоті $100\text{ MS/s}$ (131 000 відліків). Зафіксовано всі 100 транзакцій пачки:

| Параметр | Значення | Одиниці | Примітка |
| :--- | :--- | :--- | :--- |
| **Кількість подій ($N$)** | **100** | транзакцій | Повна пачка без жодного пропуску |
| **Мінімальна затримка ($t_{\min}$)** | **10.00** | нс | 1 відлік аналізатора |
| **Максимальна затримка ($t_{\max}$)** | **20.00** | нс | 2 відліки аналізатора |
| **Середня затримка ($\mu$)** | **19.40** | нс | Конвеєрна затримка шлюзу |
| **Медіана ($p50$)** | **20.00** | нс | 2 такти PL ($2 \times 10.0\text{ нс}$) |
| **90-й перцентиль ($p90$)** | **20.00** | нс | |
| **95-й перцентиль ($p95$)** | **20.00** | нс | |
| **99-й перцентиль ($p99$)** | **20.00** | нс | **Критерій $p99 \le 60.0\text{ нс}$ виконано із запасом $3\times$** |
| **Стандартне відхилення ($\sigma$, джитер)** | **2.39** | нс | Обумовлене асинхронним квантуванням дискретизатора |
| **Період між імпульсами** | **5.000** | мкс | Ідеальна стабільність апаратного таймінгу |

### Розподіл затримок
* **20.00 нс (2 такти):** 94 події ($94\%$).
* **10.00 нс (1 такт):** 6 подій ($6\%$).
* **Фізична природа розкиду:** Кварцовий генератор плати PYNQ-Z1 ($100\text{ МГц}$) та кварц Pico RP2040 ($100\text{ МГц}$) є незалежними та несинфазними. Незначне відносне биття частот (ppm drift) призводить до квантування дискретизатора LogicAnalyzer на межі $\pm 1$ такту ($\pm 10\text{ нс}$). Внутрішня затримка RTL-конвеєра є строго детермінованою і становить рівно 2 такти ($20\text{ нс}$).

## 4. Емпіричне порівняння з ОС Linux на тому ж кристалі Zynq-7020

Для усунення теоретичних припущень на цьому ж примірнику плати `pynq2` (ARM Cortex-A9 @ 650 МГц, ядро Linux 5.4) проведено прямі вимірювання затримок програмного доступу:

| Рівень обробки | Середня затримка | Типовий джитер ($\sigma$) | Порівняння з `kpol_txn_gate` |
| :--- | :--- | :--- | :--- |
| **Апаратний транзакційний шлюз PL (`kpol_txn_gate`)** | **20.0 нс** | **$\le 2.4\text{ нс}$** | **Базовий еталон ($1\times$)** |
| Native C: некешоване читання AXI через `/dev/mem` mmap | 121.2 нс | $\sim 5 - 15\text{ нс}$ | У **$6.1\times$** повільніше за RTL (тільки фізична шина) |
| Linux ISR: обробник апаратного переривання GPIO | $2.5 - 15.0\text{ мкс}$ | $\sim 1 - 5\text{ мкс}$ | У **$125\times - 750\times$** повільніше за RTL |
| Користувацький простір Linux (Python MMIO / sysfs) | 15.05 мкс ($15\,053\text{ нс}$) | $\sim 5 - 20\text{ мкс}$ | У **$752\times$** повільніше за RTL |
| Linux Context Switch + диспетчеризація процесу | $20 - 50\text{ мкс}$ | $\sim 10 - 50\text{ мкс}$ | У **$1000\times - 2500\times$** повільніше за RTL |

## 5. Висновок та верифікація гіпотези

1. **Вимога S6 та гіпотеза $H_4$ експериментально підтверджені:**  
   Повний апаратний шлях валідації транзакції від вхідного фізичного піна до формування захищеного реактивного сигналу на вихідному піні виконується за **$20.0\text{ нс}$** (на $100\text{ МГц}$), що суттєво перевершує узгоджений поріг $p99 \le 60.0\text{ нс}$.
2. **Нульова залежність від процесора (Zero CPU/OS overhead):**  
   Реакція формується суто апаратною матрицею логіки у PL. Жодне машинне переривання, перемикання контексту чи збій операційної системи Linux не здатні внести джитер або затримати реакцію шлюзу понад 2 такти тактової частоти.
3. **Fail-Closed гарантія:**  
   Апаратна логіка блокує транзакцію та виставляє сигнал аварійного відхилу (`ja3`) за той самий гарантований інтервал часу.
