# Звіт з експерименту S3-62: формальна верифікація та фальсифікація транзакційного шлюзу Fail-Closed (BMC / IC3-PDR)

* **Версія:** 1.0.1. **Review Report:** [review.md](review.md).
* **Дата виконання:** 2026-11-12 (UTC), хост `AORUS-5-SE` (x86_64, Linux).
* **Виконавець:** Antigravity (Google DeepMind).
* **Підстава:** 
  * [Issue #62](https://github.com/nick-fedchik/kuzmin-machine/issues/62): Фальсифікація S3: fail-closed формально (BMC).
  * [Issue #18](https://github.com/nick-fedchik/kuzmin-machine/issues/18): kpol_txn_gate_v2 без формальної верифікації (дефект F2′).
  * Батьківська системна вимога: **S3** (Fail-Closed поведінка шлюзу прийняття рішень).
  * Наукова гіпотеза: **H6** (Апаратний транзакційний вентиль гарантує неможливість переходу в небезпечний стан при будь-яких небезпеках чи збоях інваріантів).
* **Об'єкт:** Модуль ядра [`kpol_txn_gate_v2.sv`](../../../hw/rtl/core/kpol_txn_gate_v2.sv) (`DATA_WIDTH=32`, `FAIL_CLOSED_HAZARDS=1`).
* **Підсумок:** Гіпотезу **не спростовано в межах методу (NOT_REFUTED)**.
  * Властивості безпеки P1–P10 доведено математично без обмеження глибини рушієм необмеженої індукції (IC3/PDR).
  * Перехресна верифікація виконана методом Bounded Model Checking (BMC, $t=8$) рушієм Z3 4.13.3.
  * Невакуумність (Non-vacuity) доведена досягненням усіх 6 сценаріїв покриття C1–C6 ($t=8$).
  * Чутливість формального каркаса підтверджена 100% виявленням 4 штучно внесених дефектів-мутантів (F-03, обхід перевірки небезпеки, обхід інваріанту, мутація стану при відхиленні).

## 2. Специфікація формальних властивостей

Формальна обгортка реалізована у файлі [`s3_props.sv`](scripts/s3_props.sv). Властивості прив'язані до попереднього такту через стробування `past_valid && !p_rst && rst_n`.

### 2.1. Властивості безпеки (Safety Invariants P1–P10)

| ID | Формальне твердження | Фізичний зміст та захист від дефекту |
| :--- | :--- | :--- |
| **P1** | `!committed \|\| p_hazard_ok` | **Fail-Closed за небезпеки:** заборона коміту при активній або невідомій небезпеці (`hazard_true` або `!hazard_known`). |
| **P2** | `!committed \|\| p_inv_ok` | **Fail-Closed за порушення інваріанту:** заборона коміту при порушеному або невідомому інваріанті. |
| **P3** | `!committed \|\| p_input_ok` | **Fail-Closed за невалідного входу:** заборона коміту без відомого кандидата та істинного припущення (`assumption`). |
| **P4** | `!committed \|\| p_event_valid` | **Сувора причинність:** заборона довільного коміту без стробу вхідної події в попередньому такті. |
| **P5** | `!(committed && rejected)` | **Взаємне виключення:** виходи `committed_o` та `rejected_o` не можуть бути активними одночасно. |
| **P6** | `!(p_event_valid && p_input_ok && p_inv_ok && !p_hazard_ok) \|\| (rejected && rejected_hazard && hazard_blocked)` | **Детерміноване блокування небезпеки:** обов'язкова генерація `rejected` та `hazard_blocked` при небезпеці. |
| **P7** | `!(p_event_valid && p_input_ok && !p_inv_ok) \|\| (rejected && rejected_invariant)` | **Детерміноване відхилення інваріанту:** обов'язкова генерація `rejected_invariant` при збої інваріанту. |
| **P8** | `!(rejected \|\| !p_event_valid) \|\| (state == p_state)` | **Цілісність стану (Zero Side-Effect):** стан системи не змінюється при відхиленні транзакції або холостому ході. |
| **P9** | `!committed \|\| (state == p_cand_val)` | **Атомарне оновлення:** стан набуває значення `candidate_value` тоді й лише тоді, коли транзакція закомічена. |
| **P10** | `!committed && !rejected && state == 32'h0` | **Детерміноване скидання:** коректний нульовий початковий стан після активації `rst_ni`. |

### 2.2. Свідки досяжності (Coverage Witnesses C1–C6)

* **C1 (`C1_commit`):** успішний коміт валідної транзакції.
* **C2 (`C2_reject_hazard`):** детерміноване блокування транзакції через небезпеку.
* **C3 (`C3_reject_inv`):** відхилення через порушення інваріанту стану.
* **C4 (`C4_reject_input`):** відхилення через некоректний вхід/припущення.
* **C5 (`C5_alert_observed`):** спрацювання каналу телеметрії алерту (`alert_observed`).
* **C6 (`C6_state_changed`):** зміна значення стану (`state_o != p_state`).

## 4. Висновок

1. **Вимогу S3 та гіпотезу H6 підтверджено математично:**
   Транзакційний шлюз [`kpol_txn_gate_v2.sv`](../../../hw/rtl/core/kpol_txn_gate_v2.sv) за конфігурації `FAIL_CLOSED_HAZARDS = 1'b1` є строго fail-closed: жодна комбінація вхідних сигналів, невідомих значень або активних небезпек не здатна призвести до несанкціонованого коміту або неконтрольованої модифікації внутрішнього стану.
2. **Дефект F2′ повністю закрито:**
   Відсутність формальної верифікації для транзакційного шлюзу версії v2 усунуто, створено регресійний автоматизований тест [`test_s3_formal.py`](scripts/test_s3_formal.py), інтегрований у загальний тестовий набір `pytest`.
3. **Вердикт:** **NOT_REFUTED**.
