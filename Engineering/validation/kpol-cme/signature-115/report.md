## 1. Що не вдалося і обмеження

Це виправлення assertion у тесті, не алгоритму підпису, API чи
апаратного виконання. Воно не є аудитом криптографії, завершенням
S2 або реалізацією повного KPOL.

Негативний контроль використовує **mock** результату перевіряльника.
Він доводить чутливість конкретного тесту до `(False, причина)`,
а не стійкість підпису. Окремий позитивний запуск використовує
справжній перевіряльник; наявні регресії перевіряють також змінений
образ, неправильний ключ та інші відмови.

Перший link check пропустив приватні посилання на `drafts`, бо
`KM_DRAFTS_REPO` не був заданий. Повтор із явним шляхом до локального
репозиторію записано окремо; перший raw не переписано.

## 2. Метод

У [наявному тесті](../../../sw/kpol-ref/tests/test_kpol_reference.py)
`test_v10_concept_microcode_bram_generation` результат
`verify_bram_signature` розпаковано в `valid, msg`; assertion перевіряє
`valid` і передає `msg` у діагностику. Це той самий шаблон, що в
наявних тестах v0.6. Інших змін тестового сценарію немає.

Для контролю базовий файл прочитано через `git show` без перемикання
або зміни робочого дерева. Один і той самий метод виконано
з базовим і виправленим текстом; в обох випадках mock повертає
`(False, "CONTROL_SIGNATURE_REJECTED")`. Контроль перевіряє рівно
один виклик mock, відсутність помилок запуску та очікуваний результат.
Окремо виправлений метод виконано без підміни.

Повний код контролю, команда, дата з часовим поясом, хост, Python,
базовий SHA та хеші файлів містяться у
[negative-control-01.log](raw/negative-control-01.log).
Незмінність `kpol_reference.py` відносно бази перевірено побайтово.

Очікуваний `FAILED` усередині негативного контролю не є провалом
контрольного сценарію: його підсумок `CONTROL_EXPECTATIONS_MET`
та exit 0 означають, що відмінність старого й нового assertion
спостерігалася саме за заданим критерієм.

## 4. Перевірка критеріїв

Постановка #115 → зміна assertion → однакова mock-відмова для
базового/виправленого методу → raw-контроль і позитивні регресії.
Зворотний локатор — ім'я методу та SHA-256 тестового файлу в raw.
API `(bool, str)` та код генерації/перевірки підпису збережені.
