## 1. Що не вдалося і обмеження

Перший прогін виявив реальний дефект AXI-обгортки: зовнішній payload=0
підмінявся MMIO-регістром або одиницею. Це порушувало guard для допустимого
Int32, а не було Unknown або помилкою вхідної валідації.
[Baseline raw](raw/baseline-matrix-01.log) збережено без змін:
10 failed, 127 passed. Невдалі випадки — лише AXI-HW.

Виправлено вибір payload за джерелом тригера, без числового fallback.
Джерело без власного payload має явно сформувати потрібне значення;
0 більше не означає «візьми значення MMIO або 1». Арбітраж одночасних
SW/HW-тригерів не змінювався і цією матрицею не перевірений.

Це скінченні RTL-симуляції, не HIL, timing-вимірювання або універсальний
доказ еквівалентності. Події подаються по одній після завершення попередньої.
Навантаження черги, retention/backpressure [#151](https://github.com/nick-fedchik/kuzmin-machine/issues/151),
вхідний валідатор перед PL, багатоядерність і GPU не входили.
Граматика та CME-RAW-1 не розширювалися.

## 2. Метод

У [наявному pytest-файлі](../../../hw/tests/test_kpol_bram_pipeline.py)
додано параметризовану матрицю. Кожний текст компілюється чинним strict
CLI; образ завантажується цілком до незмінного за конфігурацією конвеєра.
Шляхи: direct BRAM + hardware trigger; AXI loader + MMIO trigger;
AXI loader + зовнішній hardware trigger. В останньому MMIO-регістр
навмисно має стороннє число, щоб нуль не можна було мовчки підмінити.

Еталон — математичний guard і кандидат стану за §3, незалежні від байтів
emitter; на дозволених трасах вони зіставляються з Interpreter.
При Int32 overflow референс піднімає KpolError; при DEC нижче нуля
дає InvariantViolation й утримує стан. У PL перевіряється відмова без
запису, а не рівність цих діагностик.

Для кожної події перевіряються W0, незмінність W1–W3, кількість
commit/reject та записів. Монітор забороняє записи порту B поза W0
і часткові записи. Початковий W0 очікується з текстової програми,
не копіюється з емітованого образу.

Кожний матричний випадок має негативний контроль: у копії raw-образу
інвертується guard, а початкове очікування зберігається. Вимагається
відмова саме на W0 після першої події, не timeout чи помилка завантаження.
Такий образ поза KPOL-CME-1 і навмисно подається в RTL для контролю;
це не нова дозволена конструкція мови або загальний mutation score.

Критерії й охоплення AXI-HW уточнені в #153 **до першого прогону** після
статичного виявлення підміни нуля. Після отримання результатів критерії
не послаблювалися. Raw містять команду, часовий пояс, хост, Git SHA,
стан worktree, source-хеші та exit code.
Версії Python/pytest/Icarus/Verilator/Yosys наведено у
[структурному raw](raw/structure-01.log).
Raw збережено verbatim, включно з кінцевими пробілами pytest у
діагностиці baseline; перевірка пробілів змін коду й документів виключає raw.

## 3. Результати

| Прогін | Факт / raw | Межа |
|---|---|---|
| До виправлення | 10 failed, 127 passed; [raw](raw/baseline-matrix-01.log). | Production RTL бази не змінено; нові тести вже додано. |
| Після виправлення | 137 passed, exit=0; [raw](raw/profile-matrix-02.log). | 135 матричних випадків і 2 наявні pipeline-тести, не 137 різних програм. |
| Повний pytest | 308 passed, 300 subtests passed, exit=0; [raw](raw/full-tests-01.log). | Регресії поточного дерева, не HIL або повний математичний доказ. |
| Open flow | exit=0; [raw](raw/open-flow-01.log). | RTL-симуляції, Verilator lint, XC7 logic synthesis; без P&R або фізичної плати. |
| Документи й індекс | exit=0; [raw](raw/structure-01.log). | Посилання, WP-структура, незмінність імпортованих входів і форматування; не змістова рецензія. |

Матриця має 45 варіантів програми на трьох шляхах: true та чотири
порівняння, INC/DEC, signed межі payload/limit, арифметичні відмови
та перейменування. Для кожного з 135 випадків інверсний контроль
відхилено. Перейменований варіант додатково має ті самі байти й проходить
ту саму трасу. Це покриття заданого набору, не всього Int32-домену.
Open flow містить попередження про ширини, невикористані сигнали й
розгортання пам'яті; raw їх не приховує. Fmax та фізичний ресурс не виміряні.

## 4. Перевірка критеріїв

| Критерій | Очікувано | Отримано / висновок |
|---|---|---|
| B3-REQ-02/06, guards | Порівняння над signed payload; однакова траса для дозволених імен. | Матриця проходить на трьох шляхах; перейменування не змінює образ чи трасу. |
| B3-REQ-06, межі | INC: MaxInt32, потім відмова; DEC: 0, потім відмова. | Обгорнуте значення не записується; кількість записів дорівнює commit. |
| B3-REQ-06, пам'ять | W1–W3 незмінні після кожної події, записи лише W0. | Читання дескриптора й монітор записів пройшли на заданих трасах. |
| §3, нульовий payload | 0 не підміняється stale MMIO-значенням. | Baseline ловить дефект; після виправлення ті самі випадки проходять. |
| Негативний контроль | Помилкова поведінка образу має порушити очікувану трасу. | У кожному випадку інверсія guard дає W0 mismatch на першій події. |
| Межа доказу | Не переносити симуляцію на FPGA чи всі програми. | HIL, навантаження FIFO та повна інтеграційна валідація залишаються окремими роботами. |
