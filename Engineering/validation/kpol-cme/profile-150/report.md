* **Виконавець:** GitHub Copilot CLI, Auto; конкретна модель не атестована.
* **Рецензент:** незалежна рецензія не проведена; автор не приймає власну роботу.

## 1. Що не вдалося і обмеження

Повний KPOL, авторська стекова граматика, `_`-state ABI, backpressure
та багатоядерний Serial Fallback не реалізовані цим кроком.
Поточний FIFO-drop залишається розбіжністю з авторським правилом;
його винесено в [#151](https://github.com/nick-fedchik/kuzmin-machine/issues/151).
Новий B5 v2 є Proposed, не прийнятим RTL-контрактом.

Безпрофільний compiler лишився сумісним експериментальним API з відомими
дефектами; підтриманий тут шлях вимагає `profile="KPOL-CME-1"`.
CLI використовує цей профіль автоматично. Це навмисне звуження CLI,
а не вилучення ширшого програмного референсу.

Перший цільовий прогін виявив неточність очікуваного коду діагностики:
аргумент Proof поза Int32 вже відхиляється typechecker як `B3-TYPE`,
а не профільним gate як `B3-PROOF`. Уточнено лише класифікацію тесту,
не послаблено вимогу відмови; [невдалий raw](raw/profile-regressions-01.log) збережено.

Перший повний pytest виявив відсутність цього Report за шістьма новими
посиланнями: [raw](raw/full-tests-01.log). Документ додано до повторного
прогону. Це власний дефект незавершеної навігації, не збій compiler.

Витяги авторських відповідей мають межі [Source-картки](../../../../Research/sources/author/rfc-2026-11-12.md):
первинний канал та автентичність оригіналів незалежно не перевірені.
Збережено статус отриманих відповідей; не приписано Автору новий ABI.

## 2. Метод

Референс та компілятор перевірялися на хості Python/pytest.
Версії Python, pytest, Icarus, Verilator і Yosys наведено в
[структурному raw](raw/structure-02.log).
Два наявні Counter increase/decrease виконувалися в direct/AXI
Icarus RTL-симуляції з незмінним RTL; перестановка образів є негативним
контролем. Це не HIL і не довільний клас програм.

Нові регресії перевіряють ручне очікування слота CME-RAW-1 для
true/EQ/NEQ/GT/LT, signed літералів, INC/DEC та перейменування правил,
відмови за позапрофільні AST, Proof gate і відсутність небажаної емісії.

До реалізації виконано негативний контроль на базі `0f92dcd`:
адаптер лише ігнорував новий keyword `profile`, викликаючи старий emitter;
CLI ще був незмінним. Це дозволило спостерігати дефекти lowering,
а не тільки помилку «unknown keyword»: інверсію за ім'ям, мовчазну
емісію unsupported-входів і невиконаний Proof.
[Первинний запис](raw/baseline-negative-control.log) містить дату, хост,
базу й pytest-відмови; новий тестовий код тоді був у робочому дереві.

Повні фінальні прогони мають у raw команду, час із часовим поясом,
Git SHA, хост, SHA-256 source/CLI/tests та код завершення.
Попередні raw не перезаписувалися.

## 3. Результати

| Перевірка | Факт / raw | Межа |
|---|---|---|
| Негативний контроль вихідної реалізації | Очікуваний pytest exit=1; [raw](raw/baseline-negative-control.log). | Адаптер нового keyword, старий emitter/CLI; не незалежна рецензія. |
| Референс, профіль і direct/AXI | 57 passed, 300 subtests passed; [raw](raw/profile-and-pipeline-02.log). | Скінченні software/RTL сценарії. |
| Повний pytest | 173 passed, 300 subtests passed, exit=0; [raw](raw/full-tests-02.log). | Не повнота всіх трас. |
| RTL open flow | exit=0; [raw](raw/open-flow-01.log). | Simulation, Verilator lint, XC7 logic synthesis; не P&R, бітстрім або фізичний запуск. |
| Документація й реєстр | [Фінальний raw](raw/structure-02.log), [попередній raw](raw/structure-01.log). | Посилання, зовнішня WP-структура, незмінність імпортованих входів, форматування; не змістова рецензія. |

У Verilator/Yosys залишаються попередження про RTL-ширини/невикористані
сигнали, розгортання FIFO в регістри й ширини BRAM-портів; raw їх не
приховує. Порогів фізичного timing або ресурсу цим прогоном не підтверджено.

## 4. Перевірка критеріїв

| Критерій | Очікувано | Локатор перевірки / результат |
|---|---|---|
| B3-REQ-01/03 | Unsupported не замінюється іншою програмою; імена не керують lowering. | `test_profile_rejects_unsupported_programs`, `test_profile_encodes_guards_and_renaming`; цільовий raw пройшов. |
| B3-REQ-02 | Один слот за CME-RAW-1, INC/DEC та дозволені guards. | Ручне пакування очікуваних слів; два direct/AXI сценарії пройшли, не весь домен RTL. |
| B3-REQ-04 | Syntax/type/profile/I/O відокремлені, existing output не змінюється. | `test_profile_cli_rejects_before_output`; цільовий raw пройшов. |
| B3-REQ-05 | Порожній/хибний/позапрофільний Proof не емітується. | `test_profile_checks_proof_before_emission`; цільовий raw пройшов. |
| KPOL-SYS-04/05 | Очікування черги та fallback визначені окремо від compiler. | Вимоги й B5 v2 актуалізовані; реалізацію **не** заявлено. |

## 5. Відтворення

З кореня worktree, не на платі:

```bash
python3 -m pytest -q -p no:cacheprovider
bash Engineering/hw/scripts/run_open_flow.sh
KM_DRAFTS_REPO=/path/to/drafts python3 Project/tools/check_links.py
python3 Project/tools/check_wp_documents.py
```

Для окремого профілю:

```python
image = compile_concept_microcode_bram_image(module, profile="KPOL-CME-1")
```

Порівняння SHA-256 потрібне, якщо відтворюється не весь зафіксований
коміт. Безпрофільний API не є альтернативою, що проходить ці критерії.
Hosted CI відображається в пов'язаному PR; цей Report фіксує локальні
перевірки, не замінює Review Report і не закриває батьківську #8.
