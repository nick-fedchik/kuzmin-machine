## 1. Обмеження та відхилення

Повну відповідність усіх норм KPOL 0.2–0.9 не перевірено: **#60 та S2 залишаються відкритими**. Висновок стосується Python-інтерпретатора, не концепції МК, апаратного захисту чи сертифікації. Повний pytest включає наявні RTL-симуляції; фізичне обладнання не використовувалося.

Дефолти `Interpreter` і `verify_module` вже були `True` до цього PR. Продукційний код не змінено; усунуто прогалину регресії, яка могла приховати повернення до `fail-open`.

Перший прогін відкинув невалідний тестовий модуль ще до виконання: [збережений результат](raw/run-20261110-01/receipt.json). Виправлення `covers` описано в протоколі; очікування не змінювалися. Рання перевірка посилань пропустила `drafts` через незадану змінну середовища; [повторна перевірка](raw/strict-links-20261110-01/receipt.json) виконана з локальним клоном.

Whitespace-попередження `git diff --check` стосуються лише сирих трас pytest. Їх не переформатовували; код і документація проходять перевірку окремо.

## 2. Метод

Очікування взято з [KPOL 0.2.0, §§2.2, 3 і 6](https://github.com/nick-fedchik/kuzmin-machine/blob/707fdba697d92ef9874c9013eb6f4f3cb2796d70/specs/kpol/kpol-0.2.0.md). Тести викликають API **без явного прапорця режиму**. Окремий негативний контроль повертає дефолт кожного API до `False` лише в пам'яті дочірнього процесу.

## 4. Висновок щодо критеріїв

Історичний F-02 про небезпечний дефолт на перевіреній версії **не відтворюється**. Регресія тепер перевіряє саме дефолт, а негативні контроли підтверджують її здатність виявити повернення дефекту. Це не підтвердження всієї гіпотези #60.

## 5. Відтворення

З кореня репозиторію:

```bash
python3 -m pytest -q sw/kpol-ref/tests/test_kpol_reference.py
python3 -m pytest -q
KM_DRAFTS_REPO=../drafts python3 tools/check_links.py
```

Для останньої команди потрібен локальний клон `drafts`; його шлях задається через `KM_DRAFTS_REPO`. Точні команди негативних контролів, коди виходу, час, SHA коміту та хеші журналів наведено в [receipt прогону](raw/run-20261110-02/receipt.json).
