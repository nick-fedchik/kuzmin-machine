## 0. Статус, межі та правило першості

### 0.1. Шари мови

| Шар | Що це | Джерело істини | Нормативний статус |
|---|---|---|---|
| **A. Авторська нотація** | Знаки, коди, структура концепту, групи, підписки й метанотація `Define`, як їх записав Автор. | Первинні матеріали Автора. | **[П]** — фіксується дослівно; документ формалізує лише засвідчене й не добудовує граматику. |
| **B. ### 0.2. Маркування тверджень

* **[П]** — дослівно або за точним локатором засвідчено в первинному матеріалі чи переданій відповіді Автора.
* **[В]** — інженерне рішення, інтерпретація або похідний контракт проєкту.
* **[Відкрито]** — питання поза межами наявних джерел. Лінійна нотація МУСИТЬ відхиляти такі форми гейтом `KPOL-AUTH-Uxx` (§5), а не тлумачити їх.

### 0.3. Принцип «без вигадок»

1. Правило шару A наводиться лише з локатором джерела. Неузгодженості самих джерел не виправляються, а перелічені в §2.10.
2. Правило шарів B і C має ідентифікатор (`KPA-LEX-*`, `KPA-SYN-*`, `KPA-CTX-*`, `KPA-CST-*`, `KPA-L-*`, `KPA-VM-*`) і джерело в коді (Додаток B).
3. Поведінку еталона, яка суперечить джерелам, нормі або іншому артефакту, не маскують правилом: її зафіксовано в Додатку C (`D-A1..D-A18`).

### 0.4. Правило першості

1. **Зміст** авторських понять визначають первинні джерела Автора. Цей документ не може їх розширити чи змінити.
2. **Прийняття/відхилення** тексту лінійної нотації та **артефакти зниження** визначає еталонна реалізація на зафіксованому коміті. Виявлена розбіжність з цим документом — дефект одного з артефактів; її МУСЯТЬ оформити Issue з рішенням власника, а до рішення чинною є поведінка еталона.
3. У разі розбіжності з описовим документом [`kpol-auth-subset.md`](kpol-auth-subset.md), посібниками чи статтями діє цей документ.

### 0.5. Нормативна лексика

Слова **МУСИТЬ**, **МУСИТЬ НЕ**, **ПОВИНЕН**, **НЕ ПОВИНЕН**, **МОЖЕ** — у значенні MUST, MUST NOT, SHOULD, SHOULD NOT, MAY за RFC 2119 / RFC 8174.

### 0.6. Відповідність

* **Відповідний текст `KPOL-AUTH`** — текст, що задовольняє `KPA-LEX-*`, `KPA-SYN-*` і `KPA-CTX-*` за типової політики `fail-closed` та не використовує форм, позначених у Додатку C як невідповідні.
* **Програма профілю `KPOL-AUTH-L1`** — відповідний текст, що додатково задовольняє `KPA-L-1..KPA-L-12`.
* **Відповідна реалізація** — для кожного входу дає той самий вердикт і той самий перший код діагностики, що й §3–§5; для відповідних текстів — CST, ізоморфний §6; для програм профілю — побайтно ті самі `code_o` і образ `CME-RAW-1`, що й §8.

## 2. Авторська нотація (шар A)

Усі твердження розділу — **[П]**, якщо не позначено інакше. Цитати подано мовою оригіналу.

### 2.1. Базові позначення (АН, слайд 1)

| Знак | Значення за Автором |
|---|---|
| `¤` | «Текущий концепт (ячейку) обозначим символом «¤»». Відносна адресація: `Go ¤-1 →`, `Go ¤+1 →`. |
| `Go a k` | «Адресация концепта осуществляется оператором Go за которым следует указание номера (адреса) концепта и далее вид адресации». `k` — вид адресації (§2.2). «Адресация как действие порождает соответствующее событие». |
| `_` | «Неопределенное состояние концепта (отсутствие значения или терминальный символ)», також подія `_`. |
| `Do op` | Арифметичний оператор: «Do за которым следует знак операции. Например операция сложения Do +». |
| `~` | «Класс событий сравнения >, <, = порождает оператор сравнения «~» и неопределенность состояния «_»». |

Пам'ять: «Чтение присходит из ячейки в стек, а запись из стека в ячейку» (`RFC-006`). Неініціалізований стан `_` «кодується окремим валідним бітом» (`RFC-005`); позиція й полярність біта не визначені.

### 2.2. Перелічувані знаки та їхні коди (АН, слайд 4, таблиця `Operation`)

Кожен перелік Автор оголошує групою типу `Token` (4 біти), тому коди лежать у `0..15`. Модуль нижче дослівно переносить імена й коди; ідентифікатори ASN.1 — транслітерація **[В]**.

```asn1
KPOL-AUTH-NOTATION DEFINITIONS AUTOMATIC TAGS ::= BEGIN

-- "?" Boolean: "!" True = 0, "¬" False = 1
AuthBoolean   ::= INTEGER { true(0), false(1) } (0..15)

-- "::" події з даними
AuthDataEvent ::= INTEGER {
    absent(0),      -- "_"  Отсутствует значение
    null(1),        -- Null Ноль
    positive(2),    -- Positive Больше нуля
    negative(3),    -- Negative Меньше нуля
    even(4),        -- Even Четное
    uneven(5),      -- Uneven Не четное
    change(6)       -- "~"  Изменение значения
} (0..15)

-- "~" порівняння
AuthCompare   ::= INTEGER { eq(0), gt(1), lt(2) } (0..15)      -- "=" ">" "<"

-- Go: вид адресації
AuthGoKind    ::= INTEGER { exec(0), write(1), read(2), init(3) } (0..15)   -- "|" "←" "→" ":"

-- Do: операції
AuthDoOp      ::= INTEGER {
    add(0), sub(1), mul(2), div(3), pow(4),       -- "+" "-" "*" "/" "^"
    inc(5),                                       -- "'"  Прибавление 1
    and(6), or(7),                                -- "&"  Or
    lnot(8), aneg(9),                             -- "¬" логічна інверсія, "#" арифметична інверсія
    shl(10), shr(11), cmp(12)                     -- "<" ">" "~"
} (0..15)

-- Біти байта Def (слайд 2 #155/#157; порядок — RFC-018)
AuthDefBit    ::= INTEGER {
    name(0), help(1), subscribe(2), organization(3),
    attributes(4), event(5), method(6), child(7)
} (0..7)

END
```

Службові елементи тієї самої таблиці без кодів: `Define` («Определение понятий»), `Convert` («Конвертация типов»), `Exit` («Выход из группы выполнения»), `Processor` («Добавить процессор»).

**[В] Відповідність кодам рантайму.** Біт `n` маски подій `KM_EV_*` у [`km_mcu_fpga_bridge.c`](../../sw/runtime/mcu/km_mcu_fpga_bridge.c) дорівнює коду `n` переліку `AuthDataEvent` (`ABSENT=0 … CHANGED=6`); біт `7` `KM_EV_ALWAYS` авторського відповідника не має. `KM_GO_EXEC/WRITE/READ = 0/1/2` і `KM_DO_ADD/SUB/MUL = 0/1/2`, `KM_DO_MOD_INC = 5` збігаються з кодами `AuthGoKind` та `AuthDoOp`; вид `init(3)` у рантаймі відсутній.

|---|---|---|
| `_` | «Отсутствие или любое значение» | `0` |
| `Token` | «Значения от 0 до 15» | `0` |
| `Byte` | ціле без знака, до 255 | `1` |
| `Int8` | ціле зі знаком, −128..127 | `1` |
| `U16` | ціле без знака, 2 байти | `3` |
| `U32` | ціле без знака, 4 байти | `7` |
| `Int32` | рядок 1: «2 Байта. От -32768 до 32767», `Size 3`; рядок 2: «4 Байта. -2147483648 до 2147483647», `Size 7` | `3` / `7` |
| `Float` | 4 байти з рухомою комою | `7` |

**[В] Спостереження.** У кожному рядку `Size` дорівнює кількості 4-бітних `Token` мінус 1 — той самий зсув «на 1», що й у межі `Max` (§2.6). Пізніше Автор повідомив: «Свойство Size я убрал на последних версиях. Теперь это пустое имя. Размер -Token» (`RFC-010`). Таблицю наведено як історичну; дубльований рядок `Int32` — неузгодженість джерела (§2.10).

### 2.4. Структура концепту (слайд 2 #155/#157, `RFC-010`, `RFC-018`)

* `Def` — «Байт. 1 каждого бита признак наличия соответствующей не обязательной компоненты»; `Class` — «Байт. Обязательный компонент».
* Біти `Def 0..7`: `Name`, `Help`, `Subscribe`, `Организация`, `Attributes/Property`, `Event`, `Method`, `Child` (перелік `AuthDefBit`).
* Порядок запису: «слева младший-справа старший. Порядок элементов записан правильно, но один лишний. Child. … При разработке уточним что с ним делать» (`RFC-018`).
* Атрибут із порожнім іменем зберігає значення типу: `: Byte "" _` — «Атрибут без имени для хранения значения данного типа». Знак `:` визначає підписку на подію ініціалізації; «Если в классе есть атрибут с пустым именем то, сразу за именем создаваемого концепта идет значение этого атрибута».

### 2.5. Події, підписки та «велика крапка» `•`

1. **Подія — вираз.** Подія `sᵢ` — підмножина станів; належність перевіряє логічний вираз `wᵢ(U)` зі значенням ІСТИНА на `sᵢ` (АН, слайд 1). «Сколько раз адресуемся столько и проверяем на событие»; «сравнение и изменение это разные события» (`RFC-005`).
2. **Підписка з маркером події.** Підписка записується після знака події: `←` запис, `→` читання, `|` виконання, `:` ініціалізація, `~` зміна/порівняння, значення-подія (`= 10`). Приклад Автора (АН, слайд 5): «Переменная счетчик. При адресации для записи обнуляется, а при вызове для выполнения прибавляет 1»

   ```text
   Byte i 0
   ← =0
   | +=1
   ```

3. **Розгортання в `Go`/`Do`.** Автор супроводжує підписки еквівалентом у `Go`/`Do` (АН, слайд 6): `← Tick +=1 '# Событие запись. Ведем счет. Go Tick → Do ‘ Go Tick ←` — читання `Tick`, `+1`, запис `Tick`.
4. **Булеві переліки як події** (слайд 4 #155): `Boolean F !` — оголошення й присвоєння ІСТИНИ; `F:=0` — «Ошибка присваивания хотя именно 0 значение»; `F |{ ! a + b ¬ a-b}` — «Подписка на событие F. При истинности сумма a и b, и разность если F-ложь».
5. **Параметри `@`.** «Это не оператор. Это для трансляции синтаксисом этим знаком определяются параметры» (`RFC-006`); метанотація: `Define Подписки {"Имя события" { {«@» {Concept}_{0}^{15}}_{0}^{1} Операторы}_{1}^{15} }_{0}^{15}` (слайд 5 #155).
6. **«Велика крапка» `•`** (АН, слайд 11): «свойством-событием булевого типа (?) с именем большая точка(•) определяющим успешность/не успешность выполнения … По умолчанию это свойство имеет значение ИСТИНА (!). Т.е. имея подписки w1 • w2 подписка w1 выполняется до самого факта чтения/записи, а по результату чтения записи (что фиксирует свойство • ) выполняется подписка w2». Для запису: «сначала выполняется подписка w1 (до изменения значения) которая, формирует значение для записи и случае успешности выполняется подписка w2. Факт не успешности можно зафиксировать присвоением свойству • значения Ложь. (•=¬)». Слайд 3 #155: «Результатом выполнения любого концепта является метасвойство (•) перечислимого типа Boolean (?) инициирующее одноименное Метасобытие».
7. **Порядок у `A • B`.** «наличие точки означает что подписка за ней выполняется после выполнения адресации. Для чтения-после чтения, для записи после записи» (`RFC-013`); «подписка B стартует после чтения текущего значения, после чего, как я понял ячейку A запишется значение, которое сформировано подпиской B» (`RFC-017`, відповідь 3).
8. **Придушення самоподії.** «Адресация к атрибуту в подписке к событию этого же атрибута не генерирует событие во избежании зацикливания» (АН, слайд 11).
9. **Черга.** «Если очередь переполнилась, то стоим ждем когда освободится» (`RFC-007`).

Отже, `•` в авторській мові **не є** запереченням: заперечення позначають `¬` (значення ХИБА, `AuthBoolean` = 1) та `Do ¬` (`AuthDoOp` = 8).

### 2.6. Групи (слайд 3 #155; #159; `RFC-009`, `RFC-011`, `RFC-012`)

| Дужки | Клас групи | Доступ і виконання |
|---|---|---|
| `( … )` | `Collection` | Послідовний доступ, за індексом і за іменем; елементи розділяються комами. |
| `{ … }` | `Collection` | Те саме без ком. |
| `[ … ]` | `Array` | Довільний доступ за індексом і паралельне виконання. |
| `« … »` | `Text` | Група концептів класу `Mark`. |
| `" … "` | `Name` | Як `Text`, без вкладення, не більше 16 елементів. |

* Закривальна дужка того самого типу, що й відкривальна (`RFC-011`). Іменована дужка — відкривальна дужка, за якою «непосредственно (без пробела)» іде ім'я групи, напр. `{Compare Token{ … }}`.
* Один елемент у дужках: у `« »` — сам знак `Mark`; у `[ ]` — «индекс, переключатель, имя или ключ»; у `( )` — не групування, а пріоритет чи зручність читання. Порожні `{}`/`()` — `Collection`, `[]` — `Array`, порожні `« »`/`" "` — порожній текст чи ім'я. Індексація з нуля (АН, слайд 12).
* `Min` і `Max` задаються підрядковим і надрядковим значенням після закривальної дужки; типово `Min=1`, `Max=0` — «одному обязательному выполнению группы Collection и выборке одного элемента один раз группе Array». Для значень типу `Token` це саме `Min`/`Max` (#159).
* Межа: «min=1 -одно обязательное выполнение max=15 максимум 16 раз. На 1 больше» (`RFC-009`), тобто ефективний діапазон `Min .. Max+1`.
* `Collection` успішна, якщо успішні всі елементи (семантичне І); `Array` — вибірка `Min` успішних елементів (семантичне АБО) `Max` разів; тимчасово: «пусть пока будет запуски. Внутри группы выполняются как семантическое И Array -ИЛИ» (`RFC-009`, атрибуція до п. 2 — припущення).
* Циклів немає: «циклы вообще отсутвуют» (`RFC-012`). Ступінь і індекс записуються надрядковим і підрядковим виразом, не знаком (`RFC-008`).

### 2.7. Метанотація `Define` (слайд 5 #155/#157)

Автор описує синтаксис власної мови тими самими групами:

```text
Define Word { Letter }^{15}                              #' От одной до 16 букв.»
Define Name [Word {«"» {Mark}_{0}^{15} «"»}]             #' Либо слово, либо до 16 знаков в прямых скобках.»
Define Help { «#» «'» {[Letter Mark ] }_{0}^{255} «»» }  #' Начинается с пары знаков.»
Define Static { Concept }_{0}^{15}
```

**[В] Відповідник в EBNF.** Пояснення самого Автора («от одной до 16», «либо … либо») узгоджуються з таким прочитанням: `{ X }_{m}^{n}` — послідовність (І) від `m` до `n+1` повторень `X`, типово `m = 1`; `[ X Y ]` — вибір (АБО); `«c»` — термінальний знак. Тоді

```ebnf
(* [В] переклад, не авторський текст *)
Word = Letter , 15 * [ Letter ] ;                     (* 1..16 букв *)
Name = Word | '"' , 16 * [ Mark ] , '"' ;             (* 0..16 знаків *)
Help = "#" , "'" , 256 * [ Letter | Mark ] , "»" ;    (* 0..256 *)
```

Це прочитання не поширюється на інші правила слайдів 5–8, де є порожні клітинки й повторені альтернативи (Q-AUTH-04).

### 2.8. Лексичний рівень Автора

* Help/коментар починається парою знаків і закінчується закривальною текстовою дужкою: `#' … »` (слайди 2, 5 #155). В АН трапляються записи `'# … »` і `#' … »`.
* «Знаки менял. В новой версии пара знаков что б # освободить» (`RFC-011`); нова пара не повідомлена (`RFC-016` без відповіді).
* `Name` обмежено 16 елементами; одиниця виміру (буква, байт чи `Token`) не визначена (`RFC-016` п. 3).
* Лексема має `Type`, `First`, `Length` і вкладене значення (слайд 7 #155).

### 2.9. Приклад Автора: машина Тьюрінга (АН, слайд 14)

Правило переходу МТ Автор записує як підписку на подію `sᵢ`: `wi = si (Go ¤.A → (vi)Do ¤ +d.Q → (fi)` — «при истинности события si записываем новое значение a’ (получаемое из vi ) а в концепт к которому собираемся переходить (¤+ d) записываем новое значение состояния q’». Повний клас `Class MT { … }` наведено в джерелі; цей документ його не нормалізує. Похідну конструкцію — у [дослідженні](../../../Research/studies/turing-construction/report.md).

## 3. Лінійна нотація: лексика (шар B)

**KPA-LEX-1 (кодування).** Вхід — текст Unicode, декодований з UTF-8. Позиція лексеми має координати в кодових точках (`line`, `column`, `offset`, `length`, `end_line`, `end_column`) і в байтах UTF-8 (`byte_offset`, `byte_end`).

**KPA-LEX-2 (пропуски).** Розділювачами є лише `U+0020`, `U+0009`, `U+000D`, `U+000A`. Інші пробільні символи Unicode (напр. `U+00A0`) дають `KPOL-AUTH-LEX-01`.

**KPA-LEX-3 (коментарів немає).** Лінійна нотація не має синтаксису коментарів і Help. Символ `#` спочатку активує гейт `KPOL-AUTH-U05`; лише за політики `record-diagnostic` він стає літералом `HASH_LEGACY`.

**KPA-LEX-4 (граматика лексем).** Лексеми розпізнаються зліва направо; на кожній позиції застосовується перша придатна альтернатива в порядку правила `token`.

```ebnf
token        = hash | text | assign | colon | open | close | single
             | integer | uninit | identifier ;
hash         = "#" ;                                         (* KPOL-AUTH-U05 *)
text         = '"' , { text_char - '"' } , '"'
             | "«" , { text_char - "»" } , "»" ;             (* TEXT; без закривального -> SYNTAX-01 *)
text_char    = ? будь-яка кодова точка, зокрема перенесення рядка ? ;
assign       = ":=" ;                                        (* перед colon *)
colon        = ":" ;
open         = "{" | "(" | "[" ;
close        = "}" | ")" | "]" ;
single       = "," | "@" | "+" | "-" | "*" | "/" | "=" | "<" | ">"
             | "!" | "¬" | "•" ;
integer      = digit , { digit } ;
digit        = ? символ c, для якого str.isdigit(c) ? ;
uninit       = "_" ;                                         (* лише якщо далі немає id_continue *)
identifier   = id_start , { id_continue } ;
id_start     = ? символ c, для якого str.isalpha(c) ? | "_" ;
id_continue  = ? символ c, для якого str.isalnum(c) ? | "_" ;
```

| Лексема | `Token.kind` | `Token.value` |
|---|---|---|
| `{` `(` `[` / `}` `)` `]` | `LBRACE` `LPAREN` `LBRACKET` / `RBRACE` `RPAREN` `RBRACKET` | сам знак |
| `,` `@` `+` `-` `*` `/` `=` `<` `>` | `COMMA` `AT` `PLUS` `MINUS` `STAR` `SLASH` `EQ` `LT` `GT` | сам знак |
| `!` `¬` `•` | `BOOL_BANG` `BOOL_NOT_SIGN` `SUBSCRIPTION_SEQ` | сам знак |
| `:=` `:` | `ASSIGN` `COLON` | сам знак |
| текст | `TEXT` | вміст **без** роздільників |
| ціле / `_` / ідентифікатор / `#` | `INT` / `UNINIT` / `IDENT` / `HASH_LEGACY` | точний фрагмент джерела |

**KPA-LEX-5 (текст).** `"…"` закривається першою `"`, `«…»` — першою `»`; інший роздільник усередині є звичайним символом (`«a"b»` → `a"b`). Символ `\` усередині тексту активує `KPOL-AUTH-U06`. Токен `TEXT` не зберігає, яким роздільником його записано: це видно лише зі `span` (`D-A13`).

**KPA-LEX-6 (класи символів).** Відповідний текст МУСИТЬ записувати цілі лише ASCII-цифрами `0`–`9`. Ідентифікатори МОЖУТЬ містити літери Unicode (зокрема кирилицю, як у метанотації Автора). Ширший клас цифр, який приймає еталон, описано в `D-A1`.

**KPA-LEX-7 (зарезервованих слів немає).** Лексер не має ключових слів. Особливе значення ідентифікаторів `Def`, `Name`, `Property`, `CloseBracked`, `Child`, `runtime`, `busy`, `Logic`, `Op`, `Min`, `Max`, `Count` (§5) і `Concept`, `Assign`, `OnPositive`, `OnAbort`, `Lower`, `Upper` (§8) визначає позиція в CST, а не лексер.

**KPA-LEX-8 (невідомий символ).** Будь-який інший символ, зокрема `'`, `^`, `¤`, `←`, `→`, `|`, `~`, `;`, `.`, `?`, дає `KPOL-AUTH-LEX-01`. Отже, авторські знаки адресації, подій і `Help` шару A **не мають** лінійного запису (§9).

## 4. Лінійна нотація: синтаксис (шар B)

**KPA-SYN-1 (граматика).**

```ebnf
program     = { statement } ;
statement   = expr , ( ":=" , statement            (* AssignmentCST, правоасоціативне *)
                     | { "•" , expr } ) ;          (* SubscriptionSeqCST, лівоасоціативне *)
expr        = postfix , { binop , postfix } ;      (* BinaryExprCST, лівоасоціативне *)
binop       = "+" | "-" | "*" | "/" | "=" | "<" | ">" | ":" ;
postfix     = primary , { array_group } ;          (* GroupBoundsCST *)
primary     = "@" , primary                        (* ParamCST *)
            | group
            | identifier , [ paren_group | brace_group ]   (* CallOrConstructCST, DefLayoutCST *)
            | integer | text | "!" | "¬" | "#"     (* LiteralCST *)
            | "_" ;                                (* UninitCST *)
group       = brace_group | paren_group | array_group ;
brace_group = "{" , elements , "}" ;
paren_group = "(" , elements , ")" ;
array_group = "[" , elements , "]" ;
elements    = { statement , [ "," ] } ;
```

**KPA-SYN-2 (жадібність).** Розбір детермінований з одним символом попереду: (а) ідентифікатор, за яким іде `(` або `{`, МУСИТЬ утворити конструкцію, навіть через пропуски (`A (B)` — конструкція `A`); (б) кожна наступна `[` МУСИТЬ приєднатися як постфіксна група меж (`A [i]` — межі, не індекс); (в) `binop` продовжує вираз; (г) два вирази без оператора — два окремі оператори (`A B` — два елементи програми).

**KPA-SYN-3 (пріоритет).** Усі `binop` мають **один** рівень пріоритету й лівоасоціативні: `A + B * C` означає `(A + B) * C`. Відповідний текст, що містить у виразі різні оператори, ПОВИНЕН явно розставляти круглі дужки (`D-A2`).

**KPA-SYN-4 (присвоєння і `•`).** Після першого `expr` оператора: якщо далі `:=` — присвоєння, права частина розбирається рекурсивно як `statement`; інакше — нуль або більше ланок `• expr`. Тому `A := B := C` = `A := (B := C)`, `A • B • C` = `(A • B) • C`, а в `A • B := C` лексема `:=` починає новий оператор і дає `KPOL-AUTH-SYNTAX-01`.

**KPA-SYN-5 (`•` лише інфіксний).** `•` у позиції початку `primary` дає `KPOL-AUTH-SYNTAX-03`.

**KPA-SYN-6 (числа без знака).** Унарних операторів немає, тому від'ємних літералів немає: `Lower=-1` і `Concept(A, -5)` дають `KPOL-AUTH-SYNTAX-01` (`D-A3`).

**KPA-SYN-7 (дужки).** Закривальна дужка МУСИТЬ бути того самого типу, що й відкривальна; невідповідна, зайва чи незакрита дужка дає `KPOL-AUTH-SYNTAX-02`. Елементи групи — оператори з необов'язковою комою після кожного; кома в початковій позиції або подвійна кома дають `KPOL-AUTH-SYNTAX-01`, кінцева кома (`(a,)`) допустима. На верхньому рівні програми кома не допускається.

**KPA-SYN-8 (`Def`).** Конструкція `Def(…)` або `Def{…}` МУСИТЬ мати рівно 7 елементів; 8 елементів активують `KPOL-AUTH-U11`, інша кількість дає `KPOL-AUTH-SYNTAX-04`.

## 5. Контекстні умови та гейти невизначеності

**KPA-CTX-1 (політика).** Конфігурація `AuthFrontendConfig` задає для кожного з кодів `KPOL-AUTH-U01..U12` політику `fail-closed` (типово) або `record-diagnostic`. За `fail-closed` перший спрацьований гейт зупиняє розбір помилкою з цим кодом. За `record-diagnostic` діагностика з рівнем `warning` записується в `ProgramCST.diagnostics`, а розбір продовжується. Відповідний текст МУСИТЬ НЕ активувати жодного гейта.

**KPA-CTX-2 (умови спрацьовування).**

| Код | Питання до Автора | Точна умова в CST |
|---|---|---|
| `KPOL-AUTH-U01` | `RFC-009` п. 2 | У групі меж `[…]` є елемент `Logic = e` або `Op = e`. |

| `KPOL-AUTH-U04` | `RFC-015` | `@`, ціль якого — ідентифікатор `runtime`. |

| `KPOL-AUTH-U06` | `RFC-016` п. 2 | Символ `\` усередині тексту. |
| `KPOL-AUTH-U07` | `RFC-016` п. 3 | `Name(x)` з рівно одним літералом `x` (будь-якого виду), довжина значення якого > 16 в одиницях `name_length_unit` (`utf8_bytes` типово або `codepoints`). |

**KPA-CTX-3 (порядок).** Гейти перевіряються в порядку розбору: лексичні (`U05`, `U06`) — під час токенізації всього тексту до синтаксичного аналізу; синтаксичні — у момент побудови відповідного вузла. Перший код діагностики є частиною вердикту (§0.6).

**KPA-CTX-4 (синтаксичні та лексичні помилки).** `KPOL-AUTH-LEX-01`, `KPOL-AUTH-SYNTAX-01..04` не залежать від політики й завжди зупиняють розбір.

## 6. Дерево конкретного синтаксису (ASN.1)

**KPA-CST-1.** Результат розбору — значення `Program` модуля нижче. Порядок елементів `SEQUENCE OF` дорівнює порядку в тексті.

```asn1
KPOL-AUTH-CST DEFINITIONS AUTOMATIC TAGS ::= BEGIN

Span ::= SEQUENCE {
    line        INTEGER (1..MAX),
    column      INTEGER (1..MAX),
    offset      INTEGER (0..MAX),       -- індекс кодової точки
    length      INTEGER (0..MAX),       -- у кодових точках
    endLine     INTEGER (0..MAX),
    endColumn   INTEGER (0..MAX),
    byteOffset  INTEGER (0..MAX),       -- UTF-8, включно
    byteEnd     INTEGER (0..MAX)        -- UTF-8, виключно
}

TokenKind ::= ENUMERATED {
    lbrace, rbrace, lparen, rparen, lbracket, rbracket, comma, at,
    plus, minus, star, slash, eq, lt, gt, boolBang, boolNotSign,
    subscriptionSeq, assign, colon, text, int, uninit, ident, hashLegacy
}

Token ::= SEQUENCE { kind TokenKind, value UTF8String, span Span }

GroupKind ::= ENUMERATED { collectionBrace, collectionParen, arrayBracket }

Node ::= CHOICE {
    identifier       Identifier,
    literal          Literal,
    uninit           Uninit,
    param            Param,
    group            BracketGroup,
    construct        Construct,
    bounds           GroupBounds,
    defLayout        DefLayout,
    subscriptionSeq  SubscriptionSeq,
    assignment       Assignment,
    binary           BinaryExpr
}

Identifier ::= SEQUENCE { span Span, token Token }                -- token.kind = ident
Literal    ::= SEQUENCE { span Span, token Token }                -- int | text | boolBang | boolNotSign | hashLegacy
Uninit     ::= SEQUENCE { span Span, token Token }                -- token.kind = uninit
Param      ::= SEQUENCE { span Span, atToken Token, target Node }

BracketGroup ::= SEQUENCE {
    span             Span,
    openToken        Token,
    closeToken       Token,
    kind             GroupKind,
    elements         SEQUENCE OF Node,
    commaTokens      SEQUENCE OF Token,
    hasStubBrackets  BOOLEAN
}

Construct ::= SEQUENCE { span Span, name Identifier, group BracketGroup }

GroupBounds ::= SEQUENCE {
    span          Span,
    target        Node,
    bracketGroup  BracketGroup,
    minRaw        INTEGER (0..MAX),
    maxRaw        INTEGER (0..MAX),
    minEffective  INTEGER (0..MAX),
    maxEffective  INTEGER (0..MAX)
}

DefLayout ::= SEQUENCE {
    span      Span,
    keyword   Identifier,
    group     BracketGroup,
    bits      SEQUENCE (SIZE (0..8)) OF INTEGER (0..MAX),
    bitOrder  ENUMERATED { lsbLeftMsbRight }
}

SubscriptionSeq ::= SEQUENCE { span Span, left Node, dotToken Token, right Node }
Assignment      ::= SEQUENCE { span Span, target Node, opToken Token, value Node }
BinaryExpr      ::= SEQUENCE { span Span, left Node, opToken Token, right Node }

Diagnostic ::= SEQUENCE {
    code             UTF8String,
    severity         ENUMERATED { error, warning },
    message          UTF8String,
    span             Span OPTIONAL,
    uncertaintyCode  UTF8String OPTIONAL,
    sourceRef        UTF8String OPTIONAL
}

Program ::= SEQUENCE { items SEQUENCE OF Node, diagnostics SEQUENCE OF Diagnostic }

END
```

**KPA-CST-2 (`span` складених вузлів).** `span` складеного вузла починається на `span` першої дочірньої лексеми чи вузла і закінчується на `span` останньої.

**KPA-CST-3 (`BracketGroup`).** `kind` визначає відкривальна дужка: `{` → `collectionBrace`, `(` → `collectionParen`, `[` → `arrayBracket`. `hasStubBrackets = TRUE`, якщо серед **безпосередніх** елементів є ідентифікатор `OpenBracket` або `CloseBracket`.

**KPA-CST-4 (`GroupBounds`).** Для групи меж `[…]` елементи переглядаються зліва направо; враховуються лише елементи `k = v`, де `k` — ідентифікатор. `Min`/`Max` з `v ∈ INT` запам'ятовуються (останнє входження перемагає), `Logic`, `Op`, нецілі `Min`/`Max` і `Count` — за KPA-CTX-2; інші елементи ігноруються без діагностики (`D-A4`). Далі

```text
min  := Min, якщо задано, інакше 1
max  := Max, якщо задано, інакше 0
minRaw       = min            -- поле названо «raw», але містить уже типове значення
maxRaw       = max
minEffective = min
maxEffective = max + 1        -- [П] «На 1 больше», RFC-009
```

Вкладені групи меж (`A[Min=1][Max=2]`) утворюють вкладені вузли `GroupBounds`; кожна група обчислюється окремо.

**KPA-CST-5 (`DefLayout`).** `bits` — значення цілих літералів серед елементів у порядку запису (зліва — біт 0, `[П]` `RFC-018`); інші елементи до `bits` не входять. Значення не обмежено множиною `{0, 1}` (`D-A5`).

**KPA-CST-6 (`Construct`).** Будь-яка інша пара «ідентифікатор + група `(…)`/`{…}`» — `Construct`; ім'я не перевіряється. Поле `bounds` описової моделі `CallOrConstructCST` еталон не заповнює: межі завжди обгортають конструкцію ззовні вузлом `GroupBounds`.

## 7. Відповідність авторської та лінійної нотації

Таблиця фіксує, як шар B записує засвідчені конструкції шару A. Рядок без лінійного запису означає, що конструкція **не** має відповідного тексту `KPOL-AUTH`.

| Авторська нотація (шар A) | Лінійна нотація (шар B) | CST | Статус |
|---|---|---|---|
| Група `( … )` / `{ … }` / `[ … ]` | та сама | `BracketGroup` з `kind` | [П] дужки; зміст доступу/виконання не моделюється. |
| Іменована дужка `{Compare Token{ … }}` | `Compare(…)`, `Compare{…}` — ім'я **перед** дужкою | `Construct` | [В] переставлення (`D-A12`). |
| Межі `{ … }_{m}^{n}` | `{ … }[Min=m, Max=n]` | `GroupBounds`, `maxEffective = n+1` | [П] семантика меж; [В] запис. |
| Один елемент у `[ ]` — індекс/ключ | немає | `A[i]` розбирається як межі (`D-A12`) | [Відкрито] для лінійного запису. |
| Байт `Def`, зліва молодший | `Def(b0, …, b6)` | `DefLayout` | [П] порядок; ширина 8 — `U11`. |
| `Name` у `" "`, `Text` у `« »` | `"…"`, `«…»` | `Literal` з `TEXT` (вид роздільника губиться) | [В] (`D-A13`). |
| Help `#' … »` | немає (`#` → `U05`, `'` → `LEX-01`) | — | [Відкрито] `RFC-016`. |
| `!` / `¬` | `!` / `¬` | `Literal` | [П] знаки; коди `0`/`1` у CST не підставляються. |
| `_` | `_` | `Uninit` | [П] знак; арифметика над `_` — `U10`. |
| `@` параметри | `@x` | `Param` | [П] роль; ABI параметрів не визначено. |
| `w1 • w2` / `A • B` | `A • B` (інфікс) | `SubscriptionSeq` | [П] порядок §2.5; булеве значення — `U08`, `busy` — `U09`. |
| `:=` присвоєння (`F:=0`) | `A := e` | `Assignment` | [П] знак; типізацію не перевіряє. |
| `Go a k`, `Do op`, `¤`, маркери подій `← → \| : ~` | немає (`LEX-01`) | — | Лише в байткоді шару C (§8.3). |
| `OpenBracket`, `CloseBracket` у `Static` | `Static(OpenBracket, …, CloseBracket)` | `hasStubBrackets` | [П] «заглушки»; `CloseBracked` — `U03`, `@runtime` — `U04`. |
| Пріоритет арифметики | один рівень, зліва направо | `BinaryExpr` | [В] (`D-A2`). |

## 8. Профіль зниження `KPOL-AUTH-L1` (шар C)

Уся семантика розділу — **[В]**. Профіль описує, як еталон `lowering.py` перетворює CST на артефакт `LoweredArtifact`: таблиці концептів і підписок, байткод `code_o` стекової машини `Do/Go` та 1024-байтний образ маршрутизації `CME-RAW-1`.

### 8.1. Умови прийняття

Вхід — `Program` без діагностик. Елементи верхнього рівня обробляються по черзі; перша порушена умова дає відповідний код, і зниження зупиняється.

| ID | Умова | Код відмови |
|---|---|---|
| `KPA-L-1` | `Program.diagnostics` порожній. | `KPOL-LOWER-UNCERTAINTY` |
| `KPA-L-2` | Кожен елемент верхнього рівня — оголошення концепту (`KPA-L-3`) або підписка (`KPA-L-6`). | `KPOL-LOWER-UNSUPPORTED-CST` |
| `KPA-L-3` | Оголошення: `Construct` з ім'ям `Concept`, перший елемент — ідентифікатор `N`, другий — ціле `Init`, решта — `Lower = n` або `Upper = n`. Вид дужок і коми не перевіряються (`D-A7`). | `KPOL-LOWER-CONCEPT`; нецілі `Init`/`n` — `KPOL-LOWER-LITERAL` |
| `KPA-L-4` | Імена концептів унікальні; концептів не більше 64. CID призначається в порядку оголошення `0, 1, …`. | `KPOL-LOWER-DUPLICATE-CONCEPT`, `KPOL-LOWER-LIMIT` |
| `KPA-L-5` | `Init`, `Lower`, `Upper` ∈ `[-2147483648, 2147483647]`; якщо задано обидві межі, `Lower ≤ Upper`. Повтор межі — діє останній. | `KPOL-LOWER-RANGE` |
| `KPA-L-6` | Підписка: `SubscriptionSeq` з лівою частиною-тригером `S`, `OnPositive(S)` або `OnAbort(S)` (рівно один аргумент-ідентифікатор), де `S` оголошено **раніше** в тексті. | `KPOL-LOWER-UNSUPPORTED-CST`, `KPOL-LOWER-UNKNOWN-CONCEPT` |
| `KPA-L-7` | Права частина — `Assign(D, e)` або група з непорожнім списком лише таких `Assign`. | `KPOL-LOWER-UNSUPPORTED-CST`, `KPOL-LOWER-EMPTY-SUB` |
| `KPA-L-8` | `Assign` має рівно два елементи, перший — ідентифікатор оголошеного концепту. | `KPOL-LOWER-ASSIGN`, `KPOL-LOWER-UNKNOWN-CONCEPT` |
| `KPA-L-9` | Вираз `e` складається з цілих у `[-32768, 32767]`, ідентифікаторів оголошених концептів, груп `( e )` рівно з одним елементом і бінарних `+`, `-`, `*`. | `KPOL-LOWER-RANGE`, `KPOL-LOWER-UNKNOWN-CONCEPT`, `KPOL-LOWER-EXPR`, `KPOL-LOWER-UNSUPPORTED-OP`, `KPOL-LOWER-UNSUPPORTED-CST` |
| `KPA-L-10` | Підписок не більше 128; слів `code_o` не більше 512. | `KPOL-LOWER-LIMIT` |
| `KPA-L-11` | Кожен концепт має не більше однієї підписки фази `POST_CHANGE` (тригери `S` і `OnPositive(S)` разом). | `KPOL-LOWER-FANOUT` |
| `KPA-L-12` | Ребра `S → D` підписок `POST_CHANGE` не мають самопетель, циклів і задовольняють `CID(D) > CID(S)`. Перевірка: спершу самопетлі, потім цикли (DFS), потім ранг. | `KPOL-LOWER-CYCLE` |

Кожен `Assign` у групі створює **окрему** підписку з тим самим тригером. Тому група з кількох `Assign` за тригера `S` чи `OnPositive(S)` завжди порушує `KPA-L-11`; її МОЖНА використовувати лише з `OnAbort(S)` (`D-A10`).

### 8.2. Таблиці концептів і підписок

| Тригер | `phase` | `trigger_mask` |
|---|---|---|
| `S` | `KM_PHASE_POST_CHANGE = 1` | `KM_EV_CHANGED = 0x40` |
| `OnPositive(S)` | `KM_PHASE_POST_CHANGE = 1` | `KM_EV_POSITIVE = 0x04` |
| `OnAbort(S)` | `KM_PHASE_ON_ABORT = 4` | `KM_EV_ALWAYS = 0x80` |

* Концепт: `flags = 0x08` (`KM_FLAG_HW_PROTECTED`), якщо задано `Lower` або `Upper`, інакше `0`.
* Підписки групуються за власником у порядку CID, усередині власника — у порядку тексту; `sub_idx` — порядковий номер у цьому розкладі. `first_sub_idx` — індекс першої підписки власника або `0`, якщо їх немає; `sub_count` — їх кількість.
* Лінії підписок розміщуються в `code_o` у тому самому порядку; `line_start_pc` — зсув першого слова, `line_len` — довжина лінії разом з `EXIT`.

### 8.3. Байткод `Do/Go`

**KPA-L-13 (слово).** `word = (opc mod 16) << 28 | (sub_op mod 16) << 24 | (flags mod 256) << 16 | (operand mod 65536)`. Зниження завжди записує `flags = 0`.

| Мнемоніка | `opc` | `sub_op` | `operand` | Шістнадцяткове слово |
|---|---|---|---|---|
| `IMM n` | `0x3` | `0` | `n mod 65536` (доповняльний код) | `0x3000nnnn` |
| `GO.READ c` | `0x1` | `0x2` | CID | `0x1200cccc` |
| `GO.WRITE c` | `0x1` | `0x1` | CID | `0x1100cccc` |
| `DO.ADD` / `DO.SUB` / `DO.MUL` | `0x2` | `0` / `1` / `2` | `0` | `0x20000000` / `0x21000000` / `0x22000000` |
| `EXIT` | `0x5` | `0` | `0` | `0x50000000` |

**KPA-L-14 (трансляція).**

```text
C⟦( e )⟧         = C⟦e⟧
C⟦n⟧             = IMM n
C⟦X⟧             = GO.READ cid(X)
C⟦e₁ op e₂⟧      = C⟦e₁⟧ · C⟦e₂⟧ · DO.k     де k(+) = ADD, k(-) = SUB, k(*) = MUL
Line⟦Assign(D, e)⟧ = C⟦e⟧ · GO.WRITE cid(D) · EXIT
```

Через `KPA-SYN-3` дерево `e` уже має лівоасоціативну форму без пріоритетів: `Assign(B, A + 1 * 2)` обчислює `(A + 1) * 2`.

```asn1

Instr ::= SEQUENCE {

    subOp    INTEGER (0..15),
```

### 8.4. Образ маршрутизації `CME-RAW-1`

**KPA-L-15.** Образ має 64 слоти по 16 байтів (`W0..W3`, `uint32` little-endian), формат слів — [KPOL-P0-1](kpol-formal-specification.md#71-формат-образу-cme-raw-1). Для концепту `c` з CID `k < N`:

```text
W0 = initVal(c) mod 2³²
W1 = 0
W2 = guard << 8,  guard = (flags(c) має 0x08 ? 0x02 : 0) | (є ребро POST_CHANGE k → d ? 0x10 : 0)
W3 = d, якщо є ребро k → d, інакше 0
```

Слоти `N..63` — нульові. Тригер (`CHANGED` чи `POSITIVE`), фаза `ON_ABORT`, значення `Lower`/`Upper` та `code_o` в образ **не** потрапляють (`D-A8`).

**Обмеження застосовності.** За апаратною семантикою [KPOL-P0-2](kpol-formal-specification.md#72-апаратна-семантика-кроку-дескриптора) фіксація (`COMMIT`) потребує `guard_flags[0] = 1` (`assumption_known`) і `guard_flags[1] = 1` (`invariant_known`), а каскад — `COMMIT`. Зниження ніколи не встановлює біт `0x01`, тому на `km_concept_micro_engine.sv` кожна подія до такого образу відхиляється, і каскад `W3` не спрацьовує. Образ є статичним описом графа маршрутизації для перевірки передумови леми `P2`, а **не** виконуваним профілем CME (`D-A9`). Виконувану семантику програми задає §8.5.

### 8.5. Абстрактна машина `Do/Go`

**KPA-VM-1 (стан).** `val_cur[k]`, `val_prev[k]` (обидва = `initVal`), `big_dot[k] = 0` для кожного CID; FIFO-черга індексів підписок; стек цілих.

**KPA-VM-2 (вектор подій).** Для значення `v` концепту:

```text
ev = ALWAYS
   ∪ (v = 0 ? NULL : v > 0 ? POSITIVE : NEGATIVE)
   ∪ (v парне ? EVEN : UNEVEN)
   ∪ (v ≠ val_prev ? CHANGED : ∅)
```

**KPA-VM-3 (запис `write(k, v)`).**

```text
якщо flags(k) має 0x08 і перевірка охоронця відхиляє v:
    big_dot[k] := 1                               -- '¬'
    поставити в чергу всі підписки власника k з phase = ON_ABORT (у порядку sub_idx)
    завершити
val_prev[k] := val_cur[k];  val_cur[k] := v;  big_dot[k] := 0      -- '!'
поставити в чергу всі підписки власника k з phase = POST_CHANGE і trigger_mask ∩ ev(v) ≠ ∅
```

Перевірка охоронця: в еталонній моделі тестів `ReferenceDoGoVM` — `Lower ≤ v ≤ Upper` для заданих меж; у C99-рантаймі — транзакція `km_fpga_execute_txn` до ПЛІС, яка межі `Lower`/`Upper` не отримує (`D-A8`).

**KPA-VM-4 (лінія).** Стек очищується; слова виконуються від `line_start_pc`: `IMM n` кладе `sext16(n)`, `GO.READ c` кладе `val_cur[c]`, `GO.WRITE c` знімає вершину й виконує `write(c, ·)`, `DO.k` знімає `rhs`, потім `lhs` і кладе `lhs k rhs`, `EXIT` завершує лінію.

**KPA-VM-5 (зовнішня подія).** `write(k, v)`, потім, поки черга непорожня, — виконання лінії з голови черги.

Розбіжності C99-рантайму з цією моделлю (переповнення черги й стека, `EXIT`, арифметичне переповнення) — `D-A11`.

### 8.6. Інтерфейс командного рядка

```bash
PYTHONPATH=Engineering/sw/kpol-auth python3 -m kpol_auth <input> [--check] \
    [--emit-bram <out.bin>] [--emit-dogo <out.json|out.bin>]
```

Вхід читається як UTF-8. Розбір і зниження виконуються до запису файлів. `--emit-dogo` з розширенням `.bin` пише слова `code_o` як `uint32` little-endian, інакше — JSON формату `kpol-auth-dogo-0.1.0`. Коди виходу: `0` — успіх, `1` — `KPOL-CLI-IO`, `2` — `KPOL-AUTH-*`, `3` — `KPOL-LOWER-*`.

## Додаток C. Відомі розбіжності та невизначеності

Пункти нижче не є нормою мови. Кожен потребує рішення власника: виправити реалізацію, закріпити поведінку в нормі або передати питання Автору.

| ID | Фактична поведінка | Вимога до відповідного тексту |
|---|---|---|
| `D-A1` | Цифри визначаються `str.isdigit`. Цифри Unicode класу `Nd` (напр. `٣`) приймаються як ціле; символи на кшталт `²`, які `isdigit` приймає, а `int` — ні, дають необроблений `ValueError` у межах, `Def` і зниженні замість діагностики. Водночас Автор пише ступені й індекси надрядковими знаками (`RFC-008`). | Лише ASCII-цифри. |
| `D-A2` | Один рівень пріоритету для `+ - * / = < > :`; зниження обчислює `A + B * C` як `(A + B) * C`. Авторський пріоритет не визначено (`N-11`). | Розставляти дужки. |
| `D-A3` | Немає унарного мінуса й від'ємних літералів; від'ємні `Init`, `Lower`, `Upper`, константи неможливо записати, хоча діапазони `KPA-L-5`, `KPA-L-9` їх допускають. | Не використовувати від'ємні значення. |
| `D-A4` | Межі `[…]`: невідомі ключі й елементи не вигляду `k = v` мовчки ігноруються; `Min > Max + 1` дає порожній інтервал без діагностики; `Count` перевіряється лише проти `Min`/`Max`, записаних лівіше; `minRaw` містить типове значення, а не «сире». | Лише `Min`, `Max`, `Count` у порядку `Min, Max, Count`; `Min ≤ Max + 1`. |
| `D-A5` | Значення бітів `Def` не обмежено `{0, 1}`; нецілі елементи мовчки випадають з `bits`. | Лише `0` або `1`. |
| `D-A6` | Гейт `U07` перевіряє лише `Name` з одним літералом (зокрема ціле); `U08` не бачить `•` усередині аргументів конструкції (`A := F(B • C)`); `U10` не бачить `_` у дужках (`(_) + B`); `U09` не перевіряє ліву ланку (`busy • A`) і бінарні вирази (`A • busy + 1`). | Не використовувати ці форми. |
| `D-A7` | Зниження не перевіряє вид дужок і коми в `Concept`, `Assign`, `OnPositive`, `OnAbort`: `Concept{A, 0}` і `Concept(A 0)` приймаються. | Писати `Concept(N, Init, …)` з `()` і комами. |
| `D-A8` | Значення `Lower`/`Upper` є лише в таблиці концептів (JSON); в образі — тільки біт `0x02`, у C99-рантаймі вони не передаються до ПЛІС. Тригер `OnPositive` в образі невідрізненний від зміни; `ON_ABORT` в образ не потрапляє. | Не покладатися на образ як на носій меж і тригерів. |
| `D-A9` | Образ не встановлює `guard_flags[0]` (і `[1]` для концептів без меж), тому на `km_concept_micro_engine.sv` кожна подія відхиляється, а каскад не спрацьовує (§8.4). | Не завантажувати образ `KPOL-AUTH-L1` як виконуваний профіль CME. |
| `D-A10` | Група з кількох `Assign` дає кілька підписок одного тригера; для `S`/`OnPositive(S)` це завжди `KPOL-LOWER-FANOUT`. Ребра `ON_ABORT` у перевірку ациклічності не входять: `OnAbort(A) • Assign(A, 1)` приймається. | Групи `Assign` — лише з `OnAbort`; не будувати циклів через `OnAbort`. |
| `D-A11` | C99-рантайм: переповнена черга (64) мовчки відкидає підписку, тоді як Автор вимагає чекати (`RFC-007`); стек (16) мовчки ігнорує переповнення й спустошення; `EXIT` не розпізнається, лінія виконується до `line_len`; знакове переповнення `int32_t` у `DO` не визначене мовою C. `ReferenceDoGoVM` вимагає `EXIT` і рахує без переповнення. | Не будувати трас, що досягають цих меж. |
| `D-A12` | Авторська іменована дужка — ім'я **після** відкривальної дужки без пропуску (`{Compare …}`); лінійна — ім'я перед дужкою з довільними пропусками. Авторський один елемент у `[ ]` — індекс/ключ, лінійний `A[i]` — межі без ключів (`1..1`). | Не використовувати `X[…]` як індекс. |
| `D-A13` | `"…"` (Автор: `Name`) і `«…»` (Автор: `Text`) дають один вид `TEXT`; різниця видна лише зі `span`. Синтаксису `Help`/коментаря немає. | Не покладатися на вид роздільника в CST. |
| `D-A14` | Зниження трактує `S • Assign(D, e)` як каскад «зміна `S` → запис `D ≠ S`» і забороняє самопетлі. За Автором у `A • B` значення, сформоване підпискою `B`, записується в ту саму комірку `A` («как я понял», `RFC-017`), а `w1 • w2` — дві підписки одного концепту (АН, слайд 11). Профіль `KPOL-AUTH-L1` не реалізує авторської семантики `•`. | Не видавати артефакти `KPOL-AUTH-L1` за виконання авторського `•`. |
| `D-A15` | Корпусний приклад `EX-05` `(A, B) • Do(A, B)` використовує `Do` як звичайну конструкцію шару B, а не авторський оператор `Do op`; його не можна знизити (`KPOL-LOWER-UNSUPPORTED-CST`). | — |
| `D-A16` | Описовий документ [`kpol-auth-subset.md`](kpol-auth-subset.md) до версії 0.1.1 вказував класи `[A-Za-zА-Яа-я…]` для ідентифікаторів і `[0-9]+` для цілих та не згадував `D-A2`, `D-A3`, `D-A9`. | Діє цей документ (§0.4). |
| `D-A17` | Лінійна нотація не має записів для `Go`, `Do`, `¤`, маркерів подій `← → \| : ~`, `Class`, `Define`, `Static` як оголошення та авторських типів (§7). | Ці конструкції не входять до відповідного тексту. |
| `D-A18` | Компілятор VMK (Go) `compileKPOLAuth` у [`kpol_compiler.go`](../../sw/vmk-go/internal/vmk/kpol_compiler.go) — регулярно-виразна підмножина: розпізнає лише `Concept(N, n` з `n` вигляду `-?[0-9]+` і `S • Assign(D, X op n)` (також з псевдонімом `(*)` замість `•`), мовчки ігнорує решту тексту без гейтів `U01..U12`, встановлює `INVARIANT_EN` усім оголошеним концептам і будує окремі виконувані дескриптори з `ASSUMPTION_EN`. Він не є відповідною реалізацією §3–§8. | Еталонні артефакти отримувати з `Engineering/sw/kpol-auth`. |

## Абревіатури та глосарій

* **KPOL-AUTH** — native-діалект мови Машини Кузьміна за первинними матеріалами М. Ю. Кузьміна.
* **АН** — авторська презентація «Пример для АН».
* **CST** — дерево конкретного синтаксису; зберігає лексеми, дужки й координати.
* **ASN.1** — *Abstract Syntax Notation One*, ITU-T X.680.
* **EBNF** — розширена форма Бекуса — Наура, ISO/IEC 14977.
* **`Do/Go`** — 32-бітний байткод стекової машини ліній підписок.
* **CME-RAW-1** — 1024-байтний образ 64 дескрипторів концептів.
* **CID** — індекс концепту (`0..63`).
* **`Token`** — авторська 4-бітна одиниця пам'яті; не плутати з лексемою лексера.
* **`•` («велика крапка»)** — авторська Boolean-метавластивість результату виконання й пост-адресний бар'єр підписки.
* **Гейт невизначеності** — правило, що відхиляє текст, зміст якого Автор не визначив.
* **Fail-closed** — відхилення за невідомого стану замість припущення.
