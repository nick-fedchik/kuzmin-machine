# KPOL-CME-2: специфікація багатоконцептного профілю компіляції на форматі CME-RAW-1

* **Версія:** 0.1.0
* **Дата:** 2026-11-14
* **Тип WP:** Specification
* **Статус:** Реалізовано в референсному компіляторі та CLI для розгляду на рецензії; не змінює погоджений `Decision B3-01` для `KPOL-CME-1` і не змінює RTL `CFG-P`.
* **WI:** [#184](https://github.com/nick-fedchik/kuzmin-machine/issues/184) (sub-issue [#8](https://github.com/nick-fedchik/kuzmin-machine/issues/8)).
* **Походження:** розширення виконавчого інженерного профілю понад [KPOL-CME-1](kpol-cme-subset-0.1.0.md) на незмінному 16-байтному слоті `CME-RAW-1` після верифікації семантики ядра CME ([#167](../hw/kpol-image-loader-pipeline-contract.md)), черги B5 v2.2 ([#151](../hw/event-queue-ingress-specification.md)) та виправлень референсу ([#183](../../validation/kpol-cme/verifier-lowering-183/report.md)).
* **Укладач:** GitHub Copilot CLI (Gemini 4 Carbon, `gemini-4-carbon`); незалежна рецензія не проведена.

## 1. Призначення та межі

Профіль `KPOL-CME-2` визначає детерміновану багатоконцептну підмножину поточного інженерного синтаксису KPOL, яка компілюється у чинний 1024-байтний образ BRAM `CME-RAW-1` ($64 \times 16$ байтів) і має побітово ідентичну спостережувану поведінку між еталонним `Interpreter` (`kpol_reference.py`) та RTL-трактом `CFG-P` (`kpol_bram_pipeline_axi.sv`: `km_concept_micro_engine.sv` + `kpol_txn_gate_v2.sv` + `km_autonomous_sequencer.sv`) без жодної модифікації RTL.

* Профіль обирається явно: `compile_concept_microcode_bram_image(module, profile="KPOL-CME-2")` або прапорцем `--profile KPOL-CME-2` у [`compile_kpol_bram_image.py`](../../hw/scripts/compile_kpol_bram_image.py).
* Початковий профіль [`KPOL-CME-1`](kpol-cme-subset-0.1.0.md) залишається типовим значенням CLI (`--profile KPOL-CME-1`) і зберігається без змін.
* Конструкції, які не можуть бути виконані на `CME-RAW-1` без розходження між програмною моделлю та RTL, відхиляються компілятором до емісії образу (`fail-closed`) із детермінованим префіксом `CME2-*`.

| Межа поза `KPOL-CME-2` | Причина у `CME-RAW-1` / джерелах | Куди віднесено |
| :--- | :--- | :--- |
| Неініціалізований стан `_` (`KPOL-SYS-02`) | У `W0` немає окремого `valid`-біта для відокремлення `_` від `0` | [#185](https://github.com/nick-fedchik/kuzmin-machine/issues/185) (`CME-RAW-2`) |
| Одночасний літерал охоронця та `ADD/SUB` із кроком $\ge 2$ | Спільне 32-бітне поле `W1 = operand_val` у 16-байтному слоті | [#185](https://github.com/nick-fedchik/kuzmin-machine/issues/185) (`CME-RAW-2`) |
| Присвоєння довільної константи `set S := K` та `state-guard` | `CME_ACT_ASSIGN` бере значення з `event_param_i`, а `pred_code` порівнює `event_param_i` | [#185](https://github.com/nick-fedchik/kuzmin-machine/issues/185) (`CME-RAW-2`) |
| `Hazards` та `on reject ... covers` | `km_autonomous_sequencer.sv` не записує окремий `Bool`-стан прапорця відмови при `cme_committed == 0` | [#185](https://github.com/nick-fedchik/kuzmin-machine/issues/185) (`CME-RAW-2`) |
| Токен `•`, `(*)`, `Concept`/`Define`/`Group`/`@` | Авторський native-діалект очікує відповідей на `RFC-009` і `RFC-015–017` | [#186](https://github.com/nick-fedchik/kuzmin-machine/issues/186) (`KPOL-AUTH`) |

## 2. Дозволена підмножина синтаксису та семантики

Модуль `KPOL-CME-2` повинен проходити `parse_module` і `check_module` без діагностичних помилок та задовольняти такі структурні умови:

1. **Відсутність позапрофільних секцій і токенів:**
   * AST-списки `imports == []`, `types == []`, `units == []`, `channels == []`, `supervisors == []` мають бути порожніми (`CME2-SHAPE`; непідтримувані лексеми відхиляються раніше на етапі `parse_module` — `CME2-SYNTAX` у CLI);
   * `hazards == []` (порушення — `CME2-HAZARD`);
   * лексеми `•` та `(*)` заборонені в усьому тексті модуля (`module.phase_aliases_used == False`, порушення — `CME2-GUARD`);
   * `cascade_map` у виклику API заборонений (`CME2-CASCADE`) — каскади виводяться виключно з правил `on change(...)` самого модуля.
2. **Концепти (стани `State`):**
   * від $1$ до $64$ оголошень `State_i: Int32 = Init_i;` у межах знакового 32-бітного діапазону `[-2147483648, 2147483647]`; індекс оголошення визначає `CID` $\in [0, N-1]$;
   * слоти `CID` $\in [N, 63]$ заповнюються нулями (`guard_flags == 0x00`, fail-closed відхилення випадкових звернень);
   * невідомий початковий стан `Unknown` (`Literal(UNKNOWN)`) або `Owner` не підтримуються (`CME2-SHAPE`).
3. **Інваріанти (`Invariants`):**
   * кожний оголошений стан `S` зобов'язаний мати явний інваріант невід'ємності `S >= 0` (або еквівалентний `0 <= S`), узгоджений з апаратною перевіркою `~next_state[31]` у `kpol_txn_gate_v2.sv`;
   * початкове значення кожного стану зобов'язане задовольняти `Init_i >= 0` (`CME2-INVARIANT`);
   * секції `Assumptions` та `Goals` у `KPOL-CME-2` не підтримуються (відхиляються з `CME2-GUARD` та `CME2-INVARIANT` відповідно).
4. **Правила (`Solution`) і відображення на `CID`:**
   * кількість правил дорівнює кількості станів ($1:1$ між станом `S_dst` і правилом, що його оновлює; рівно одне присвоєння `set S_dst := ...` у тілі правила, без `emit` / `send` / `Alert`);
   * кожне правило є **або зовнішнім**, **або каскадним**:
     * **зовнішнє правило:** `rule R on Ev(p) when G { set S_dst := Expr; }`, де кожна оголошена подія `Ev(p: Int32)` використовується рівно в одному зовнішньому правилі (бієкція `Event <-> зовнішній концепт`);
     * **каскадне правило:** `rule R on change(S_src) when G { set S_dst := Expr; }`, де рівно один стан `S_src` зазначений у `change(...)`, і `S_src` сам оголошений у цьому модулі.

## 3. Охоронці (`when`), дії (`set`) і колізія `operand_val`

### 3.1. Канонічні форми охоронця

У правилі з параметром `x` (де `x` — формальний параметр `p` зовнішньої події або ім'я стану-видавця `S_src` у `on change(S_src)`, бо під час каскаду `km_autonomous_sequencer.sv` передає нове значення `S_src` на вхід `cme_event_param`) дозволяються:

* булеві константи `true`, `false` та довільна кількість зовнішніх унарних `not`;
* односторонні знакові порівняння `x == K`, `x != K`, `x < K`, `x > K`, `x >= K`, `x <= K` (або дзеркальні `K op x`), де $K \in [-2147483648, 2147483647]$:
  * `>=` кодується як `CME_GUARD_INVERT_ASSUMPTION (0x08)` + `CME_PRED_LT (0x04)`;
  * `<=` кодується як `CME_GUARD_INVERT_ASSUMPTION (0x08)` + `CME_PRED_GT (0x03)`;
* двосторонній знаковий інтервал `Binary("and", left, right)` над тією самою змінною `x` (включно з `not (...)` зовні), що зводиться до $lo \le x \le hi$:
  * суворі межі `>` та `<` зсуваються до включних $lo + 1$ та $hi - 1$;
  * якщо після зсуву $lo < -32768$, $hi > 32767$ (зокрема `x > 32767` або `x < -32768`) або $lo > hi$, компіляція завершується помилкою `CME2-RANGE`.

Будь-яке звернення охоронця до власного стану концепту (окрім `S_src` у `on change(S_src)`), арифметика в охоронці або невідомий оператор відхиляються з `CME2-GUARD`.

### 3.2. Канонічні форми дії та детектор колізії `operand_val`

Для цільового стану `S_dst` дозволені такі форми правої частини `set S_dst := Expr`:

| Конструкція KPOL | Код `action_opcode` | Потреба `operand_val` | Примітка щодо `CME-RAW-1` |
| :--- | :--- | :--- | :--- |
| `set S_dst := x` (`p` або `S_src`) | `CME_ACT_ASSIGN (0x00)` | Ні | Копіює 32-бітний `event_param_i` у стан `S_dst` |
| `set S_dst := S_dst + 1` або `1 + S_dst` | `CME_ACT_INC (0x01)` | Ні | Операнд `+1` зашитий в opcode RTL |
| `set S_dst := S_dst - 1` | `CME_ACT_DEC (0x02)` | Ні | Операнд `-1` зашитий в opcode RTL |
| `set S_dst := S_dst + K` або `K + S_dst` ($K \ge 2$) | `CME_ACT_ADD (0x03)` | Так (`W1 = K`) | Знакове додавання з перевіркою переповнення |
| `set S_dst := S_dst - K` ($K \ge 2$) | `CME_ACT_SUB (0x04)` | Так (`W1 = K`) | Знакове віднімання з перевіркою переповнення |

**Правило колізії операнда (`CME2-OPERAND-COLLISION`):** якщо правило одночасно потребує `W1 = operand_val` для охоронця (`EQ`, `NE`, `LT`, `GT`, `RANGE`) **і** потребує `W1 = operand_val` для дії (`CME_ACT_ADD` або `CME_ACT_SUB` із кроком $K \ge 2$), компілятор зобов'язаний відхилити модуль до емісії з кодом `CME2-OPERAND-COLLISION`. Поєднання будь-якого літерального або діапазонного охоронця з `INC`, `DEC` чи `ASSIGN` (`set S_dst := x`), а також поєднання `when true` з `ADD`/`SUB` ($K \ge 2$), колізії не створює і підтримується повністю.

Нульовий крок `S_dst + 0` / `S_dst - 0`, від'ємний літерал кроку та присвоєння константи `set S_dst := K` відхиляються з `CME2-ACTION`.

## 4. Ациклічні каскади та умови побітової еквівалентності з RTL

Для кожного ребра підписки `S_src -> S_dst` (`on change(S_src)`):

1. **Обмеження fan-out $\le 1$ (`CME2-CASCADE`):** у 16-байтному дескрипторі `S_src` є рівно одне 6-бітне поле `subscriber_cid`, а `km_autonomous_sequencer.sv` має однослотовий буфер `cascade_pending`. Тому кожен концепт `S_src` може мати щонайбільше одного підписника `on change(S_src)`.
2. **Ациклічність графа (`CME2-CASCADE`):** орієнтований граф підписок перевіряється 3-кольоровим обходом у глибину (DFS); самопідписка `S -> S` та будь-які цикли `A -> ... -> A` відхиляються до емісії (відповідно до інваріанта скінченності каскадів та `RFC-012`). Довільні ациклічні ланцюжки довжини $1..63$ (зокрема `A -> B -> C`) дозволені.
3. **Каскад у `CID 0` (`guard_flags[4] = 0x10`):** для кожного видавця `S_src`, який має підписника `S_dst` (зокрема коли `S_dst` займає слот `CID 0`), компілятор виставляє прапорець `CME_GUARD_SUBSCRIBER_EN = 0x10` (`guard_flags[4]`) і записує `subscriber_cid = CID(S_dst)`.
4. **Стартова узгодженість (`CME2-CASCADE`):** `Interpreter.run()` ставить початкову перевірку `change_watches` на старті інстансу, тоді як апаратний секвенсор після завантаження BRAM очікує зовнішніх подій. Щоб початковий стан `Interpreter` та BRAM збігалися без фіктивних стартових транзакцій, охоронець `G` кожного каскадного правила `on change(S_src)` зобов'язаний давати `False` на початковому значенні `Init(S_src)`.
5. **Гарантована зміна стану видавця при `commit` (`CME2-CASCADE`):** у `km_concept_micro_engine.sv` сигнал `trigger_subscriber_o` активується за `gate_committed`, тоді як `Interpreter` породжує `change(S_src)` лише за фактичної нерівності нового й попереднього значень `S_src`. Тому концепт, який є видавцем каскаду (`S_src`), зобов'язаний мати ненульовий крок зміни (`INC`, `DEC`, `ADD` або `SUB` з $K \ge 1$): за відсутності wrap-around (`overflow_err == 0`) виконується тотожність $`S_{src} \pm K \ne S_{src}`$, отже `gate_committed` і фактична зміна стану еквівалентні. Листовий концепт (кінцевий підписник каскаду, який сам не має підписників) може вільно використовувати `CME_ACT_ASSIGN` (`set S_dst := S_src`).
6. **Тактова семантика `step` на AXI/HW:** один крок `step Ev(...)` у блоці `Proof` відповідає поданню однієї зовнішньої події з очікуванням завершення скінченного каскаду (`status.busy == 0` у регістрі `0x008` згідно з контрактом B4/B5).

Точні коди полів `CME-RAW-1` у [`kpol_reference.py`](../../sw/kpol-ref/kpol_reference.py) та `km_concept_micro_engine.sv`:
* `pred_code`: `NOP = 0x00`, `EQ = 0x01`, `NEQ = 0x02`, `GT = 0x03`, `LT = 0x04`, `RANGE = 0x05`, `BITMASK = 0x06`;
* `action_opcode`: `ASSIGN = 0x00`, `INC = 0x01`, `DEC = 0x02`, `ADD = 0x03`, `SUB = 0x04` (значення `> 0x04` в RTL відхиляються `fail-closed`);
* `guard_flags`: `ASSUMPTION_EN = 0x01`, `INVARIANT_EN = 0x02`, `HAZARD_EN = 0x04`, `INVERT_ASSUMPTION = 0x08`, `SUBSCRIBER_EN = 0x10` (неактивний слот має `guard_flags == 0x00`).

## 5. Обов'язковий гейт `Proof` та коди відмов `CME2-*`

На відміну від безпрофільного виклику, `KPOL-CME-2` вимагає наявності непорожнього й невакуумного блока `Proof` як у Python API, так і в CLI:

* відсутній `Proof`, порожній `Proof {}`, `total_checks == 0`, неактивований `assert ... when ...` або порушений `expect`/`assert` блокують емісію образу з кодом `CME2-PROOF`;
* якщо задано `acl_table`, перевіряється дозвіл на запис (`CAP_WRITE`) для кожного змінюваного стану (`CME2-ACL`).

| Код відмови | Умова спрацьовування |
| :--- | :--- |
| `CME2-IO` | Помилка читання вхідного файла або спроба перезаписати існуючий вихідний файл у CLI (заборонено режимом `xb`) |
| `CME2-SYNTAX` | Лексична або синтаксична помилка `parse_module` |
| `CME2-TYPE` | Помилка статичної перевірки типів або зв'язування імен у `check_module` |
| `CME2-SHAPE` | Непідтримувані секції модуля, кількість станів поза `1..64`, тип стану/параметра не `Int32`, відсутність бієкції правил/подій |
| `CME2-INVARIANT` | Відсутній інваріант `S >= 0` для будь-якого стану, додатковий непідтримуваний інваріант/ціль або `Init < 0` |
| `CME2-HAZARD` | Присутня непорожня секція `Hazards` |
| `CME2-GUARD` | Використано `•`/`(*)`, звернення охоронця до стану поза `change(S_src)`, невідомий оператор або складений вираз поза `RANGE` |
| `CME2-RANGE` | Межі двостороннього інтервалу після зведення виходять за `[-32768, 32767]` або $lo > hi$ |
| `CME2-ACTION` | Присвоєння константи `set S := K`, крок $\le 0$, крок поза `Int32` або сторонній операнд дії |
| `CME2-OPERAND-COLLISION` | Одночасна потреба в `W1 = operand_val` для охоронця (`EQ/NE/LT/GT/RANGE`) та дії (`ADD/SUB` із $K \ge 2$) |
| `CME2-CASCADE` | Передано зовнішній `cascade_map`, цикл або самопідписка в `on change(...)`, `fan-out > 1`, істинний охоронець каскаду на старті або видавець без монотонного кроку |
| `CME2-PROOF` | Відсутній, порожній, вакуумний або хибний `Proof` |
| `CME2-ACL` | Порушення таблиці апаратних прав доступу `acl_table` (`check_module_security_acl`, наприклад запис у стан без `CAP_WRITE`) |
