## Призначення і межі

### Призначення
Цей посібник визначає методику налаштування, прошивки та експлуатації мікроконтролера Raspberry Pi Pico (RP2040) як швидкісного 8/24-канального логічного аналізатора для фізичної реєстрації субмікросекундних часових інтервалів на апаратному стенді PYNQ-Z1.

Посібник закриває прогалину верифікації гіпотези H4 та вимоги `REQ-HW-012`: фізичне вимірювання детермінованої латентності конвеєра ($80\text{ нс}$), джитеру та тривалості імпульсів `Commit` / `Reject` ($100\text{ нс}$) без потреби в коштовних стаціонарних осцилографах.

### Межі застосування
* **Охоплює:** Запуск прошивки RP2040 PIO ([`pico/pico_firmware_pio.py`](pico/pico_firmware_pio.py)), отримання вибірок через USB CDC, конвертацію потоку в стандартний формат VCD (Value Change Dump) за допомогою [`pico/pico_capture.py`](pico/pico_capture.py) та автоматичний розрахунок латентності.
* **Не охоплює:** Фізичну комутацію роз'ємів (визначено в [`hil-bench-wiring-guide.md`](hil-bench-wiring-guide.md)).

## Навігація чи використання

### Крок 1. Підготовка мікроконтролера Raspberry Pi Pico
1. Підключити Raspberry Pi Pico до ПК кабелем Micro-USB, утримуючи білу кнопку `BOOTSEL`.
2. На комп'ютері з'явиться віртуальний накопичувач `RPI-RP2`.
3. Завантажити стандартну прошивку MicroPython (або спеціалізований UF2 бінарник Sigrok / `pico-logic-analyzer`).
4. Скопіювати прошивку [`pico/pico_firmware_pio.py`](pico/pico_firmware_pio.py) на пристрій під назвою `main.py` за допомогою утиліти `ampy`, `rshell` або Thonny IDE.

### Крок 2. Підключення ліній вимірювача до макетної плати
Згідно зі схемою [`hil-bench-wiring-guide.md`](hil-bench-wiring-guide.md), підключити лінії GP0..GP5 шлейфом до макетної плати BB-102:
* `GP0` $\to$ Фізичний вихід датчика (External Stimulus).
* `GP1` $\to$ Вхід тригера PMOD JA1 (`ext_hw_trigger_i`).
* `GP2` $\to$ Вихід валідації PMOD JA2 (`hw_commit_pulse_o`).
* `GP3` $\to$ Вихід відхилення PMOD JA3 (`hw_reject_pulse_o`).
* `GP4` $\to$ Затвор силового польового транзистора `IRLZ44N`.
* `GP5` $\to$ Монітор циклу конвеєра PMOD JA4 (`busy`).
* `GND` (Pin 38) $\to$ Спільна шина `GND_STAR`.

### Крок 3. Запуск захоплення та генерація VCD
На робочій станції запустити хостовий скрипт захоплення:
```bash
# Тестовий прогін емуляції (без підключеної плати)
python3 Engineering/hw/boards/pynq-z1/pico/pico_capture.py --mock --output capture.vcd

# Фізичний прогін на підключеному стенді (/dev/ttyACM0)
python3 Engineering/hw/boards/pynq-z1/pico/pico_capture.py --output capture.vcd --rate 125000000
```

Скрипт автоматично виміряє час між фронтом стимулу та відповіддю:
$$\Delta t = t_{\text{Commit}} - t_{\text{Trigger}}$$
та виведе підтвердження детермінізму:
```
Trigger edge:  250.0 ns
Response edge: 350.0 ns
Delta latency: 100.0 ns (80 ns execution + 20 ns CDC)
Status: PASS
```

### Крок 4. Візуалізація у PulseView / GTKWave
Для інтерактивного перегляду осцилограм відкрити згенерований файл `capture.vcd` у безкоштовному пакеті PulseView або GTKWave:
```bash
gtkwave capture.vcd
```

## Обмеження та метрологічний бюджет похибки

| Параметр вимірювання | Значення | Метрологічний вплив |
| :--- | :--- | :--- |
| **Крок дискретизації (125 МГц)** | $8{,}0\text{ нс}$ | Максимальна похибка квантування становить $\pm 8\text{ нс}$. |
| **Крок дискретизації (200 МГц)** | $5{,}0\text{ нс}$ | При розгоні RP2040 до 200 МГц похибка становить $\pm 5\text{ нс}$. |
| **Джитер 2-FF CDC синхронізатора**| $\pm 10\text{ нс}$ (1 такт 100 МГц) | Асинхронний фізичний вхід захоплюється першим або другим тактом FPGA. |
| **Затримка Level Shifter** | $3\text{--}7\text{ нс}$ | Симетрична затримка трансляції рівнів, що додається до абсолютного часу. |
| **Сумарний очікуваний діапазон** | $90\text{--}110\text{ нс}$ | Строго відповідає нормативному бюджету $80\text{ нс}$ конвеєра $+ 20\text{ нс}$ CDC. |

## Абревіатури та глосарій

| Термін | Значення |
| :--- | :--- |
| **PIO** | Programmable Input/Output, апаратні автомати введення-виведення RP2040 |
| **CDC** | Clock Domain Crossing, синхронізація сигналів між тактовими доменами |
| **VCD** | Value Change Dump, стандартний формат файлів осцилограм |
| **PulseView** | Графічний інтерфейс користувача з відкритим кодом для логічних аналізаторів (проєкт Sigrok) |
