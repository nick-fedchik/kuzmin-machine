# EKPOL: позначка за третє відвідування

У читацькій картці рахуємо відвідування. На третє даємо відзнаку. На четверте — вже ні. Для цього потрібні дві комірки: одна рахує візити, друга реагує на зміну першої. Таку комірку зі станом і правилами реакції в EKPOL називають **концептом**.

## Від зовнішньої події до підписки

Збережіть програму як `visits.ekpol` у корені репозиторію:

```ekpol
module VisitsCard;

concept Visits: i32 = 0 [>= 0] {
    on Visit(stamp) when stamp == 1 => Visits += 1 commit;
}

concept Badges: i32 = 0 [>= 0] {
    on change(Visits) when Visits == 3 => Badges += 1 commit;
}

test ThirdVisit {
    send Visits(1);
    send Visits(0);
    expect Visits == 1;
    send Visits(1);
    send Visits(1);
    expect Badges == 1;
    send Visits(1);
    expect Visits == 4;
    expect Badges == 1;
}
```

Прочитайте перше правило як речення: **на подію** `Visit(stamp)`, **якщо** `stamp == 1`, **додай** один візит і **зафіксуй** результат (`commit;`). `stamp` тут лише ознака відмітки: нуль не зараховує візит. `i32 = 0 [>= 0]` означає: знакове ціле, спочатку нуль, допустимі лише невід’ємні результати.

У другого правила немає зовнішньої кнопки «видати відзнаку». `on change(Visits)` — **підписка**: коли `Visits` змінився, перевір нове значення. Саме тому на третьому візиті перевірка бачить `3`, а не `2`. Якщо відмітку відхилили, стан не змінився й підписку не запускають.

## Звірте прогноз із виконанням

У правилі `Visit` — назва події, а в тесті `send Visits(1)` вказує, **куди** подати відмітку `1`: у комірку `Visits`. `expect` перевіряє, що залишилося в пам’яті. Щоб побачити також кроки між перевірками, запустіть із кореня репозиторію:

```sh
python3 Engineering/sw/kpol-ref/kpol_debugger.py --program visits.ekpol \
    --trace-events '0:1,0:0,0:1,0:1,0:1'
```

`0` перед двокрапкою — номер `Visits`, першого оголошеного концепту. Стежте за парою `(Visits, Badges)`: спочатку `(0, 0)`, потім **`(1, 0) → (1, 0) → (2, 0) → (3, 1) → (4, 1)`**. Для третього зарахованого візиту в трасі видно два записи: спочатку в `Visits`, потім у `Badges`. Обидва спричинені однією вхідною подією.

**Змініть один знак.** Якщо замінити `Visits == 3` на `Visits >= 3`, чи пройде останній `expect`? Повторіть команду: компілятор повідомить `EKPOL-PROOF-ERR`, бо за четвертий візит теж нараховано відзнаку. Для одноразової відзнаки поверніть `==`. Якщо ж хочете заохочувати *кожен* візит починаючи з третього, залиште `>=` і змініть останнє очікування на `2`.

## Як читати короткий запис

Поверніться до початкової програми з одноразовою відзнакою. У ній правило всередині `Badges` можна **замінити** коротким записом:

```ekpol
~ Visits :: Visits == 3 => Badges += 1 .
```

`~ Visits` читається як `on change(Visits)`, `::` — як `when`, а завершальна крапка тут відповідає `commit;`. Замініть рядок і повторіть запуск: остання пара залишиться `(4, 1)`.

## Короткий глосарій

- **Подія** — привід перевірити правило. **Умова** (`when`) — запитання з відповіддю «так» або «ні».
- **Каскад** — послідовність реакцій: запис у першу комірку дає привід перевірити правило другої.

Далі: [каскад із чотирьох комірок](../sw/vmk-go/examples/cascade_4concept.ekpol) та [формальна специфікація EKPOL](../specifications/kpol/ekpol-formal-specification.md).
