* **Версія:** 0.1.2
* **Дата:** 2026-11-12
* **Тип WP:** Report / Analysis
* **Виконавець:** GitHub Copilot CLI, Auto; конкретна модель не атестована.
* **Об'єкт:** початкова локальна папка `kuzmin-machine-ng`; [маніфест поточної редакції](../../registers/migration-manifest.json).
* **Підстава:** пряма команда власника скопіювати актуальне без legacy.
* **Статус:** внутрішня перевірка перенесення; не незалежна рецензія.

## 1. Мета, база й критерії

Використано чистий `kuzmin-machine@707fdba697d92ef9874c9013eb6f4f3cb2796d70`.
Структура та критерії наведені у [Plan](../../plans/ng-transition.md).
Робота не включає наукового переоцінювання, нового фізичного запуску,
оновлення заявленого TRL, нового релізу або публікації.

## 2. Зміни та охоплення

Скопійовано 259 відібраних tracked-входів; 1040 інших не перенесено.
Кожне рішення відбору є у маніфесті. Створено три змістовні корені,
навігацію, джерельні картки, поточні реєстри, опис Solution і політику
розміщення. Єдині форми — у `Project/templates/`.

Адаптовано імпорти, корені перевіряльників, CI та pytest-колекцію.
Вилучено тільки тести виключеного demo/v1-шляху; поточні компоненти,
pipeline та compiler-регресії залишено. Перевірку RTL переведено
на gate v2/BRAM/CME/sequencer/AXI без iCE40-проксі й старої demo-обгортки.
Runbook і призначення перемикачів PYNQ-Z1 оновлено для CFG-P.

Незмінні Source/raw/fixture/проходи опозиції не переформатовано.
Live Markdown отримав тип, версію, походження, межі, історію й глосарій;
для компактних пакетів постановка й метод є розділами, не порожніми файлами.
У формі Review додано глосарій. Номер NG-паспорта TRL узгоджено
з наявною історією до 0.2.4 без зміни самооцінки.

AV-10/11 CLI навмисно вимагає новий `--output-dir`; уже наявний експорт
не перезаписується. Цю відмінність від старих команд явно описано у
Validation, а алгоритм обчислення затримок не змінено.

## 3. Метод та фактичні перевірки

Перевіряються відібрані тести, локальні посилання, незмінність первинних
входів, структура WP та поточний відкритий RTL-маршрут.
Конкретні команди, коди завершення та підсумки зберігаються у
[validation-results.json](raw/validation-results.json);
машинні діагностики й stdout/stderr — поруч у [raw](raw/).

Повний відібраний suite пройшов; немає битих локальних посилань або
`file:`-посилань. Усі 7 збережених посилань на точні версії `drafts`
перевірено локальним клоном, без пропусків. У першому циклі перевірено 93 live Markdown
та хеші 108 незмінних входів. RTL simulation/lint/XC7 logic synthesis
завершилися успішно в описаних межах.

Змістовий reader-check нової навігації відтворив п'ять потрібних
розрізнень: тематичний Research, склад compiler-тракту, винятки
незмінності, відсутність нового прийняття та місце походження.
За ним додано прямі входи до fixture і формальної траси.
Зауваження про відсутній Project/README.md не підтвердилося
перевіркою існування файла й links-check. Reader-check не є
незалежною рецензією чи атестацією наукових тверджень.

## 4. Обмеження та відомі прогалини

Структурний provenance-лінтер успадкованих експериментальних Report
не проходить через відсутні sidecar. Їх не вигадано заднім числом;
числа й схвалення оригіналів не перенесено як нове схвалення NG.
Точна діагностика — у [provenance.json](raw/provenance.json).
S1 залишається `NOT_ASSESSED`.
У вибраному корпусі це 9 документів, 413 числових рядків,
0 рядків із sidecar-покриттям; це підрахунок лінтера, не число
неправильних наукових результатів.

Окремий перенесений namespace/import probe відтворює успадкований
контрприклад: unresolved import приймається. Його очікуване завершення
з помилкою фіксується як відомий контрприклад, не як успіх перевірки
контракту. Виправлення семантики поза межами цієї міграції.

Повний pipeline лінтується з відомими width/unused-попередженнями;
strict lint застосований лише до відповідних чистих компонентів.
Успішний logic synthesis не доводить STA чи поведінку фізичної плати.
AV-10/11 залишаються доказами CFG-R, не CFG-P.
Протоколи й первинні записи не дають підстав назвати всю міграцію
новим експериментом або незалежною оцінкою.

## 5. Висновок і залишок

На завершення початкової підготовки локальне дерево мало окрему
навігацію без змістовного `docs/`, із відстежуваним походженням і явними
виключеннями. Папка не була Git-клоном; commit, remote, branch, Issue,
PR, tag і push на тому етапі не створювалися.
Рішення про прийняття нового складу й зовнішнє поширення — за власником.
Успадковані наукові й provenance-прогалини не приховано структурою.

## 6. Рішення власника й підготовка подальшого злиття

Після першого циклу власник визначив пропрієтарний, не відкритий режим.
#20 закрито як completed; Project-статус Done. #5 залишається Open
із Project-статусом Postponed; #8/#120/#115 — Open/Todo.
Джерела рішень і машинний знімок — у
[реєстрі поточних WI](../../registers/open-work-items.md).

До NG додано LICENSE, NOTICE, AUTHORS.md та ліцензійну Policy;
права на сторонні Source не перепризначено.
[План](../../plans/ng-transition.md) доповнено окремим майбутнім
перенесенням tracked-дерева до наявної Git-історії.
Цей підготовчий етап не замінював дерево старого клону й не створював
гілки, commit, PR або push. Статусні зміни на GitHub були окремо дозволені.
Повторні організаційні перевірки —
[owner-preparation-checks](raw/owner-preparation-checks-20261112.json);
перші логи й числові результати не переписано.

Наступна команда власника дозволила виконання міграції в Git як
окремої #148. Її фактичний об'єкт, перевірки й межі наведено в
[окремому Report](../structure-migration/report.md). Це не змінює
заднім числом початкових raw або результатів підготовки.
