# План: підготовка NG та міграція структури в Git

* **Версія:** 0.3.0
* **Дата:** 2026-11-12
* **Тип WP:** Plan
* **Власник рішення:** Микола Федчик.
* **Виконавець:** GitHub Copilot CLI; підстава — прямі команди власника.
* **WI виконання в Git:** [#148](https://github.com/nick-fedchik/kuzmin-machine/issues/148).

## Мета та межі

Створити окрему папку Research/Engineering/Project з актуальними
документами, кодом і потрібними доказами; не переносити архіви,
замінені специфікації й PoC-демонстратори. Початкову локальну підготовку
виконано без Git/PR/push. Наступний етап — перенесення цього складу
окремим PR до чинного репозиторію, без переписування історії.

## Роботи, залежності та критерії

| Робота | Залежність | Перевірний результат |
|---|---|---|
| Визначення складу | Чистий source SHA | Кожен tracked source або має призначення, або причину виключення. |
| Копіювання | Карта шляхів | Окреме дерево, джерельні файли не змінені, immutable-хеші збігаються. |
| Оформлення WP | Копії | Навігація, типи, межі, версії, історія, терміни; без вигаданих результатів. |
| Адаптація виконання | Нові шляхи | Перевірки працюють з NG, не читають код зі старого клону. |
| Контроль | Оформлення й виконання | Тести, посилання, структурна перевірка WP, RTL-лінт/синтез; результати у Report. |

## Ризики й межі

Видалення залежності не повинно приховати чинний тест. Для виключених
демо вилучено тільки тести їхніх реалізацій; перевірки поточного
pipeline, compiler, формального ядра й записів даних збережено.
Зміна шляху не підтверджує фізичний результат нової збірки.

## Виконання заміни структури в наявному Git

Заміна виконується за наступною прямою командою власника для того самого
`nick-fedchik/kuzmin-machine`, не для видалення чи перестворення
репозиторію. Об'єкт — гілка `chore/148-research-engineering-project`
у власному worktree. Злиття до main не доручено.

| Крок виконання | Умова та контроль |
|---|---|
| Зафіксувати базу | Перевірити актуальний main і чистий стан; при зміні SHA повторити перевірку сумісності NG із новими змінами. |
| Узгодити WI і власну гілку/worktree | Окрема #148 створена за командою власника; відкладену #5 не активувати. |
| Замінити лише tracked-вміст | Використати маніфест підготовленого NG; не копіювати й не видаляти `.git`, не переносити кеші та локальні секрети. Не видаляти локальні untracked/ignored-файли старого клону. Видалення старих tracked-шляхів показати в diff, а не виконувати широке очищення клону. |
| Зберегти походження | Новий коміт має продовжувати наявну історію; старі SHA та їхні permalink залишаються доступними. Не застосовувати orphan history або force-push. |
| Включити правові входи | LICENSE/AUTHORS/NOTICE і політика пропрієтарного режиму підготовлені за рішенням #20; Source зберігає власні умови. |
| Перевірити й подати результат | Переглянути staged diff; запустити відповідні тести, links/WP і RTL-маршрут; подати окремий PR. Злиття — за рішенням власника. |
| Узгодити зовнішні посилання | Оновити живі шляхи в Issues після появи нових шляхів у main; історичні посилання на точний SHA не переписувати. |

Стани робіт — у [поточному реєстрі](../registers/open-work-items.md).
Виконання в Git — в окремому [Report](../assessments/structure-migration/report.md).
Старі критерії S2 й незавершені compiler/usability/finding не
видаються за виконані самим перенесенням папок.
