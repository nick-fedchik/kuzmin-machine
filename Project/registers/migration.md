# Реєстр вибіркового перенесення NG

* **Версія:** 0.3.0
* **Дата:** 2026-11-13
* **Тип WP:** Register
* **Власник:** Микола Федчик; укладач — GitHub Copilot CLI.
* **База:** `nick-fedchik/kuzmin-machine@707fdba697d92ef9874c9013eb6f4f3cb2796d70`, чистий стан.

## 1. Межі та джерела

Основний машиночитаний запис — [migration-manifest.json](migration-manifest.json).
Він охоплює всі tracked-файли вихідного зрізу: скопійовані входи та
явні виключення. [path-map.json](path-map.json) є картою старий → новий.
Кеші, untracked build і локальна обмежена для поширення копія PAM
не є входами. Спільний source-клон не змінювався; перенесення в Git
виконується у власному worktree в межах #148.

## 2. Схема та стани

`entries` містить source, destination, source_sha256, immutable та
призначення. `excluded` містить старий шлях і причину; старий tracked-шлях
прибирається з нової гілки, але оригінал залишається в Git за SHA бази.
`destination_sha256` фіксується після
адаптації, не підміняє початкового хешу.
Нові NG-файли обліковуються окремо як `created`.

Стани «скопійовано», «адаптовано» й «незмінний доказ» описують операцію,
а не прийняття чи правильність результату.

## 3. Правило відбору

Перенесено поточні контракти й compiler/loader/CME, їхні тести,
актуальні дослідницькі висновки та джерела, п'ять пакетів обмежених
доказів, чинні правила й нові шаблони.
Не перенесено архіви, дельти KPOL v0.1–0.9, демо-FSM і залежні
wrapper/top/build, старі бізнес-матеріали, стару базу AV-повтору,
попередні реєстри й звіти міграцій.

Незмінні проходи опозиції, compiler fixture та raw потрібні як докази
або тестові входи, а не як чинні legacy-документи. Повні старі тексти,
на які посилаються активні документи, доступні за immutable Git URL.

Фіксований вхід compiler —
[`kpol-v01-examples.md`](../../Engineering/sw/kpol-ref/tests/fixtures/kpol-v01-examples.md).
Первинні інженерні записи — у пакетах
[Validation](../../Engineering/validation/README.md), дослідницькі —
у [Data опозиції](../../Research/studies/concept-assessment/data/opposition-passes/).
Повний перелік винятків визначає `immutable: true` у маніфесті та
`immutable_input: true` у [файловому індексі](wp-index.json).

## 4. Ведення і контроль

Перевірити існування, унікальність шляхів і SHA-256 незмінних записів.
Для адаптованих копій зберігати початковий хеш та точне походження.
Новий прогін не записувати поверх raw; відсутній provenance не
відновлювати здогадками. Структурний перевіряльник WP перевіряє
винятки й хеші незмінних входів.

## 5. Обмеження та результат

Це новий реєстр, не переписаний старий F1–F14.
У джерельному зрізі міграції окремої авторської специфікації
М. Ю. Кузьміна 2026 року не було встановлено; формальний аналіз
є похідною реконструкцією. Новий
[Source #155](../../Research/sources/author/introduction-2026-11-13.md)
про поняття/групи/синтаксис отримано 2026-11-13, поза тим зрізом.
Його хеш і походження обліковуються окремо; маніфест не переписано,
новий матеріал не оголошено повною прийнятою специфікацією.
Результати початкової підготовки — у [Report NG](../assessments/ng-migration/report.md);
виконання в Git — у [Report #148](../assessments/structure-migration/report.md).
Нова гілка продовжує наявну Git-історію; NG не оголошено новою baseline.
